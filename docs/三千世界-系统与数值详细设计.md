## 一、G2 主资源挂机（修为）

### 1.1 产出公式

```
每秒产出 = 境界基础产出 × (1 + Σ qiRate 加成) × 阵营修炼倍率 × buff 倍率
```

- **境界基础产出**：见 §六境界表 `baseQi` 列；
- **阵营修炼倍率**（善恶系统联动，v1.8 重做）：正道 `0.75` / 左道 `1.0` / 魔道 `1.5`，按当前 karma 区间实时取（karma 跨过分界线的瞬间切换，无缓冲）；阵营档位还联动战力/奇遇频率/掉落/判定等维度，全表见主设计文档 §6.3「三阵营状态效果」与本文档 §8.1 ALIGN_EFFECTS；
- **buff 倍率**：奇遇限时 buff 与 debuff 的乘积。

### 1.2 积累上限（qiCap）

```
修为上限 = max( baseQi × 7200 秒 , 下一阶突破 need × 1.15 ) × (1 + Σ qiCap 加成)
```

- 上限永远高于突破阈值 15%（复核修订：**旧式「纯 2 小时产出」会封死化神以后的所有突破**，见复核报告问题 1）；
- 渡劫到阈值即消耗（界面批三起默认**手动触发**，开 `settings.autoTrib` 自动渡劫开关后恢复自动掷判——**自动批 2026-10-02 起开关位于修行页底部「自动」区**，原设置页挂靠作废），因此该上限在正常游玩中几乎不可见——它的实际角色是 **真仙（无下一阶）后的溢出水槽** 与异常兜底；真仙后上限回落为 2 小时产出量，到顶显示「已臻化境」；
- `qiCap` 加成乘区（天赋/聚灵诀）作用于整个 max 结果。

### 1.3 离线结算

- **离线门槛 60 秒（v1.7 新增）**：本次结算间隔（`now − lastSave`）**< 60 秒时不进入离线规则**——该区间按在线口径全额推进（不打离线效率折、不吃 12h 上限、不跑批量渡劫循环、不产生离线收益汇总）。短切后台/秒回不触发「闭关结算」弹窗，避免收益面板被碎片化；`≥ 60 秒` 才走以下离线规则；
- **离线效率基准 50%**：离线期间按 `每秒产出 × (0.5 + Σ offlineEff 加成)` 计算；
- **离线时长上限 12 小时**：超出部分不计（未来可留「鸿蒙大世界云补偿」钩子，本期不做）；
- 离线期间每攒满一次突破阈值就在结算循环内掷一次渡劫（主文档 §7.5 已定，循环上限 64 轮）；**离线不触发奇遇**（v1.7 同步奇遇时钟机制，见奇遇池设计 §四）；
- 结算完成后写一条汇总日志：「闭关 X 小时 Y 分，得修为 N，渡劫 M 次（成 K 败 L）」；
- **离线收益汇总字段（v1.7 登记）**：每次离线结算（≥60s）同时写 `worlds.{id}.lastOffline = { at, secs, qi, stones, trib: { n, s, f } }`，供修行页离线收益面板与回线首次弹窗消费（UI 设计 §3.2）；旧存档缺省 `null`，面板与弹窗对 `null` 不渲染。

### 1.4 修为用途（资源水槽）

| 用途 | 出口 |
|---|---|
| 渡劫突破 | 攒满阈值后手动点「渡劫」掷判定（`settings.autoTrib` 开启则自动掷；主文档 §七） |
| 渡劫失败损耗 | 失败修为 ×0.5（受 tribFailLossMod 修正） |
| 奇遇事件 | 部分事件按 qiPct 增减 |
| 丹药/秘宝 | 商店部分商品以修为计价（见 §五） |

> 灵石（stones）是第二货币：装备炼化、商店购买的主要出口，见各节；**（修行状态批 v2.0）功法升级改耗修为**（§4.2 v2.0），灵石不再承担功法升级出口。

### 1.5 修行状态（修行状态批 v2.0 · mode）

| 状态 | mode | 修为产出 | 灵石/装备 | 奇遇时钟 | 练习度（悟法） | 秘境 |
|---|---|---|---|---|---|---|
| 潜心问道（原「闭关领悟」，走查批 v2.2 更名） | `seclude`（默认） | ×1.0 全速 | **不产灵石、不出装备**（不进战斗模拟；引灵入体转化闸 `claimStones:false`，走查批 v2.1） | ×0.5（清修减半） | ×1.5（容易领悟） | 不推进 |
| 外出历练 | `venture` | ×0.55 放缓 | 击杀灵石 + 掉落全开 | ×1.5（机缘加倍） | ×0.5（不易领悟） | 角色前往 `ws.zone` 秘境击杀推进 |
| 潜心悟道 | （离线回归） | **按原有规则结算**（OFFLINE_EFF 0.5 + ΣofflineEff、12h 上限、引灵入体全不变） | 同左 | 离线零奇遇（时钟冻结，不变） | 离线不涨 | 离线不模拟（不变） |

- 模式只作用**在线口径**：乘区实现点 = `Idle.settle`（qiMult）/ `Events.tickOnline`（eventMult）/ `Arts.tickPractice`（practiceMult）/ `claim`（combat 闸）；离线路径零触碰，`lastOffline.mode` 只作叙事口径（修行页「闭关所得 / 历练所得」两套文案）；
- 玩家偏好级切换（不改角色数据）：修行页两卡选择 → `SQ.Actions.setMode`；脏值 normalize 回落 `seclude`；
- 实测校准（sim-event-economy 重跑）：奇遇密度 闭关 ≈4.7 条/h（20 分钟保底不随 ×0.5 线性减半）、历练 ≈7.0 条/h；节奏主轴 魔 < 左 < 正 维持。

### 1.6 游戏历（走查批 v2.3）

- **1 游戏日 = 现实 1 秒**，自入世（`profile.createdAt`）起算；12 月 × 30 日 = **360 日/年**，离线照常流逝；
- 起始年 `ws.calYear` 创角随机 1~9000（脏档 normalize 钳位、缺省 1 保幂等）；显示名 = 世界名去尾字（罗云州 → 「罗云历4321年7月8日」）；
- 视图换算不存累计值；修行页顶部常驻显示，日志页与奇遇叙事流时间戳均按游戏历渲染；
- 冷却类时长统一以游戏时间表述：势力叛离 = 1 游戏年、洞府迁居 = 1 游戏年（走查批 v2.8 统一口径）。

### 1.7 新手起步加速（新手起步批 v1.27）

- **动因（实测）**：新手前 30 分钟手感模拟（默认闭关攒修为）显示首次破境 ≈18 分钟、首通秘境落在窗口外（≈38 分钟）——前段为纯干等；
- **口径 `D.NEWBIE_RAMP = { realms: 0, qiMult: 3 }`**：**仅境界 ≤ realms（=0）、仅在线**（`!offline`）的结算修为 `rate × qiMult`——出了首境自动失效、离线结算不享（防离线刷加速）；
- **刻意最小面**：`rateOf` 契约、离线效率/上限（`OFFLINE_EFF`/`CAP_HOURS`）、击杀节奏（`KILL_BASE_SEC`/`PROG_PER_KILL`）、掉落率一律**零改动**——`sim-pacing` 稳态带复跑不变；只压缩境界 0→1 段的在线等待；
- **实测落点**：首破境 18min → **≈6.5min**、首通回 30min 窗口内（**≈24.5min**）；断言 #164（工程规范 §4.18）同 realm 开/关加速求比值直测系数 =3。

## 二、G3 战斗历练（秘境）

### 2.1 核心循环

```
选择秘境 → 按战斗速度持续击杀 → prog 0→100 → 通关：掉装备 + 解锁下一秘境
```

- **击杀节奏**：`每小时击杀数 = 60 × 战斗速度系数`，基准速度 1 次/60 秒（P4 勘误：原「1 次/10 秒」与本公式矛盾，以公式为准，验收 4.4 #31 同口径），受 `combatSpeed` 乘区修正；**战斗只随在线 tick 推进，离线期间不模拟秘境**（P4 登记决策：离线收益聚焦挂机修为，秘境刷取是在线玩法）；
- **单杀进度**：每次击杀 `prog + PROG_PER_KILL × 富余乘子`（`PROG_PER_KILL = 5` ⇒ 贴线时 20 杀通关）。🆕 **战力富余加速（第卌三批 · 用户令「高战力刷低级秘境要更快，更符合直觉」）**：乘子 = `min(PROG_SURGE_CAP, 1 + 富余 × PROG_SURGE_COEF)`，`富余 = 战力 ÷ 本区需求 − 1`（**直接复用瓶颈判定那一对读数**，不另立战力口径），`COEF 0.5 / CAP 4` ⇒ 需求×2 时 +8/杀（13 杀）、×4 时 +13/杀（8 杀）、×9 以上吃顶 +20/杀（**5 杀通关**）。三条边界：**瓶颈态（战力 < 需求）乘子恒 1**、`prog` 仍封顶 90；**只喂进度口**——击杀间隔、掉落率、单杀灵石一律不动，高战刷低区是「快」而不是「多」（否则低区变成资源提款机，§2.3/§2.4 与 `sim-pacing` 全线重写）；进度取整后入档（`prog` 全程整数，界面直读与事件乘区口径不变）。首通额外 `prog` 清零重计为可重复刷取模式（重复刷只掉装备/灵石，不再解锁）；判据 = 冒烟 **#306**；
- **单杀收益**：灵石 = 秘境表 `stonesPerKill` × (1 + Σ stonesRate)；每次击杀掷掉落（见 §2.3）。

### 2.2 瓶颈机制

```
当前战力 < 秘境需求战力 → 击杀间隔 ×3，且 prog 封顶 90（无法通关）
```

- UI 在秘境入口显示红字「修为不足，举步维艰」，并给出建议（换装备 / 升功法 / 先渡劫）；
- **历练入口预告（体验手感批 v1.26）**：同一判定口径前移到修行页「外出历练」模式卡——当前秘境战力不足时卡片常驻「举步维艰」预告（含建议先闭关破境），挫败从事后红字提前到事前；数值口径零改动，仅 UI 呈现（UI 卷 §三）。
- **战力公式**：

```
战力 = (境界基础战力 + Σ 装备 atk) × (1 + Σ combatPower 加成) × (1 + Σ 功法战力加成)
```

### 2.3 掉落规则

- **单次击杀掉落率**：基准 `8% × (1 + Σ dropRate)`；
- **品阶权重**：按秘境索引查掉落表（§六），索引越高稀有度重心越靠上；
- **通关必掉**：prog 满 100 时必掉 1 件装备，品阶权重在常规基础上整体上浮一档；
- 掉落即进入 G4 自动择优流程，玩家无感知（只弹 toast：「拾得 玄铁剑（良品）→ 已替换 / 已炼化 +60 灵石」）。

### 2.4 秘境切换

- 同一时间只有一个「进行中秘境」；切换秘境不损失 prog（各秘境 prog 分别存档）；
- 已通关秘境可回访刷取（收益不变），未解锁秘境显示剪影 + 解锁条件。
- **首通自动推进（体验手感批 v1.26）**：首通当前秘境（`ws.zone` 且首通奖励已发）后——下一秘境**已解锁且战力 ≥ 其门槛** → 自动 `ws.zone +1` 并写战斗日志「首通牵引」（lexicon `zone.autoadvance`），无缝进入新目标；已解锁但战力不足 → 不跳（避免自动撞瓶颈），写牵引日志（`zone.autoadvance.hint`）留守刷取——秘境页排序本就将下一目标置顶；玩家手动 `setZone` 行为不变。（**✅ 系统深化批 2026-10-02 · 已实施（实施收口 2026-10-03）改造登记**：本条「首通自动推进」的推进点将后移——首通后先进入「域主现世」态，**域主战胜利后**才触发本条自动推进（牵引手感与判定口径不变），见 §2.6；实施落地前本条现行口径不变。）

### 2.5 秘境词缀（zone affixes · ✅ 系统深化批 2026-10-02 · 已实施（实施收口 2026-10-03））

同一秘境在不同驻留时段带一条限时「词缀」——只作用于**该区战斗结算**的局部环境修正，让重复刷取产生「今日此地天时如何」的变化感。

- **存档**：`ws.zoneAffix = { affixId, until }`（`until` = 现实时间戳；normalize：未知 id / 结构非法 → null，缺省 = 无词缀按 ×1.0 结算）；词缀绑定当前 `ws.zone`，切区即重掷覆盖；
- **roll 时机**：① `setZone` 切入该区（含回访旧区）时立即重掷；② 驻留期间每 `AFFIX_MS = 6h`（21,600,000ms）自动重掷（在线结算时判定；离线不掷，回线时已过期即补掷一次——与江湖传闻「离线只过期不刷新」§12.1 同口径）；
- **切入即见、不隐藏**：秘境页顶部与历练模式卡常驻显示词缀名 + 效果 + 剩余时长（词表 key `affix.{id}.name/.desc` ×8 = 16 key，实施批随词表卷升版）；
- **乘区纪律**：全部效果为**本区结算局部乘区，不进全局 `mods`**——消费点仅限 `combat.simulate`（stoneEach / dropP / 击杀间隔）与 `bottleneckOf`（need 判定线 / intervalPenalty）；闭关模式（`MODES.seclude combat:false`）不进战斗模拟，词缀无消费点，**天然豁免**（照常显示，对闭关收益零影响）。

**效果字段定义（6 个，词缀效果只由它们组合）**：

| 字段 | 消费点 | 语义 |
|---|---|---|
| `stonesMult` | stoneEach 末端乘算 | 击杀灵石乘数 |
| `dropMult` | dropP 乘算 | 击杀掉落率乘数 |
| `gearLuckAdd` | 本区掉落 roll 时 gearLuck 加算 | 品阶侧幸运（只作用于击杀掉落，不影响首通/域主必掉） |
| `needMult` | bottleneckOf 判定线 `need ×` | 瓶颈门槛乘数 |
| `intervalAdd` | 瓶颈间隔惩罚基准值（3，或精判定 2）之上**加算**，随后仍吃御风 ×0.8 既有顺序 | 瓶颈惩罚加项（仅瓶颈态生效） |
| `speedMult` | 击杀间隔 `÷ speedMult` | 击杀速度乘数 |

| `miwu` | 迷雾 | 负面 | dropMult 0.85 + gearLuckAdd 0.20 | 掉得少但掉得好——补偿走品阶侧 |
| `pinji` | 贫瘠 | 负面 | stonesMult 0.70 + dropMult 1.10 | 灵石减三成、掉落量补偿 |

> **「贫瘠」补偿维度裁定（本批对原案的偏离登记）**：原案补偿为 eventRate 侧写（奇遇频率上浮）——**不采纳**。理由：词缀乘区纪律 = 仅本区战斗结算内生效，而 eventRate 属在线奇遇时钟的**全局通道**，侧写会破「不进全局 mods」红线，且闭关模式下奇遇时钟读不到当前区词缀（无消费上下文）。改用备档 `stonesMult 0.70 + dropMult 1.10`：补偿与惩罚同消费点兑现，实现零跨通道耦合。

- **与全局乘区并存关系**：词缀局部乘区与 mods.sum 同域加算池（stonesRate / dropRate / combatSpeed 等）为**乘算关系**（全局池内加算、词缀在末端独立乘），与 caveMult 对 qiRate 池的并存口径同构（§8.2）；
- 首通必掉（§2.3）与域主必掉（§2.6）的品阶上浮独立于 gearLuckAdd，词缀不改必掉口径。

### 2.6 域主精英战（首通高潮化 · ✅ 系统深化批 2026-10-02 · 已实施（实施收口 2026-10-03））

现行「首通自动推进」（§2.4）改造为两段式高潮：首通达成 → 该区进入**「域主现世」**态 → 玩家主动挑战 → 胜利后才推进下一区。

- **存档**：`ws.zoneBoss = { zone, state: 'ready' | 'dead', retryAt }`（`retryAt` = 失败冷却截止时间戳，仅 ready 态有意义；normalize：zone 越界 / state 非法 → 清理）；旧档无此字段缺省 null = 维持现行「首通即推进」口径，实施批上线后新首通一律走新流程，**已通关旧区不追溯生成域主**；
- **触发**：首通某区（`ws.cleared` 入账）时写 `{ zone, state:'ready' }`；**首通附赠奖励（ZONE_TREASURE 法宝授予 §10.3、 zone 首通功法）发放点不变**——域主战是新增高潮挑战，不是奖励前置门槛；
- **挑战判定**：历练页点「挑战域主」→ `powerOf ≥ ZONES[zone].need × BOSS_MULT (1.8)` **一次性掷判**（读挑战瞬间当前战力，可先吃淬体丹 combatPower +20%、护法位、瓶颈侧战力加成等既有 buff 备战——战力读取与 §2.2 瓶颈判定同源口径）；
- **胜利**：① 必掉**品阶上浮两档**装备 1 件（对照：现行首通必掉仅上浮一档 §2.3——域主奖励在其上再 +1 档，封顶仙品）；② 首杀灵石 = `ZONES[zone].stones × BOSS_WIN_STONE_K (10)`，记 `in.event`（Ledger 同源锚）；③ `state:'dead'`，随后触发 §2.4 自动推进（**推进点后移至域主战后**：下一区已解锁且战力达标 → 无缝切换 +「首通牵引」日志照旧；达标不足 → 牵引 hint 日志照旧——体验手感批 v1.26 的牵引手感完整保留，只是中间多一场高潮战）；
- **失败**：可重试，冷却 `BOSS_RETRY_CD_MS = 10min`（现实时间），**无其他惩罚**（不掉修为、不挂 debuff、不耗灵石）；
- **持久化**：域主态随档持久，离线回来仍在、仍可挑战（离线不自动结算域主战——战斗只随在线推进，§2.1 同口径）；
- **战力门槛估算（v1.30 实施批勘误 + 探针结案）**：`ZONES.need = 1.5 × 解锁境界基础战力`（§6.2），`× 1.8` → 域主线 = **2.7 × 境界基础战力 = 该区 need 的 1.8 倍**〔勘误：v1.29 原文「need 的 1.2 倍」系算术笔误（2.7÷1.5=1.8），由此派生的「上品套 + 一颗淬体丹即标准通关路线」宣称作废〕。探针实测（`.tests/probe-deepbatch.cjs` P3 · 典型 ΣcombatPower 0.25 口径）装备阶梯比值：裸身 0.83 / 良品 0.99 / 上品 1.13 / 灵品 1.34 / 仙品 1.61；备战叠加后**上品+丹+瓶颈侧 1.55（差 14%）/ 灵品+丹 1.61 / 灵品+丹+瓶颈侧 1.85 压线 / 仙品+丹 1.93 余裕**——实际标准通关路线 = **灵品套 + 淬体丹（+ 瓶颈侧加算备战）**，比 v1.29 宣称高一档。**BOSS_MULT 维持 1.8 结案**（触发条件复核见 §九.15）；
- 词表 key `zone.boss.*`（现世 / 挑战 / 胜利 / 失败 / 冷却）实施批随 UI 卷与词表卷统一升版。

### 3.2 品阶（5 阶）与词条池

品阶从低到高：**凡品 → 良品 → 上品 → 灵品 → 仙品**。词条随品阶递进解锁（主文档 §7.6 已定）：

| 品阶 | atk | qiBonus | resist | 词条基础区间 |
|---|---|---|---|---|
| 凡品 | ✅ | — | — | atk 2~5 |
| 良品 | ✅ | ✅ | — | atk 4~8，qiBonus 3%~8% |
| 上品 | ✅ | ✅ | ✅ | atk 8~14，qiBonus 8%~15%，resist 40~80 |
| 灵品 | ✅ | ✅ | ✅ | atk 14~24，qiBonus 15%~25%，resist 80~150 |
| 仙品 | ✅ | ✅ | ✅ | atk 22~36，qiBonus 25%~40%，resist 150~260 |

> **缩放规则（复核修订，见复核报告问题 2/4）**：
> - `atk 实际值 = atk 基础区间随机 × max( P[掉落秘境解锁境界] / 100 , 1 )`——与境界基础战力指数挂钩（旧的线性 ×(1+索引×0.35) 跟不上境界 ×3 增长，会导致后期秘境数学上不可达）；
> - **qiBonus（百分比）不随秘境缩放**，固定区间——百分比若参与缩放，后期单件可破 130%，击穿乘区体系；
> - **resist 不随秘境缩放**，固定区间——它喂给有封顶的渡劫公式（满仙品 Σ≈1,040，resist 项 ≈0.17，永远拿不满 0.20 上限，留追求空间）；
> - **attrValue（属性亲和，第四词条）灵品起解锁**，不随秘境缩放：灵品 8~14 / 仙品 15~25，单属性随机（精/气/神），槽位亲和权重与判定机制见《角色属性设计》§3.3。词条解锁阶梯更新为：凡 1 / 良 2 / 上 3 / **灵·仙 4**。
> - **独占法器（v1.12 勘误）**：`exclusiveGear` 的 `atk` 按同规则缩放，但倍率在**获得时**以 `max( P[当前最高首通秘境解锁境界] / 100 , 1 )` 一次定格、此后不随新首通重定（防「压着晚拿」刷倍率）；qiBonus / resist / attrValue 仍为定值顶格不缩放。修复背景：定值 atk 36 对上后期缩放装（atk 数千~数万）会被自动择优瞬间顶掉，「顶级独占」名存实亡——配套豁免见 §3.4。

### 3.3 阵营（alignment）分布

- 掉落时掷阵营：**基础分布 左道 60% / 正道 25% / 魔道 15%**；
- **档位联动位移（v1.12 新增，ALIGN_EFFECTS `dropAlignW`）**：按当前 karma 档位实时取——正道光环档 = 左 50 / 正 38 / 魔 12；左道档 = 基础分布；魔道气息档 = 左 45 / 正 10 / **魔 45**。「同气相求」：档位越高越掉对应阵营装，魔道装词条 ×1.10 且每件 karma −15，构成魔道「质高而难回头」的掉落侧落点，与事件性质权重（35/65）同构；商店与事件 `dropGear{alignment}` 指定产出**不受**位移影响；
- 魔道装备词条数值 **×1.10**（补偿 karma 代价：每件 -15）；正道装备 ×1.00；左道 ×1.00；
- 商店与奇遇 `dropGear{alignment:'evil'}` 可定向产出魔道装备（如「魔道密使」事件）。

### 3.4 评分与自动择优

```
评分 score = ( atk + qiBonus×100 + resist×0.5 + attrValue×3 ) × 特殊词条系数
特殊词条系数 = 带 special 时 1.15，否则 1.0（特殊词条价值 ≈ 半条主词条，P5 复核）
```

（score 仅用于自动择优的 **同槽比较**，不再参与经济结算——见下方炼化修订）

- **要求前置检查**：拾取/购买装备先过佩戴要求（§3.5）——不满足者**不参与择优比较**，直接入库藏阁（见下）；
- **自动替换**：满足要求的新装备 score > 当前槽位 score → 自动装备，旧件自动炼化；
  🔧 **勘正（GitHub issue #2 · 2026-10-14）新增玩家开关 `ws.gearAutoRefine`（缺省 true = 上面这两条的旧行为）**：
  关闭时「被换下的旧件」与「不如在件的新件」一律**先入库藏阁**，不再自动炼化（灵石与 Ledger 因此零流动）；
  **库藏阁满时仍回落炼化腾位**——`STASH_CAP` 是落盘容量红线，不为开关放开（代码内已写 `shortcut:` 注）。
  开关落点认 `ws` 而非 `state.settings`：`autoEquip` 的十一个调用点签名各异，只有 `ws` 一定在场。
- **独占法器择优豁免（v1.12）**：独占法器（诛邪剑残/照世镜）**不参与自动替换比较**——穿上后只有手动操作能取下；随机新件 score 更高时不自动顶换，改 toast「拾得 仙品·XX——当前佩戴『诛邪剑残』为独占法器，是否手动替换？」+ CONFIRM（旧独占件入库藏阁，豁免溢出炼化）；
- **库藏阁（stash）**：不满足要求的装备自动入库暂存，**动态容量 12→15**（随境界/挂点解锁，融合批 F5；冒烟 #133/#134，工程规范 #98 同口径）；每次境界提升后自动复检，达标即参与择优；库满时自动炼化其中 score 最低者（写日志）；
- **自动炼化（复核修订，见复核报告问题 3）**：返还为 **品阶固定表 × (1 + 境界索引 × 0.5)**：

| 品阶 | 凡品 | 良品 | 上品 | 灵品 | 仙品 |
|---|---|---|---|---|---|
| 返还基数（灵石） | 5 | 20 | 100 | 500 | 2,500 |

  旧的 `score × 品阶系数` 公式会让后期单件炼化返还 ≈ 1 小时刷图收入（掉落 ~29 件/小时 → 通胀 20 倍），已废弃；
- 无手动锁定功能（本期不做，保持全自动的省心定位）；
- 每次替换/炼化/入库写日志，玩家可在日志栏回溯。

### 3.5 佩戴要求（按价值而定）

装备要求 = **品阶基础境界** + **极品词条追加**，两层叠加：

| 品阶 | 基础佩戴境界 |
|---|---|
| 凡品 / 良品 | 无要求 |
| 上品 | 金丹（境界 2） |
| 灵品 | 化神（境界 4） |
| 仙品 | 合体（境界 6） |

- **极品词条追加（神兵认主）**：`resist` 或 `attrValue` roll 到区间 **前 10%** 的高价值装备，佩戴境界 **+1 阶**——价值越高要求越高；
- 特殊词条**不**追加要求（避免与「无视佩戴要求」词条自我矛盾）；
- 未达标装备在 UI 显示红字要求（「需境界：化神」），入库藏阁等待；
- **设计意图**：低境界刷到仙品不再是「即刻战力」而是「存起来的盼头」，给秘境刷取加一条长线钩子；同时压住前期跳级配装对瓶颈机制（§2.2）的击穿。

### 4.6 自行领悟（自悟系统 · ✅ 2026-10-05 保底修复 + 收敛批落码）

除「练习度顿悟」（§4.1）外，修持中另有一条**无需购买、无外部来源**的功法获取通道——「自行领悟」：角色凭自身机缘悟出一部**市面传承**功法。参数唯一事实源 = `D.ARTS_SELFLEARN`。

**候选池**（`SQ.Arts.selfLearnCands`）：`obtain.type === 'shop'` 的市面传承 × 品阶白名单 × 已达标（`canLearn`）× 未持有（`!owned`）。**地阶 / 天阶永不入池**（`TIERS = ['huang','xuan']`），专属渠道（`initial` 初始自带 / 首通 / 黑市 / 奇遇）亦不入池——保坊市 / 首通 / 奇遇 / 黑市的独占性；境界提升扩大可学习面，候选随 `canLearn` 达标数扩容。

**推进时钟**（`ws.artsLearnClock` = 「自上次得手以来的累计加权秒」）：

- 在线推进 = `dtSec × 模式 practiceMult × (1+ΣartsSpeed) × 边际递减`，其中 `practiceMult` = 闭关 1.5（易悟）/ 历练 0.5（难悟）；
- 掷点**不扣减时钟**：本次应掷次数 = `floor(clock/interval) − floor(prev/interval)`（边界跨越数），保底跨线时至少掷一次；
- **保底**：`clock ≥ PITY_H×3600` 时本次必得（`force`）；得手 / 池枯竭即清零（池枯竭静默，进度归零）；
- **边际递减**（收敛批）：`eff × 1/(1+DECAY×已自悟部数)`，`ws.artsSelfLearnN` 记录已自悟部数，**越悟越难**——防一口气掏空池子；
- **离线悟道**（`opts.offline`）：不乘模式乘区（潜心悟道），改乘 `OFFLINE_MULT` 折扣，且单次结算推进上限 `OFFLINE_MAX_ROLLS` 个掷点（防长离线回归爆发式得手）。

**常量表 `D.ARTS_SELFLEARN`**：

| 字段 | 值 | 说明 |
|---|---|---|
| `INTERVAL_MIN` | 8 | 每 8 加权分钟掷一次 |
| `P` | 0.22 | 每次掷中概率（首部闭关期望 ≈0.4h，含天赋/功法 artsSpeed 加成） |
| `PITY_H` | 2 | 保底：累计 2 加权小时必得一部（闭关 ≈1.2h 现实 / 历练 ≈3.7h 现实） |
| `OFFLINE_MULT` | 0.5 | 离线折扣（潜心悟道按在线参考速率 50% 推进时钟） |
| `OFFLINE_MAX_ROLLS` | 2 | 单次离线结算至多推进 2 个掷点 |
| `DECAY` | 0.6 | 边际递减系数：`eff × 1/(1+DECAY×n)`；19 部池闭关口径 ≈49h 掏空（含 artsSpeed ≈42h） |
| `TIERS` | `['huang','xuan']` | 可自悟品阶上限（地阶/天阶永不自悟） |

- **进度条**（`SQ.Arts.selfLearnPct`）：`clock / (PITY_H×3600) × 100`，钳位 0~100（满 100 必得一部）；
- **存档与脏值纪律**：`ws.artsLearnClock`（数值，缺省 0，负数回落 0）+ `ws.artsSelfLearnN`（整数，缺省 0，负→0、小数截断）——`normalize` 幂等补齐，旧档缺字段自动回落 0 不破档；得手日志 `arts.selflearn`。

> 设计意图：给「不买功法」的玩家一条慢速随机通道（与坊市购买互补），并通过**收池分层（黄/玄）+ 边际递减**把「掏空全部可自悟功法」控制在 ≈40h+（闭关口径），不稀释坊市购买价值。断言 #240~#243 / #246（工程规范 §4.26）。

### 5.5 成交前置判定：先判后扣 + 弹窗与成交同源（第廿六批 2026-10-13 新立 · 正典）

**为什么购买成功不等于买到**：货架内容在**掷货时**按「未持有」过滤（§5.2 功法行），而一轮货架要挂满 4 小时才补货（§5.1）。这期间玩家可能已经从别的渠道拿到同一件——功法走自悟 / 奇遇赠典 / 秘境掉落，丹方图纸走残片兑换与炼丹炼器产出，法宝走特席与秘境。旧写法成交前**不复查落点**，于是照扣全价、按「重复所得」折半返还（`Arts.dupValue` = 0.5× 价），货**凭空消失**且**不留日志** ⇒ 玩家净亏一半。未达标功法撞上「待修习架已满」（`D.SHELF_CAP`）是同一形状的第二个出口。

**现行口径**（唯一实现 = `SQ.Shop.undeliverable`，`assets/systems/shop.js`；返回非 `null` 即**在扣灵石之前**整笔拒单，灵石 / `out.shop` / 材料账 / `it.sold` 一律不动）：

| 货类 | 拒因 | 判定口 |
|---|---|---|
| 功法 `arts` 已持有 | `owned` | `SQ.Arts.owned` |
| 功法未达标**且**待修习架已满 | `shelffull` | `!SQ.Arts.canLearn && ws.shelf.length >= D.SHELF_CAP` |
| 炼丹子货（丹方 / 图纸 / 丹炉图纸 / 丹炉成品）已拥有 | `owned` | 🆕 `SQ.Alchemy.goodOwned`（与 `deliverPackGood` 的发货分支同一处） |
| 法宝已有档 | `owned` | `SQ.Treasures.entryOf` |
| 材料包（`pack.type === 'mat'`） | **放行** | 材料可叠加，不存在「落不下」 |

**弹窗与成交同源**：购单 CONFIRM 是**无阻塞**弹窗，它开着的时候秒级 tick 照跑 ⇒ 补货 / 手动刷新会把 `ws.shop.items` **整表替换**，回调里的 `idx` 便指向另一件货（实测：弹窗写「春风化雨篇 · 2,300 灵石」，点确认实扣 360 买走一件法器）。现由 `SQ.Shop.goodSig(it)`（`kind` + `ref` + 子货引用 + 法器属性组合 + `price/qiPrice/stones`）与 `SQ.Gear.itemSig(gear)` 给出**身份指纹**：视图开弹窗时记下、成交时经 `SQ.Actions.buy(ref, idx, black, expect)` 回传，引擎复查不符 ⇒ `reason:'stale'`、分文不动。**同一守卫覆盖破坏性那一面**：`SQ.Gear.salvage`（库藏炼化）会 `splice` 掉那一件，序号错位 = 销毁的不是玩家指的东西 ⇒ 同批加 `expect`。

**射程边界**：商人特席 `buyMerchant` **不走 CONFIRM**（点一下即下单）⇒ 无 stale 窗口，只上本节的先判后扣；黑市与坊市同走 `Shop.buy`（`black` 标志）⇒ 自动同判；`salvageArt` / 融合 / 淬炼 / 门中供给 / 遗泽购买按 **id** 或整表刷新，不属这一形。**溢出折算的去处**：`gainArt` 的 `dupValue` 半值返还**保留**，但从此只由**玩家没有选择权的所得**走到——秘境掉落（`combat.js:164`）与奇遇赠典（`events.js:336 / :346`）；坊市与特席那两处 `gainArt`（`shop.js:249 / :338`）已在扣钱之前被本节的 `undeliverable` 拦住，不会再撞上「已持有 / 架满」。批次详情 = 主设计 §七A 第 **68** 条。

### 6.1A 寿元表（LIFESPAN）与道伤槽（DAO_SHANG）〔🆕 寿元批 2026-10-15 · 第卌一批〕

本节是本游戏**第一条会让本世非自愿终结**的规则。此前一世只有两种结束方式：玩家主动兵解、或渡过飞升大劫（§6.1 与《轮回转世系统》§一）——「修炼卡住」从不付出代价，只原地等待。

**时钟口径（只有这一条，与修为同一条河）**：1 游戏年 = 360 秒**已结算时长**，即 `SQ.Idle.settle` 返回的 `hours × 10`；离线照 `OFFLINE_CAP_H`（12h）封顶。于是：

| 玩家行为 | 岁月流逝 | 修为产出 | 流逝 ∶ 产出 |
|---|---|---|---|
| 挂着页面 | 86,400 s/日 = 240 年 | 同额 × 在线乘区 | **1 ∶ 1** |
| 每日回归一次 | 12h 封顶 = 120 年 | 12h × `OFFLINE_EFF` 0.5 | **2 ∶ 1** |

⇒ 「关掉网页防老化」这条路不成立：离线照样计时，而离线产出打折，**常在线反而更省寿**。定标的意义在这里——寿元是**卡境的代价**，不是离线的惩罚。

**结论**：

1. **决策 Q1 的三个宣称口径全部复现**：魔道 ≈6 天（速通浅档 5.9 ✓）、左道 10~13 天（锚 13.3，压上沿 ✓）、正道 12~13 天（毕业画像 13.4 ✓）。典型同投资下：正道比左道慢 16~22%、魔道快 28%——「三种玩法风格」的节奏差成立；
2. **观察项 ①（典型魔道深档 0.79 超带）**：karmaMod −0.25 + 终局 p=0.35（期望失败 7.2 次）让深度入魔的同投资画像明显减速——这正是「快而险」的代价表达，判定为**设计意图内**，不改数值；若实测深档魔道流失显著，按 §九第 10 条路径先调 karmaMod −0.25→−0.20，不动 need 表；
3. **观察项 ②（速通魔道 0.44~0.49 低于带下限）**：验收带以「典型同投资」画像为对象，速通 build 属刻意优化画像（旧表速通 8.4/13.3=0.63 同样快于当年典型），不判违规；但新魔道 ×1.5 把优化上限推到 6 天以内——**若实测魔道选择率 >60% 且正道流失明显**，按优先级动 qiRateMult 1.5→1.4 或下调魔道分支收益（§九第 10 条既定路径），不动 need 表；
4. **渡劫手感差验证**：深魔期望失败 7.2 次 vs 深正 0.6 次——12 倍差距构成「稳而顺 vs 快而险」的体感主轴，与 §6.3 定位行一致；
5. **未计入项**：奇遇三分支收益（qi/qiPct，≈6.5 条/在线小时）对节奏的扰动未建模——登记于奇遇池设计 §十二.7，代码实施批以实机日志复核；事件经济若整体推快 >10%，优先下调人级收益带（该节既定优先级）。

### 8.3 渡劫奖惩阶梯（✅ 系统深化批 2026-10-02 · 已实施（实施收口 2026-10-03））

渡劫连续失败不应只剩「修为损半」一种反馈——失败要积累**可被成长消化的短期压力**，成功要有**高光时刻**。本节在既有渡劫结算之上扩展奖惩阶梯；**p 公式主体与全部既有承重常量零改动**（红线见 §8.3.4）。

#### 8.3.1 连续失败计数 `ws.tribulation.streak`

- 渡劫失败 +1、渡劫成功清零；整数 ≥0，normalize 缺省 0（旧档补齐）；
- 法宝 X09 续命 `skipAttempt` 生效（本次尝试不计）时，**streak 同步不 +1**——与 attempts 回退同源同结算；
- **结算顺序**（`tryBreakthrough` 失败分支的扩展，既有步骤相对次序不变）：法宝 `tribOnFail` 回调 → `retain` 覆盖损失系数 → 修为损失落账 → **streak 判定**（skipAttempt 生效则不计，否则 +1）→ **debuff 挂载**（道伤 / 封固，走 pushBuff 既有通道）→ **心魔记账**（层数写入）→ 吃一堑 / 养魂木 `tribulation.next` 一次性修正（既有通道，位置不变）→ 失败日志。成功分支：既有成功结算 → **streak 清零 + 心魔层清零** → 破境高光（§8.3.3）。

#### 8.3.2 失败惩罚阶梯（常量表 `TRIB_STREAK`）

```
TRIB_STREAK = {
  daoShang: { minStreak: 1, field: 'qiRate', mult: -0.15, hours: 12 },   /* 道伤 */
  xinmo:    { minStreak: 2, perStack: -0.01, maxStacks: 3 },             /* 心魔 */
  fengGu:   { minStreak: 3, field: 'qiRate', mult: -0.25, hours: 24 },   /* 修为封固 */
  logKeys:  ['tribulation.streak1', 'tribulation.streak2', 'tribulation.streak3']
}
```

| 档 | 触发 | 效果 | 通道与叠加口径 |
|---|---|---|---|
| **道伤** | streak ≥1 | qiRate −15%，12h（现实时间） | 既有 buffs 通道 pushBuff——同字段同向不叠加，重犯刷新时长、保留最强，天然满足「刷新不叠层」 |
| **心魔** | streak ≥2 | tribBonus −0.01/层，层数 = `min(streak − 1, 3)`（封顶 −0.03）；渡劫成功清零 | p 公式 **talent 加项**同读点（与雷纹 / 破障丹 / 气运并列加算，先加总后 TRIB_P_CLAMP，clamp 内生效） |
| **修为封固** | streak ≥3 | qiRate −25%，24h | 与道伤同通道 pushBuff：同字段同向保留最强一条（−25% 覆盖 −15%）、时长并行刷新 |

- **设计意图（心魔）**：给既有成长线一个「解药」出口——法宝 X01 鸿蒙紫气（失败累积气运）、护法位（+0.03/+0.06）、护体神光「吃一堑」（tribNext +0.05）全部进同一加项读点，投入过成长的玩家连败后可对冲乃至反转身魔；「险」因此是可备战的关卡，而不是纯数值惩罚；
- **日志与 UI**：每档触发写专属日志（词表 key `tribulation.streak1 / streak2 / streak3`，实施批随词表卷升版）；渡劫确认浮层增显当前心魔层数及其对 p 的影响（−0.0n）——UI 细节 UI 卷随实施批统一升版，本卷只登记口径。

#### 8.3.3 成功奖励「破境高光」（常量表 `TRIB_SUCCESS_BONUS`）

```
TRIB_SUCCESS_BONUS = {
  poJing:      { field: 'qiRate', mult: +0.50, mins: 30 },   /* 破境 buff */
  WIN_STONE_K: 300,        /* 一次性灵石 = ZONES[新境界].stones × 300 */
  FATE_P:      0.10,       /* 天道垂青 */
  wuLouKarma:  5           /* 无漏道基 */
}
```

- **「破境」buff**：qiRate +50%，30 分钟，走 pushBuff（增益与道伤 / 封固的减益**正负分开判、互不吞掉**，既有通道语义）；
- **一次性灵石** = `ZONES[新境界].stones × WIN_STONE_K (300)`，记 `in.event`（Ledger 同源锚，与奇遇灵石同分类；REALMS 与 ZONES 索引平行，新境界索引即 zone 索引）。例：筑基 → ZONES[1].stones 8 × 300 = **2,400**；渡劫 → 真仙 → ZONES[9].stones 15,000 × 300 = **450 万**（与 §九.5 终局刷图 ≈540 万/小时同量级、一次性发放，不通胀）；`WIN_STONE_K` 与 `FACTION_WAR.WIN_STONE_K`（§11.7，同为 300）**同名同值但为独立常量、不耦合**（一处调值不影响另一处）；
- **「天道垂青」**：成功时 `FATE_P = 10%` 概率触发一条带 **`trib_success` 标签**的专属奇遇——事件条目由《专属事件池设计》卷同批扩容（互指），本卷只定**触发机制与标签契约**：标签 = `trib_success`，触发复用奇遇 fire 落地五件套，once / 冷却 / seen 判定链与随机通道同口径（§12.3 通道公平同纪律）；池内无该标签条目时静默跳过（不报错、不空放）；
- **「无漏道基」**：成功时 streak = 0（本次为一击即中、此前无连败）→ **karma +5**（走既有 karma 记账通道，受 KARMA_CLAMP ±1000）+ 金字日志（词表 key 实施批随词表卷升版）。设计意图：给「一次过」轻奖励，与心魔「连败税」同构，双向强化「渡劫是关卡」。

#### 8.3.4 数值红线（实施批不得越界）

- **不改** p 公式主体结构（base + resistBonus + powerPart + talent + karmaMod + alignFlat + guardianBonus 先加总后 clamp）、`TRIB_P_CLAMP [0.05, 0.95]`、`REALMS` 表 `tribBase`、`TRIB_LOSS_BASE 0.5` / `TRIB_LOSS_CLAMP [0.30, 0.70]`——心魔是 talent 加项**内部**的负向加数，不是新公式项；

### 10.1 结构

- **全录 30 件**：**先天 12 件**（`x01~x12`，全局唯一，**认主**成长 `MAX_STAGE 3`，认主随渡劫成功推进——每 n 次渡劫 +1 阶）/ **后天 18 件**（`h01~h18`，**祭炼**成长 `MAX_LV 5`，耗资源升阶、三成机率失败降级）；**双书梗化扩容批 +6（先天 3 / 后天 3 → 先天 15 / 后天 21 = 36 件，见 §10.6）**；**双书梗化二批 +10（先天 4 / 后天 6 → 先天 19 / 后天 27 = 46 件，见 §10.7）**；
  - 🆕 **勘正（第卌三批 · 用户令「认主要渡劫才涨进度，太慢了」）**：上面那句「每 n 次渡劫 +1 阶」是**当时的单通道口径**，现已改为**双通道共喂一枚计数**——`bondCount` 由 ① 渡劫成功 +1/次 与 ② 每 `BOND_HOURS: 8` 小时**已结算时长** +1 份 两路同加，`BOND_COST: 2` 的 modulo 与 `bondAdvance` 推进口**只有一条**（不另立升级路）。计时通道挂在世界包 claim 的结算之后，与寿元同一条时钟（离线照 `OFFLINE_CAP_H` 封顶 ⇒ 每小时产的份数在线离线同值），先天法宝全部满阶即**停表**（不再无意义长计数）。落盘新增 `ws.treasures.bondHours`（未满份的余数，旧档补 0 零迁移）。渡劫仍是**更快**的一路：中期两次渡劫 ≈1~2 小时，快于 8 小时/份 ⇒ 计时是「卡境时不停摆」的下限而非替代。判据 = 冒烟 **#307**（七判，含 (g) 走真入口 `pack.claim`）。

### 12.1 机制摘要

- 在线按现实分钟节奏刷新的**限时传闻卡**（`rumorClock` 每跨 `REFRESH_MIN=10` 分钟掷一批 `BATCH=[1,2]` 条，活跃上限 `MAX=4`），指向当前角色**可触发**的事件（抽取复用 `natureDraw` + 阵营 `tierW` + `buildPool` 全过滤 + 天→地→人降级回退，再滤活跃卡已指向 evId）；
- TTL 按品阶：人 40 / 地 70 / 天 110 现实分钟；**离线只过期不刷新**（绝对时间戳判定，与「离线零奇遇」正典对齐；回归聚合日志「江湖事过境迁」）；
- **触发** = 主动点击「前往查证」：校验链（未过期 / pendingChoice 空 / condOk 复核 / 非 once 已见 / 非冷却中）→ 落地五件套照抄 fire（冷却/lastId/seen/pendingChoice，`via:'rumor'`）——**不清 eventClock、不消耗 eventShield**（独立通道）；抉择模态、判定 DSL、resolveBranch、图鉴、feed 全链路与随机奇遇零差异；
- **过期** = 未触发即作废：once/冷却/seen 均未消耗，事件可再次出现；在线静默移除、离线回归聚合日志；
- **war 卡**：势力冲突开战推送 `{kind:'war'}` 传闻（TTL = 冲突剩余时长，不占 MAX 名额），**交战方**卡内「应战」按钮点击跳势力页/应战 CONFIRM，**非交战方只读「观望」无按钮**（走查修复批 2026-10-02，§11.7 联动）；
- 文案：common 词表 `rumor.tpl.{tier}.1~10` 模板 × `rumor.place.1~8` 地点池（生成时掷定入档 `tpl/place`，不剧透事件名；世界分卷可覆写）。

### 12.2 常量与存档

```
RUMORS: { MAX: 4, REFRESH_MIN: 10, BATCH: [1,2], TTL: { ren: 40, di: 70, tian: 110 }, TPL_PER_TIER: 10, PLACES: 8 }
worlds.{id}.rumors = [{rid, evId, tier, nature, bornAt, expireAt, tpl, place} | {rid, kind:'war', bornAt, expireAt}]
worlds.{id}.rumorClock = 0    // 在线累计秒；normalize：结构校验 + 过期/未知 evId 丢弃
```

### 12.3 红线

- 经济零新增：只改事件触达方式，不改任何事件收益（双锚缩放与事件池 §十三勘误全沿用）；
- 通道公平：与随机通道同一套 once/冷却/seen/独占判定链语义；
- 引擎 `rumors.js` 零裸中文（CJK 纪律 A1 同口径）；#161 冒烟段预登记。
