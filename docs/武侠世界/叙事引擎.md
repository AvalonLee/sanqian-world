## 一、界面：一卷书

主界面 = **一册可翻的线装书**，不是 tab 页面。

```
┌──────────────────────────────────────────────┐
│  第二卷 · 第三章  雨夜渡口          卯时 · 湘潭 │ ← 页眉（卷/章/场景/时辰地点）
├──────────────────────────────────────────────┤
│                                              │
│   他睁眼时，天还没亮。檐水一滴一滴，           │ ← 正文（62%，行高 1.9，19.5px，栏宽 34 字）
│   敲在青石上，像是有人在数着什么。             │
│                                              │
├──────────────────────────────────────────────┤
│  ※ 这一句，你要不要落笔？                     │ ← 朱批区（18%，可滑出，收合后不留占位）
│  〔批〕〔改〕〔不动〕                          │
├──────────────────────────────────────────────┤
│  三流 · 功力 412/1200 · 银 3 两 2 钱 · 侠名 +12│ ← 页脚（8%，一行细窄；数值只在此出现）
└──────────────────────────────────────────────┘
```

| 分区 | 占比 | 说明 |
|---|---|---|
| 页眉 | 12% | 卷章题 + 时辰地界（细字，无边框） |
| 正文 | 62% | 中文阅读最佳行长 34 字 |
| 朱批 | 18% | 分岔时可滑出，收合后不留占位 |
| 页脚 | 8% | 功力 / 境界 / 银两 / 侠名 / 墨（**唯一露数字的地方**） |
| 书签（悬浮） | — | 目录 / 功谱 / 人物 / 舆图 / 存档（右下角抽屉） |

**原九页（坊市 / 炼丹 / 法宝 / 江湖榜 / 宗门 / 成就 / 轮回 / 日志 / 设置）在本世界不出现**，只保留「书 + 附录四页」。这是刻意砍的：**形态不减法，两个世界就会长得一样**。

## 二、三层结构

| 层 | 规模 | 时长（在线） | 作用 |
|---|---|---|---|
| **卷** arc | **18~24 章** | 0.8~1.2 小时 | 一条主线（血仇 / 寻亲 / 夺宝 / 护人 / 复仇） |
| **章** chapter | 4~6 节，800~1500 字 | ≈2 分钟 | 一个场景单元 |
| **节** beat | 200~400 字 | ≈22 秒 | 一个动作或一段对话 |

一局 = **10 卷 × 20 章 ≈ 200 章**，在线 7~9 小时（全程快进可压到 5 小时），现实跨度 5 天。

> **🔧 册152 勘正**：草案 §七 原写「卷 30~50 章 / 1~1.7 小时」，与 §2A.1 二改后的「18~24 章」冲突，现行取 **18~24**（与 §五 的时间跨度推算、数值验收表同源）。

## 三、状态机

```
arc      卷：{ id, title, act(1~3), chapterFrom, chapterAt }
chapter  章：{ no, title, scene, place, time, beats[], written }
beat     节：{ no, type, text, fork?, done }
```

一个 `ws.narrative` **只持「当前卷 / 章 / 节」三个指针 + 最近 3 章正文缓存**，全文流水进侧档（复用第一世界 `sanqian-logs-v1` 的展示流思路，避免主档膨胀）。

> **存档纪律**：`narrative.cache` 上限 3 章，超出的正文不落主档——这是主档容量红线（第一世界 `probe-savecap` 同型判据）。

## 四、八种节类型

| 类型 | 作用 | 出 ※ |
|---|---|---|
| `scene` | 写景、转场（**开章必一**） | 否 |
| `action` | 动作（赶路 / 交手） | 可 |
| `talk` | 对话 | 可 |
| `think` | 心念（性格轴的自我陈述） | 否 |
| `event` | 奇遇触发（接事件池） | 视事件 |
| `gain` | 所得（得书 / 得物 / 破关） | 否 |
| `fork` | 纯分岔位 | **是** |
| `cliff` | 章末悬念 | 否 |

> **入码（册229 现行落点）**：书形态退役后，八种节里**只有三种有真消费**——`action`（闯荡遇敌，78 条）、`scene`（到达地界写景，13 条）、`gain`（平安步拾遗，13 条）。`talk`（26）与 `event`（18）两型的素材**已退役**：对话由 KNOTS 场面执行器承担、奇遇触发由 WORLD_EVENTS 承担，留着就是第三、第四套重叠入口。`think` / `fork` / `cliff` 三型从未落数据（属章骨架层，随 `pack.narrative` 一并退役）。**教训**：给事件表加新 kind 前先确认「谁读它」——书形态的模板三成是零消费预备料，退役比补消费点便宜。

## 五、章骨架（固定，不许自由拼）

```
scene → [action|talk] ×2~3 → [event|gain]? → fork? → cliff     （4~6 节）
```

**固定骨架的理由**：每章形状一致，模板复用率才高；且玩家熟悉节奏后，「※ 出现在哪」本身就是阅读预期的一部分。

**中段差异化改的正是配比，不是骨架**：复仇线 `action` 多 · 查真相线 `talk` 多 · 逃亡线 `scene` 多。骨架不动、血肉随机——这是「不做随机事件大乱炖」的落点。

## 六、模板三层与数值→文学

```
scene.{placeKey}.{weather}.{time}      写景
act.{kind}.{intensity}.{tone}          动作
talk.{whoKind}.{mood}.{topic}          对话
```

变量池：`{name}` 主角 · `{master}` 尊长 · `{foe}` 对手 · `{sect}` 门派 · `{art}` 武功 · `{place}` 地界 · `{n}` 数值。

**数值→文学三条硬规则**（禁止「内力 1240 点」上屏）：

| 规则 | 做法 |
|---|---|
| 百分比化 | `>70%` 尚有余力 / `30~70%` 只余半数 / `<30%` 几近枯竭 |
| 时间模糊化 | `>30 日` 月余 / `3~30 日` 旬日 / `<3 日` 三两日 |
| 数量约略化 | `>100` 百十来个 / `<5` 三五个 |

容量估算：**500~800 条骨架句 + 6~8 类词池**可支撑十万字级多样性（第一世界 5029 键词表的积累是这套的直接前身，路径已验证）。

## 七、默认选择与分岔生成

**无干预时**，主角按性格三轴 + 数值自动选——这就是「书自己在写」：

```
score(opt) = 0.4·personaFit + 0.4·feasible + 0.2·relationTilt + rand(-15, 15)
```

| 项 | 含义 |
|---|---|
| `personaFit` | 选项倾向与性格三轴的点积（侠轴 +80 时「救人」+40、「夺物」−40） |
| `feasible` | 数值门槛（境界 / 武功 / 内伤）够不够——**不够的选项直接不生成**，这就是「养决定有没有得选」 |
| `relationTilt` | 在场人物与主角的关系值 |

**分岔规则**：

- 每章 **≤2 个 ※**，位置在 `[action|talk]` 之后
- 每个分岔 2~3 个选项，**必须含一个保守项**（退 / 忍 / 不动）——保证任何数值下都有得选（这是「不设硬墙」的写法）
- 选项元数据：`{ id, labelKey, inkCost, axis:{xia?,kuang?,du?}, req:{realm?,art?,injury?}, effect }`
- **卷末枢纽**（每幕 3~5 个）**不出 ※**：走向写死，保底剧情骨架，防止玩家把书写崩

## 八、离线提要

不在线时**只结算数值与指针，不生成正文**。回归时按章聚合：

```
第七卷 · 第 12~19 章（你离开的三日）
· 第十二章 破庙夜雨 —— 他避雨入庙，撞见三名刀客分赃。
· 第十三章 刀口舔血 —— 一场混战，他折了两根肋骨，夺下一口好刀。
…（最多 8 行，超出折叠为「…共 8 章」）
```

> 这是放置类的情感核心：**他离了你也活得好好的，只是走得不太一样**。回归看到的是**结果**，不是「待处理事项」。

## 九、打字机三条实现纪律（取自本仓前科，违反即返工）

1. **只追加不重建**：逐字用 `appendChild` / 改 `nodeValue`，**不整段 `innerHTML +=`**，更不整页重建。册147 的「明细浮层每秒闪烁」就是整页 `innerHTML` 重渲 + 常驻入场动画两个错叠加。
2. **入场动画挂「新帧类」**（如 `p.on` / `chapter.fresh`），**不挂常驻元素**——凡在 `renderAll` 重渲范围内的浮层，动画挂元素本身就会每次重播。
3. **「跳过」= 一次性写入剩余字符**，不许把 `speed` 调大模拟（会留半帧与定时器泄漏）。

**另外两条页面级纪律**（册152 原型四轮踩出来的）：

- **纸面滚动完整配方** = 背景无有界装饰 + 固定栏与纸面同色且不透明 + 固定栏边缘 **22px 纸色渐隐**。三条缺一即出现「硬切半行」或「色带断层」。
- 正文段落用「首帧透明 + `.on` 显形」时，选择器必须限定**直接子元素**（`#body > p`），否则容器里任何 `<p>` 都会被隐藏。

### 10A.3 `chapter()` 章生成骨架（本批实现）

`pack.narrative.chapter(ws, pk, ctx)` 已在 `index.js` 实现（G18 可选契约第一份实现）：

1. `scene` 节取当前地界子场景
2. 中段 3 节从本地界事件池取（章内不重复，用**章号确定性散列**选取 —— `chapter` 是纯函数，同输入同输出，**不调 Math.random**）

### 10A.4 正文渲染 `render()`（S1-d 落地 · 册158）

`pack.narrative.render(chapterResult, ws) → { lines:[中文…], fork }` —— 把 `chapter()` 的骨架变成纸上的字。**纯函数**，同输入同输出。

**模板三层**（`lexicon-tpl.js`，73 键）：

| 层 | 内容 | 数 |
|---|---|---|
| 一 | 节级句式 `tpl.<type>.<n>`（占位符 {scene}/{who}/{p1}/{mood}） | **60** |
| 二 | 词池与措辞 `pool.*`（功力五档 / 心境四档 / 门槛回声四族 / 通称） | 13 |
| 三 | 数值→文学（`progWord` 五档映射 + `renderBeat` 组装） | 函数 |

**三条硬规则的兑现位置**：

1. **门槛不显示数字只给回声**：think 节功力未足 75% 时追加 `pool.echo.*`（「自家功夫还差着一重火候，急不得。」）——措辞按「有无门派/熟人」分族；
2. **每章至多一个 ※**：`chapter()` 已保证，render 不追加；
3. **门槛须可推断**：think 六条模板**全部**含 {p1} 功力措辞（初稿只有 2 条带，确定性散列下规则未必可见，E11 抓到后改）；**心境是状态不是随机文案**——非平静（违和 ≥60 / 内伤）时 render 在章尾**稳定追加**心境句，不靠模板命中。

**红线 = 纸上无机器**：渲染输出不允许出现 `{` 残留、`tpl.` / `pool.` 等裸键名（E11 全文扫描）。缺模板宁可少一句，不印键名。

```

你察觉背后有目光，回头时却只见巷尾一闪而过的衣角。
邻座几位江湖客正为一桩悬案争得面红耳赤。
酒过三巡，那人终于吐出一个名字——随即四下张望。
明日要走的路在心里又数了一遍。内息尚在初起，夜还长。自家功夫还差着一重火候，急不得。

总觉得这世道哪里不对，却又说不上来。
```



### 10A.5 书界面「先睹」（S1-e 落地 · 册159）

`view/wuxia-book.js`：创角屏择界卡上，**装了叙事包的 coming 世界**给一枚「先睹」钮 → 打开书浮层（逐句打字机 + 章头/页脚 + ※ 分岔框）。

**三条纪律（照抄原型）**：① 打字只 appendChild/改 textContent，不重建正文区 innerHTML；② 点纸面即跳过；③ 定时器族集中件内私有，合上逐枚 clear。

**预览不落档（立身之本）**：会话态（假 ws = `normalize(initialState())`、章号、分支选择）全在件内私有，合上即散 —— `coming` 语义一字不改，localStorage 不产生存档（走查 W6 钉）。

**入口接线**：按钮走全局 `data-act` 委托（无独立监听体，D15①）⇒ 派发器转发**不取 ctx()**（冷启无档，ctx 会读 ws 抛错 —— 册159 实测踩坑）。

**判据 = 走查 `verify-ui-wuxiabook` 7 判**（钮唯一 / 浮层与章头 / 跳过落纸 / 纸上无机器 / 合上即收 / 不落档 / 零报错）。边界：预览会话初始 realm 0 ⇒ 首章通常无桥段分岔（need 未达），分岔形态由 E10/E11 数据背书，有分岔的 UI 走查判等转 live 后补。

### 10A.6 章推进 `advance()`（S3-a 落地 · 册160）

`pack.narrative.advance(ws, opt, ctx)` —— 翻过一章的**数值面**（正文仍由 `chapter()`/`render()` 出，本口只管账）。纯函数纪律同 `chapter()`：章号散列定日，**不调 Math.random、不读实时钟**；只写传入 `ws`。

| 事务 | 规则 | 出处 |
|---|---|---|
