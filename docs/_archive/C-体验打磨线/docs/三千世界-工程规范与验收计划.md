## 一、词表层规范（G11）

### 1.1 取词规则

- 所有面向玩家的文案 **一律走 `t(key)`**，源码中不允许出现裸中文常量（日志模板、按钮、标题、词条名、事件文案全覆盖）；
- 词表按 `profile.worldId` 加载：`common` 基础词表 + 世界词表覆盖（世界词表缺 key 时回落到 common，common 也缺时 **直接显示 key 本身**——让遗漏在界面上肉眼可见，而不是静默空白）；
- 词条支持插值占位：如 `log.tribulation.success = "渡劫成功，境界晋升为 {realm}"`，占位符统一 `{snake_case}`。
- **世界包词族契约（v1.0）**：哪些键族属于「世界身份」、live 世界必须/建议/禁止覆写，见 [`三千世界-世界包词族契约.md`](三千世界-世界包词族契约.md)；机读镜像 `SQ.LEX_CONTRACT`，审计 C 组（C1 must 族覆盖 / C2 forbid 族零命中）按契约对账。`tab.`（菜单描述）族由世界分卷拥有——「修行 → 战争」这类整体换皮为纯数据改动。

### 1.2 key 命名规范

```
{domain}.{item}[.{sub}]     全小写 snake_case，层级 ≤ 3
```

| domain | 覆盖内容 | 示例 key |
|---|---|---|
| `resource` | 主资源、货币、战力等数值名 | `resource.primary`（修为）/ `resource.currency`（灵石） |
| `realm` | 阶位体系名 + 各阶位名 | `realm.system`（境界）/ `realm.3`（元婴） |
| `idle` | 挂机动作与状态文案 | `idle.action`（打坐）/ `idle.cap_full` |
| `combat` | 战斗区域体系 + 各区名 + 瓶颈提示 | `combat.system`（秘境）/ `combat.zone.1` / `combat.bottleneck` |
| `gear` | 装备体系名、槽位名、品阶名 | `gear.system`（法器）/ `gear.slot.weapon` / `gear.tier.4`（灵品） |
| `skill` | 技能体系名 + 各功法名与描述 | `skill.system`（功法）/ `skill.tuna.name` |
| `shop` | 商店体系名、按钮、黑市 | `shop.system`（坊市）/ `shop.refresh` / `shop.blackmarket` |
| `event` | 事件名 / 叙事 / 三分支文案 / 日志（v2.0 口径） | `event.cave_find.name` / `event.cave_find.story`（100~200 字叙事）/ `event.cave_find.branch.right\|evil\|neutral`；旧 `.text/.a/.b` 废止 |
| `talent` | 天赋名与描述 | `talent.gifted.name` / `talent.gifted.desc` |

### 1.3 完整性审计（P3 验收手段）

- 审计脚本思路：扫描 `view/` 与 `assets/systems/` 源码中的 CJK 字符字面量，白名单（注释、词表文件本身）之外出现即报错；
- 每个世界包交付时跑一遍「key 对账」：词表 key 集合 ⊇ 代码引用的 key 集合，缺失清单直接输出。

## 二、世界注册表与世界包契约（G10）

### 2.1 registry 条目字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一，snake_case（xiuxian / guwu / magic / tech / urban / cthulhu） |
| `displayName` | string | 走词表 `world.{id}.name`，registry 只存 key 引用 |
| `status` | enum | `live` 可投生 / `coming` 灰显待开启 / `hidden` 完全不露出 |
| `nameParts` | object | 世界名生成池 `{prefix[], middle[], suffix[]}`（部分世界可只有两段） |
| `tags` | string[] | 世界卡关键词标签（3 个为宜，词表 key 引用） |
| `pack` | object | 世界包实现引用，见 §2.2；`coming/hidden` 世界可为 null |

### 2.2 世界包必须提供的契约（live 世界）

| 契约项 | 职责 | 消费方 |
|---|---|---|
| `lexicon` | 本世界全量词表；**按世界包词族契约覆写 must 族**（系统名/菜单描述/资源名/阶位名…），见 [`三千世界-世界包词族契约.md`](三千世界-世界包词族契约.md) | G11 |
| `initialState()` | 返回该世界存档初始值（含专属字段：修仙 = karma + tribulation） | G1 core |
| `normalize(raw)` | 该世界存档缺字段补齐 | G1 core |
| `claim(ws, dt, now, profile)` | 时间差结算入口（挂机产出、渡劫掷判、buff 过期、事件触发全在此编排；profile 供天赋乘区读取，P4 登记） | G1 core |
| `realms` / `zones` / `gearTiers` / `arts` / `shopPool` / `events` / `talents` / `caves` / `companions` | 各系统数据表（对应详设文档各表；`caves`/`companions` 为 G13/G14，v2.1 登记） | G2~G8 / G13 / G14 |
| `attributes` | 属性定义（2~4 条：id/词表 key/dc 标准线规则/被动效果映射），修仙 = 精气神 | G12 |
| `specialHooks` | 特殊词条/特殊属性效果注册表：`{ id → { 挂点, 参数 } }`；挂点白名单（引擎标准事件点，**17 项**）：`on_kill_stones`（击杀货币）、`on_kill_drop`（击杀追加掉落）、`on_claim_qi`（收功主资源）、`on_claim_stones`（收功货币）、`on_tick_idle`（挂机 tick）、`on_negative_event`（负面奇遇处理）、`on_debuff_apply`（debuff 时长）、`on_bottleneck`（瓶颈间隔/战力）、`on_trib_fail`（突破失败损失）、`on_trib_next`（下次突破判定修正）、`on_check`（属性判定修正）、`on_shop_refresh`（刷新费）、`on_refine`（炼化返还）、`on_shop_price`（商店价格）、`on_offline_cap`（离线上限）、`on_cave_enter`（入驻洞府，v2.1）、`on_cave_mult`（caveMult 结算唯一读取点，v2.1）；世界包只能挂白名单挂点，**禁止自造引擎钩子** | G4/G5/G6/G7/渡劫·攻关/G12 |
| `worldSystems` | 专属系统定义（修仙 = 善恶 + 渡劫的判定规则数据） | 专属 UI 与 claim |

**边界纪律**：通用系统（G2~G8）只读世界包的数据表，不 import 世界包内部模块；专属系统可以读通用状态、通用系统对专属字段 **只透传不解释**（core 不知道 karma 是什么，只负责存取）。

### 2.3 命名生成器规则

- 从 `nameParts` 各段独立随机拼接；生成时机 = 创角屏 3 首次渲染；
- 结果 **固定写入 `profile.worldName`**，此后所有界面只读不再生成；
- 去重不强求（名字池组合数 ≥ 300 时碰撞概率可接受），但同一次创角会话内重进屏 3 不重掷（防「刷世界名」）。

### 3.6 存档纪律

- **异步桥契约（x-hub 规范）**：`xhub.storage` 是异步 Promise、按扩展隔离、跨形态（module/view）共享同一份——`load/save/claim/mutate` 全链路 async，入口用 **boot 模式**（先 `await` 读档再首绘，禁止顶层同步读）；`localStorage` 回退**仅限无宿主浏览器预览**（`typeof window.xhub === 'undefined'` 分支）；
- **单一写入通道**：一切状态变更走 `mutate`（玩家操作）或 `claim`（时间结算），禁止旁路直写存储；
- **karma 是缓存**：任何影响 karma 的变更（换装/升级功法/事件选择）后触发重算，重算公式见事件池文档 §五；存档里的 karma 值仅用于读取加速，以重算结果为准；
- **时间戳统一 ms**；所有「未来到期」字段（buff 到期、补货时间）存绝对时间戳，不存剩余秒数（防改系统时间刷 buff 的成本最低化，本期接受该作弊面）；
- **版本号规则**：结构变更 → `v` +1，并在 core 登记「v(n-1) → v(n) 迁移规则」；同版本内新增字段走 normalize 补齐不升版本。

## 七、平台接入规范与发布清单（x-hub）

> 依据《x-hub 扩展开发规范》（平台附件）校准，P1 起全程生效；与本文档冲突时以平台规范为准。

### 7.1 manifest 完整声明（定稿）

```json
{
  "id": "com.avalonlee.sanqian-world",
  "name": "三千世界",
  "version": "0.3.0",
  "runtime": "web",
  "kind": "view",
  "surfaces": ["module", "view", "window", "drawer"],
  "openIn": ["view", "window", "drawer"],
  "entry": {
    "module": "./module/index.html",
    "view": "./view/index.html",
    "window": "./view/index.html",
    "drawer": "./view/index.html"
  },
  "minSize": { "w": 380, "h": 620 },
  "moduleVariants": [
    { "id": "standard", "name": "标准", "minW": 3, "minH": 3, "idealW": 4, "idealH": 3 },
    { "id": "compact", "name": "紧凑", "minW": 2, "minH": 2, "idealW": 2, "idealH": 2 },
    { "id": "wide", "name": "通栏", "minW": 4, "minH": 2, "idealW": 6, "idealH": 2 }
  ],
  "icon": "./icon.svg",
  "description": "多世界放置修仙：起名、抽天赋、择界重生，挂机渡劫证道真仙",
  "permissions": []
}
```

- `id` 为开发者自有反向域名（`com.x-hub.*` 是平台保留段，禁用）；全小写、含 `.`、≤128 字符 ✓；
- `version` 必须三段纯数字（`0.3.0`），发布弹窗会自动递增补丁号写回；
- **四形态齐备（界面批五登记）**：`surfaces` 含 `module / view / window / drawer`；`window` 与 `drawer` **复用 `./view/index.html`** 同一入口文件——三种运行形态经 `xhub.storage` 共享同一份存档，切换形态不丢进度；
- `openIn` 声明 `view / window / drawer`（`module` 为卡片形态，不可直接 `openIn`）；
- `minSize` 声明 `380×620`（窄屏单列布局下限）；不声明 `moduleOptions`（默认无宿主表头，卡面自绘）；
- `moduleVariants` 声明三形态 `standard / compact / wide`，同一 `module/index.html` 用 `:root[data-xhub-variant]` 属性选择器分支布局（工程约定）；
- 不声明 `network` / `data:*` / `fs` / `open-url` / `events` / `shared-storage`——本扩展只用免权限 API（`storage.*`、`runtime.info/open`、`events.on`、`theme.get`、`config.*`）。

### 7.2 开发纪律（平台易错点对策）

1. **桥由宿主注入**：直接调 `window.xhub.*`，不 import 任何包；能力可用性以运行期 `runtime.info().capabilities` 为最终权威；
2. **静态扫描是纯文本匹配**：注释、字符串、示例里出现 `xhub.data.…` / `xhub.net.…` 等未声明权限的调用字样会被判「用到没声明」直接 error——文档示例不要抄进源码注释；
3. **planned API 禁用**：`clipboard.* / net.* / system.* / ui.* / fs.readText 等受控读写` 未实现，勿依赖（`ui.toast` 不存在——游戏内 toast 全部自绘 DOM）；
4. **外链**：`window.open` / `target="_blank"` 在宿主静默失效；本扩展无外链需求，若未来加「官方群/反馈页」必须走 `openExternal` + `open-url` 权限；
5. **存储**：异步 boot 模式（§3.6）；键名 `sanqian-state-v1` 在扩展隔离空间内唯一即可；宿主自己的 `.storage.json` / `.config.json` 不要当数据目录用；
6. **web 运行时无落盘需求**：本扩展不写文件（无 service 后端、无 `.data/` 目录）；导出存档等需求未来若做，走 `fs.saveText`（需补 `fs` 权限声明）；
7. **入口 HTML**：零 CDN、零构建，本地相对路径引用 `assets/*.js`；语言 `lang="zh-CN"`；viewport 声明齐全。

### 7.3 发布上架流程（P8 前或用户要求上架时执行）

1. 客户端「发布」→ 本地预检（与 4.9 平台关卡组同口径）→ 打包 `.xhpack` 上传；
2. 平台机器关卡：包结构 / manifest / 入口文件 / 权限申报对账 / 静态扫描 / 版本递增；
3. 人工审核 → 签名上架，已装用户自动更新；
4. 截图物料：1~3 张（主界面修行页 + 创角三屏 + module 卡），单张 ≤2MB；
5. 发布者身份前置：账号登录 → 邀请码 → 申请开发者（首次发布前预留审核时间）。
