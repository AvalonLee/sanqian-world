## 一、设计原则

1. **效果全部挂通用系统乘区**：天赋不写死数值逻辑，只声明 `effects` 字段，由对应系统（挂机/战斗/商店/事件/突破）在计算时读取，保证换世界后引擎不用改。
2. **正负分明**：每条天赋要么是纯增益（`positive`）、要么是纯减益（`negative`），不做混合双刃剑——「高风险高回报」的体验由 **组合规则**（1正+2负）提供，而不是单条天赋内部对冲，UI 上玩家一眼能读懂。
3. **池分两层**：`common`（跨世界通用，进任何世界都可抽到）+ 世界专属（如 `xiuxian`，只在对应世界创角时进池）。
4. **稀有度用权重表达**：不设显式 tier 弹窗，强力词条权重低、出现即惊喜；数据结构保留 `tier` 字段仅供配色/展示（普通=常规色，稀有=高亮色）。
5. **重抽规则**（已拍板）：创角阶段无限免费重抽，同一次 roll 内不出现重复词条；点「确认」写入 `profile.talents` 后永久锁定。

## 二、数据结构

```js
// talents/common.js / talents/xiuxian.js 中的单条天赋
{
  id: 'gifted',              // 全局唯一，snake_case
  name: '天资聪慧',           // 显示名（未来走 t() 词表）
  kind: 'positive',          // 'positive' | 'negative'
  tier: 'common',            // 'common' | 'rare'（仅影响展示配色）
  world: 'common',           // 'common' | 'xiuxian' | …
  weight: 10,                // 抽取权重
  desc: '修为产出 +15%',      // UI 描述（由 effects 生成或手写）
  effects: { qiRate: 0.15 }  // 乘区声明，见 §三
}
```

### 抽取算法（伪代码）

```js
function rollTalents(worldId) {
  // 1. 决定组合：40% → 1正1负；35% → 2正1负；25% → 1正2负
  const combo = pickCombo();          // {pos: 1|2, neg: 1|2}，pos+neg ≤ 3
  // 2. 组池：common 池 + 当前世界专属池
  const posPool = [...COMMON_POS, ...WORLD_POS[worldId]];
  const negPool = [...COMMON_NEG, ...WORLD_NEG[worldId]];
  // 3. 按 weight 加权无放回抽取
  let talents = pick(posPool, combo.pos).concat(pick(negPool, combo.neg));
  // 4. 单正单负组合 → 正面天赋效果 ×1.5（「极致单一」规则）
  if (combo.pos === 1 && combo.neg === 1) amplify(talents, 1.5);
  return talents;
}
```

> `amplify` 只放大 `effects` 中**对玩家有利方向**的数值 ×1.5（如 `qiRate: 0.15 → 0.225`，`shopCost: -0.10 → -0.15`），显示描述同步重算，保留 1 位小数百分比。

## 三、效果字段字典（乘区约定）

| 字段 | 含义 | 作用系统 | 备注 |
|---|---|---|---|
| `qiRate` | 主资源产出倍率（加算） | G2 挂机 | 0.15 = +15% |
| `qiCap` | 挂机积累上限倍率 | G2 挂机 | |
| `offlineEff` | 离线产出效率修正 | G2 挂机 | |
| `stonesRate` | 货币（灵石）获取倍率 | G3 战斗 / G6 商店 | |
| `combatSpeed` | 战斗推进速度倍率 | G3 战斗 | |
| `combatPower` | 战斗力修正 | G3 战斗 | 同时影响渡劫 resistBonus 的「战力项」（配装富余度，见数值详设 §6.3） |
| `dropRate` | 装备（法器/兵甲）掉落率倍率 | G3 战斗 | |
| `gearLuck` | 掉落品阶权重向高档偏移 | G4 装备（修仙=法器） | |
| `artsSpeed` | 功法升级速度/消耗修正 | G5 技能 | |
| `shopCost` | 商店价格倍率（负值=便宜） | G6 商店 | |
| `eventRate` | 奇遇触发频率倍率 | G7 事件 | |
| `eventLuck` | 奇遇正/负偏向 | G7 事件 | 正值=好事多，负值=祸事多 |
| `realmCost` | 突破（升境界）修为需求修正 | G8 阶位 | 负值=需求更少 |
| `tribBonus` | 渡劫成功率加算 | 渡劫系统 | 修仙专属，进 p 公式 |
| `tribFailLossMod` | 渡劫失败修为损失修正 | 渡劫系统 | 基准 0.5；-0.10 → 只损 40%；+0.10 → 损 60% |

> **世界专属字段规则**：`tribBonus` / `tribFailLossMod` 仅在修仙池生效；古武军势包新增 4 个专属字段——`gateMod`（攻关线修正）、`routMod`（攻关失败损兵修正）、`xiaGain`（侠名获取修正）、`bannerBoost`（旗帜效果放大），仅在古武池生效（见 [`古武军势/专属天赋池（80条）.md`](./古武军势/专属天赋池（80条）.md)）。通用池词条永远只用世界无关字段。

## 六、组合期望与平衡说明

### 6.1 单次 roll 的组合分布

| 组合 | 概率 | 正面强化 | 体验定位 |
|---|---|---|---|
| 1 正 + 1 负 | 40% | 正面 ×1.5 | 极致单一：一个鲜明长板 + 一个短板 |
| 2 正 + 1 负 | 35% | 无 | 主流均衡 |
| 1 正 + 2 负 | 25% | 无 | 高风险高回报（未来可考虑给额外补偿，见 §6.3） |

### 6.2 专属词条出现率（修仙世界创角，v1.3 二轮扩容后）

- 正面池：28 通用 + 40 专属 = 68 条；专属词条权重占比 ≈ **53%**——平均每次 roll 的正面位一半以上是修仙专属；稀有专属（雷灵根/历劫之躯/剑道奇才/天道垂青等 14 条）合计权重占比 ≈ **16%**，平均 6 次重抽见一次，惊喜感保留；
- 负面池：22 通用 + 40 专属 = 62 条；专属负面权重占比 ≈ **61%**——短板的世界观味道进一步拉满；
- 扩容守则复盘（两轮均执行）：全部词条只用 §三 字典字段、单条幅度不超过同乘区既有最大值（tribFailLossMod 最深仍为历劫之躯 -0.15，新增 -0.06/-0.08 均在其下）、稀有度用权重表达（稀有 4~5 / 普通 6~8）；
- **词条密度控制**：同一乘区的近似词条（如 qiRate 系）刻意保留梯度（+3%~+15%），组合期望见 §6.3。

### 6.3 平衡待办（P5 复查）

1. **1正+2负 是否给补偿**：当前无额外补偿，纯靠玩家自愿选择。若数据上没人选，可加「逆境之子」隐藏修正（如全乘区 +5%）；
2. **`tribBonus` 上限核对**：雷灵根(+0.15) + 道心通明(+0.08) 若同时出现（2正组合），叠加装备/善恶后 p 已被 `clamp(…, 0.95)` 封顶，无需额外处理，但要在冒烟测试里验证 clamp 生效；
3. **`combatPower` 与渡劫的联动**：`combatPower` 修正会间接抬高 resistBonus 战力项（`(战力/境界基础战力−1)×0.15`，封顶 0.15），剑骨(+15%)的实际渡劫收益已被该项封顶自然约束，P5 按数值详设 §6.3 对表复核即可；
4. **amplify ×1.5 的舍入**：统一「乘后四舍五入到整数百分比」，避免 0.225 这类三位小数进 UI。

## 七、UI 呈现约定（P2 三屏之「屏 2」）

- 卡片布局：正面词条 **绿系高亮**、负面词条 **红/灰系**，`rare` 加描边或角标；
- 每张卡显示：名称 + 一行描述（由 `desc` 直出，不显示 id/weight）；
- 顶部显示当前组合类型（如「2 正 1 负」）；「重抽」按钮无限次；「确认锁定」按钮需二次确认（提示「确认后天赋永久锁定」）；
- 单正单负组合时，正面卡追加「极致单一 · 效果增强」角标，解释 ×1.5 来源；
- 词条描述未来接入词表层后走 `t('talent.gifted.desc')`，各世界可对同一通用词条换皮（如 `stonesRate` 在古武世界显示「军功获取 +20%」）。

## 八、扩展新世界时的接入清单

1. 新建 `talents/{worldId}.js`，导出 `{ positive: [...], negative: [...] }`；
2. 每条声明 `world: '{worldId}'`，效果只用 §三 字典中的通用字段（新世界专属字段需先在设计文档登记）；
3. 专属池规模标准（v1.3 修订）：新世界**首发 ≥24 条**（正负各 12，最小完整集）；进入内容成熟期后**对齐修仙/古武标准 80 条**（正负各 40）；至少 2 条与该世界的 **专属系统** 互动（对标修仙的渡劫词条、古武的 gateMod/bannerBoost 词条）；
4. 在 `registry.js` 世界包中挂 `talentPool` 引用，创角屏 2 自动按 `worldId` 组池。
