## 一、项目定位

从「单一修仙挂机」重构为 **「多世界放置 RPG 引擎 + 首发玄幻修仙世界」**：

- **引擎层**提供可复用的通用系统（挂机、战斗、装备、技能、商店、事件、阶位/突破等）；
- **世界观**通过 **词表包（lexicon pack）+ 专属系统插件** 接入，一个世界 = 一个内容包，不是新代码分支；
- 首发世界为 **玄幻修仙**（由现有版本改造），其后逐步扩展其他世界。

## 二、世界观架构

```
鸿蒙大世界（未开发 · 未来轻联网 · 跨世界枢纽）
      │
      ▼
三千小世界（用户默认所处 · 单机放置）
   ├── 玄幻修仙      ← 首发（现版本改造）
   ├── 古武军势      ← 待开发
   ├── 魔法能量      ← 待开发
   ├── 科技降神      ← 待开发
   ├── 现代都市      ← 待开发
   └── 克苏鲁世界    ← 隐藏 · 未开发（registry 预留 id，UI 不露出）
```

- **鸿蒙大世界**：远期规划为轻度联网的跨世界枢纽（云存档 / PVP / 交易行入口）。架构上只保留 `meta` 命名空间占位，不实现。
- **世界包** = 一套词表 + 一份专属系统定义 + 一组初始参数。
- **扩展建议**：先把修仙世界做完整，等通用系统抽象稳定后再做第二个世界（推荐古武军势——与修仙差异大，能验证抽象是否够通用）。

## 四、创角流程（首次进入）

**三屏分步**（已确认，塑造仪式感）：

```
[屏 1] 起名           → 1 个文本输入
   ↓
[屏 2] 随机天赋       → 1~2 正 + 1~2 负，总数 ≤ 3；创角阶段无限免费重抽，确认即锁定
              底部附「问道初心」阵营倾向三段选择（v2.1，决策已定：入口在屏 2）
   ↓
[屏 3] 选择重生世界   → 每个世界显示随机生成的世界名 + 关键词标签
   ↓
[完成] 写入 profile，创建 worlds[worldId]，进入主界面
```

> **性别/种族预留（v2.5）**：本期创角**不开放**性别与种族选择（不做置灰占位），默认男性（`profile.gender='male'`）/ 人族（`profile.race='human'`），字段预留、normalize 补默认，未来版本开放；结缘双修不限性别，开放女性玩家后自动兼容（《财侣法地四柱框架》§5.3）。

### 4.1 天赋规则

合法组合（总数 ≤ 3 且正/负各 ≥ 1）：

| 组合 | 概率建议 | 说明 |
|---|---|---|
| 1 正 + 1 负 | ~40% | 极致单一，正面天赋效果更强 |
| 2 正 + 1 负 | ~35% | 主流 |
| 1 正 + 2 负 | ~25% | 高风险高回报 |

- 生成算法：`pos = rand(1,2)`，`neg = rand(1,2)`，若 `pos + neg > 3` 重抽；
- **重抽窗口只在创角阶段**：无限次免费重抽（RPG 刷初始的标准做法），点「确认」→ 写入 `profile.talents`，此后永久锁定；
- 天赋池分两层：
  - `talents/common.js`：跨世界通用（如「天资聪慧」+产出 / 「体弱多病」-战斗速度）；
  - `talents/xiuxian.js`：修仙专属（如「雷灵根」渡劫 +15% / 「凡骨」突破需求 +10%）；
- 天赋效果直接挂到通用系统的乘区上（如 `qiRate +20%`、`combatSpeed +10%`、`shopCost -15%`）；
- **具体词条清单、效果字段字典、抽取算法与平衡说明** 见子文档 [`三千世界-天赋池设计.md`](./三千世界-天赋池设计.md)（通用池正 28 + 负 22 = 50 条，修仙专属池正 40 + 负 40 = 80 条，合计 130 条）。

### 4.2 世界名生成

世界名 **固定到存档**（`profile.worldName`），只生成一次，作为这一世的身份标识。

| 世界 | 命名风格 | 样例 |

## 六、善恶系统（修仙世界专属 · 第一个世界系统）

### 6.1 核心概念

**善恶值 `karma`**：带符号整数，范围 `[-1000, +1000]`，初始 `0`。

```
karma >= +200        正道光环
-200 < karma < +200  左道（中立）
karma <= -200        魔道气息
```

（阈值 ±200 为初版试跑值，待调参）

### 6.2 善恶值来源

| 来源 | 正道加成 | 魔道加成 | 备注 |
|---|---|---|---|
| 修习功法 | 每个正道功法 Lv × `+2` | 每个魔道功法 Lv × `-2` | 覆盖式重算，不累加 |
| 法器 | 每件正道法器 × `+15` | 每件魔道法器 × `-15` | 同理（四槽法器体系（装备），G4） |
| 奇遇事件 | 每条奇遇三分支各带 karma 值（人级 \|k\|≤8 / 地级 ≤15 / 天级 ≤25），选定分支即计入 `karmaEventScore` | 同左 | v2.1 起**所有奇遇均为三分支抉择**（正/魔/左），事件分只增不清；词条见 [`三千世界-奇遇事件池设计.md`](./三千世界-奇遇事件池设计.md) |
| 阵营倾向漂移 | 创角所选倾向 × `+12/天` | 同左（负向） | v2.1 新增：`alignDrift` 分量，封顶 ±260——单靠倾向可缓慢入浅档（±200），深档仍须行为积累（见 §6.4） |
| 战斗击杀 | 秘境妖怪分正/邪属性 | — | 远期再扩 |

> **重要**：karma 不用 `+=` 增量，而是 **每次变更后按当前「装备 + 功法 + 历史事件分 + 倾向漂移」重新计算**，避免反复穿脱装备刷分。

### 6.3 三阵营状态效果（v2.1 重做：从「倍率差异」升级为「玩法风格差异」）

功法与装备均分 **正道 / 魔道 / 左道（中立）** 三阵营；角色按当前 karma 档位实时获得状态效果（跨档瞬间切换，无缓冲）：

| 维度 | 正道光环（karma ≥ +200） | 左道（-200 < karma < +200） | 魔道气息（karma ≤ -200） |
|---|---|---|---|
| 修炼速度（qiRate 乘区） | **×0.75** | ×1.0（基准） | **×1.5** |
| 战力（combatPower 乘区） | ×1.0 | ×1.0 | **×1.25** |
| 奇遇频率（奇遇时钟曲线乘数） | **×1.3（更易遇仙）** | ×1.0 | **×0.5** |
| 物品/功法获取（dropRate 乘区 + 事件收益权重） | **×1.25** | ×1.0 | **×0.5（但质更高，见下）** |
| 奇遇性质权重（机缘/危机） | **70 / 30** | 55 / 45（基准） | **35 / 65** |
| 奇遇等级权重（人/地/天） | 60 / 30 / 10（基准） | 同基准 | **35 / 40 / 25（高阶奇遇更易）** |
| 掉落品质 | 掉落阵营向正道位移（正装 38%） | 基准分布 | **掉成品阶 40% 概率 +1（「福缘凝华」，v2.7 概率化）+ 掉落阵营向魔道位移（魔装 45%，词条 ×1.10）**（dropAlignW/dropTierUpChance，数值详设 §8.1） |
| 判定 | **各类判定条件 -5%**：渡劫 p `+0.05`、属性判定 dc ×0.95 | 基准 | 基准（渡劫劣势走既有 karmaMod 分段） |
| 定位 | 稳而顺：慢修但处处逢源 | 中庸白板 | 快而险：倍率碾压但奇遇/掉落稀少，靠高阶奇遇与品阶上浮补质量 |

设计目标：三阵营是**三种玩法风格**而非数值优劣——正道「多奇遇多掉落慢修炼」、魔道「高倍率高品质低频率」、左道「全基准」；节奏基准已重验（数值详设 §6.4.1 v1.9 重模拟：典型画像验收带全过、决策宣称三口径复现，两观察项登记 §九.10）。

### 6.4 阵营倾向（v2.1 新增：创角第四决策）

- 创角时可选**阵营倾向** `profile.alignBias ∈ { right, neutral, evil }`（默认 neutral，入世后锁定不可改）；
- 游玩中 karma 缓慢向倾向漂移：`alignDrift += 倾向符号 × 12 × 离线/在线天数`，分量封顶 ±260，计入覆盖式重算；
- 漂移是「底色」，事件/装备/功法是「大笔」——倾向魔道但一路行善，仍可被拉回左道甚至正道（漂移不改符号上限，只持续施压）。

### 6.5 数据结构变更

```js
// 功法
{ id: 'tuna', name: '吐纳法', alignment: 'neutral', attr: 'qi', reqs: { realm: 0 }, special: 'inner_breath' }   // alignment: 'right'|'evil'|'neutral'；attr: 滋养属性；reqs: 学习要求（境界/属性/karma）；special: 固定特殊属性（每部一条）
// 装备
{ slot: 'weapon', name: '玄铁剑', alignment: 'right', resist: 80, attrValue: { attr: 'jing', value: 18 }, reqs: { realm: 2 }, special: 'ignore_req'|null, ... }   // attrValue 灵品起存在；reqs 生成时定格；special 上品起低概率随机（含「无视佩戴要求」）
```

## 七、渡劫系统（修仙世界专属 · 终版）

### 7.1 触发时机（界面批三改：默认手动）

- **默认手动触发**：`settings.autoTrib` 缺省 `false`——修为达阈值（`qi >= REALMS[realm+1].need` 且 `realm < 满级`）时不再自动掷判，修行页出现「修为圆满」卡 + 「渡劫」按钮，玩家主动点击（`SQ.Actions.tryTrib`，**须修为圆满方可掷**）方触发；
- **自动渡劫（可选）**：开关开启后回到原口径——`claim` 内修为达阈值即立即掷一次判定（**概率判定 + 挂机自动渡劫**，被动结算）。**开关位置：修行页底部「自动」区**（自动批 2026-10-02 自设置页迁入，与自动奇遇并列）；
- 引擎内部直调 / 仿真未显式传 `autoTrib` 时沿用自动口径，故既有数值仿真与断言不受影响。

### 7.2 成功率公式

渡劫抗性来自两个方向：① 个人战斗力 / 特殊法器（四槽装备）的独立渡劫抗性词条；② 善恶系统判定。

```
resistBonus = resist项 + 战力项（上限 0.35）
  resist项 = min( Σ装备resist / 1200, 0.20 )
  战力项   = min( (战力 / 当前境界基础战力 − 1) × 0.15, 0.15 )
karmaMod    = karma 分段映射（见下表）
p = clamp( base(realm) + resistBonus + talentBonus + karmaMod + guardianBonus, 0.05, 0.95 )
```

- `guardianBonus`（v2.4 登记，G14 护法位）：好感最高道友档 3 = +0.03 / 档 4 = +0.06；**魔道档位（karma ≤ −200）失效归零**（「魔道夜行，无人护法」）；正道 ALIGN_EFFECTS 的 tribBonusFlat +0.05 并入 karmaMod 段先加总后 clamp（数值详设 §8.1）。

base(realm) 见数值详设 §6.1 表（**势力批 v2.4 勘误**：自金丹起 ×0.75 已折算入表，真仙 0.338；旧『0.95→0.45 线性递减』口径作废）
```

> 复核修订（详见《数值复核报告》问题 4）：早期草案的 `战力/50` 项会随境界 ×3 增长、自化神起裸战力即封顶 0.35，导致 resist 词条失效。修订为「resist 固定区间项 + 配装富余度项」双封顶结构，保留「战力 + 法器抗性」双来源的既定决策。

| karma 区间 | karmaMod |
|---|---|
| `>= +800` | `+0.20` |
| `+200 ~ +799` | `+0.10` |
| `-199 ~ +199` | `0` |
| `-799 ~ -200` | `-0.12` |
| `<= -800` | `-0.25` |

> **边界口径（v2.8 勘误，代码批 1 实测发现）**：早期表把 `-200` 同时写进「`-200 ~ +200` → 0」与「`-200 ~ -800` → −0.12」两行、`-800` 同时写进「−0.12」与「≤ −800 → −0.25」两行，实现按行序命中导致 **karma = −200（恰好踏进魔道档位）拿到 karmaMod 0**——魔道「快而险」的渡劫代价在入档第一点整点缺失（与 §6.1 档位表 `karma ≤ −200 = 魔道` 不对齐）。现统一为**闭区间整数口径**并与档位表对齐：`−200` 起吃 −0.12、`−800` 起吃 −0.25、`+200` 起吃 +0.10、`+800` 起吃 +0.20；引擎侧 `TRIB_KARMA_MOD` 用 `±199.999 / ±799.999` 边界（与 `KARMA_TIERS` 同一写法，兼容非整数 karma）。验收 #46b 覆盖四个整点边界 + 「档位效果与渡劫代价同点生效」断言。

### 7.3 结果

| 结果 | 效果 | 日志示例 |
|---|---|---|
| 成功 | `realm + 1`，`qi = 0`，`artsLevels` 全清零（栏位保留） | 「渡劫成功，境界晋升为 X」 |
| 失败 | `qi *= (0.5 + tribFailLossMod + 神修正)`（基准半损，天赋与「神」属性各 ±0.10，总损失 clamp 30%~70%，见属性设计文档 §二），境界不变，`tribulation.lastResult = 'fail'` | 「天雷落下，渡劫失败，修为受损」 |

### 7.4 冷却

**无显式冷却字段**：失败后修为砍半，自然跌回阈值以下，重新攒气的时间就是天然冷却。

### 7.5 离线批量结算

```js
let iter = 0;
while (t < now && iter < 64) {
  // 结算挂机产出
  // 检查渡劫阈值 → 掷一次判定
  iter++;
}
```

`iter` 上限兜底，防止极端时间差导致死循环。

### 7.6 法器词条与品阶

`resist`（渡劫抗性）为 **独立第三词条**，品阶越高词条越满：

- 凡品：`atk`
- 良品：`atk + qiBonus`
- 上品及以上：`atk + qiBonus + resist`（灵品起再 + `attrValue` 第四词条）

**佩戴要求与特殊词条（v1.4 新增）**：上品起携带佩戴境界要求（上 2 / 灵 4 / 仙 6，极品词条再 +1 阶）；上品起低概率（3%/8%/15%）随机附带 1 条特殊词条（含「无视佩戴要求」），未达标装备入库藏阁等待境界提升。完整规则见数值详设 §3.5/§3.6。

**法器架构优化（v2.6 · 决策 16）**：独占法器 atk 获得时缩放定格 + 自动择优豁免（手动换装）；掉落阵营分布随 karma 档位联动（dropAlignW）；百器录图鉴（特殊词条/独占法器，炼化不除名）；装备 source 获得溯源。细则见数值详设 §3.2/§3.3/§3.4/§3.7。

**工程约定（已按 x-hub 扩展开发规范校准）**：

- **不引入构建工具、零 CDN**：所有 `*.js` 为 IIFE，挂 `window.SQ.*`，HTML 里按依赖顺序 `<script src>` 加载（静态 HTML + 本地相对路径是平台推荐形态）；**禁止引用任何外链资源**（Tailwind CDN / Font Awesome / Google Fonts 会被宿主 CSP/离线拦掉），图标用内联 SVG；
- **桥 API 由宿主注入**：直接调 `window.xhub.*`，不 import 任何 xhub 包；能力存在性以运行期 `runtime.info().capabilities` 为准；
- `manifest.json` 关键字段：`id: "com.avalonlee.sanqian-world"`（自有反向域名，非平台保留段）、`name: "三千世界"`、`version: "0.1.0"`（必须三段纯数字）、`runtime: "web"`、`kind: "view"`、`surfaces: ["module", "view", "window", "drawer"]`、`openIn: ["view", "window", "drawer"]`（window / drawer 与 view **共用同一份 `view/index.html`**，规范明令不复制页面）、`minSize 380×620`、`entry`（module/view 各指向真实 HTML 文件）、`description`、`permissions: []`；
- **权限零声明的依据**：本扩展只用 `storage.*` / `runtime.open` / `events.on` / `theme.*` / `config.*`——全部无需权限；不用 `data.*` / `fs` / `openExternal` / `events.emit`。⚠️ 平台发布预检对源码做**纯文本静态扫描**（注释里出现 `xhub.data.xxx` 调用示例也算「用到」），代码与注释中不得出现未声明权限的 API 字样；
- **存储契约**：`xhub.storage` 是**异步 Promise** 且按扩展隔离、跨形态（module/view）共享同一份——core 的 `load/save/claim/mutate` 全链路必须 async，入口用 **boot 模式**（先 `await` 读档再首绘，禁止顶层同步读）；`localStorage` 回退仅用于无宿主浏览器预览（`typeof window.xhub === 'undefined'` 时）；
- **主题铁律**：页面永远不铺不透明底——`body` 底用 `var(--xhub-page-bg, transparent)`，内容表面用 `var(--xhub-surface)` 玻璃令牌，所有颜色写成 `var(--xhub-*, fallback)` 并按「双声明 fallback」适配明暗（详见 UI 文档 §八）；
- 核心运行时接口：`window.SQ = { claim, mutate, load, save, normalize, defaultState, Worlds, generateWorldName, visibleWorlds }`（异步方法返回 Promise）；
- 世界包向 registry 注入三个函数：`initialState()` / `normalize(raw)` / `claim(ws, dt, now)`；
- **真机调试**：扩展中心 →「我的扩展」→ 添加源码目录（含 manifest.json）即加载，改代码约 1.5s 自动热重载；module 形态需到「工作台 → 自定义布局」拖入网格。
