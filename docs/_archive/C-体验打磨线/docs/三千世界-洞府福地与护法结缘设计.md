## 一、四柱定位（引擎视角）

「财侣法地」是修仙类放置游戏的经典成长四轴。引擎层映射：

| 柱 | 引擎承载 | 状态 |
|---|---|---|
| 财（资源） | 灵石经济 + G6 商店 + G4 炼化 + 事件收益 | 已有，补总账可视化（`ledger`） |
| 侣（护持） | **G14 护法结缘**：好感度名录 + 护法位 + 个体助力 | 🆕 本卷定义 |
| 法（方向） | G5 功法（54 部 + 独占通道） | 已有，形式化「主修」 |
| 地（效率） | **G13 洞天福地**：洞府驻留 + 独立乘区 | 🆕 本卷定义 |

设计公理：**财是底气，法是方向，地是效率，侣是护持**——四柱各管一个维度，互不越界：地不产灵石（财）、侣不提基础产出（地）、法不送好感（侣）。跨柱联动只走已登记的乘区与加项。

## 二、G13 洞天福地（地）

### 2.1 核心循环

```
灵石 / 境界 / 秘境首通 → 获得洞府入驻资格 → 择一驻留 → caveMult 独立乘区 + 签名效果
→ 产出效率提升 → 更快换境界 → 解锁更高阶福地
```

### 2.2 数据契约（世界包提供 `caves` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一 |
| `nameKey` | string | 词表 `cave.{id}.name` |
| `descKey` | string | 词表 `cave.{id}.desc`（灵气浓度叙事，30~60 字） |
| `mult` | number | caveMult，1.00~1.35（引擎硬顶 1.40，世界包不得超） |
| `reqs` | object | `{ realmMin?, stonesCost?, zoneCleared? }`——入驻资格三要素（可组合） |
| `signature` | object/null | `{ hook, field, value }`——签名效果，挂点限既有白名单（工程规范 §2.2）+ §2.5 新增两项 |

### 2.3 驻留规则

- **同时只能驻留一处**；入驻即生效，切换有 **游戏时间 1 年冷却**（360 游戏日 = 360 现实秒；走查批 v2.8 口径澄清：冷却统一为游戏 1 年，非现实一年）；
- caveMult 对**在线产出与离线结算同时生效**（「闭关」叙事 = 离线，洞府是闭关质量的第一变量）；
- 签名效果只在驻留期间生效，搬离即失——高阶福地各有侧重（冲离线 / 冲渡劫 / 冲产出），**择洞如择路**，是切换策略的核心张力；
- 资格校验发生在入驻时（境界 / 首通 / 灵石一次付清）；灵石扣除走 `mutate` 并记入 `ledger.out.cave`；
- 初始洞府免费（caveMult 1.00，无签名），保证「地」柱从创角起就可见、可成长。

### 2.4 数值纪律（硬约束）

1. **caveMult 是独立乘区**：产出公式末端 `× caveMult`，**不进 qiRate 加算池**——防止击穿功法六槽乘区审计上限（工程规范 #105）；
2. 签名效果走**既有乘区加算**（offlineEff / combatPower / artsSpeed / tribBonus 加项），来源登记「洞府签名」（数值详设 §8.2）；同一时刻只有一处签名生效（驻留唯一性天然防叠加）；
3. 全表 mult 预算：初阶 1.00 → 顶阶 ≤1.35，与阵营倍率（0.75~1.5）同数量级——「地」是第四条大轴，量级配得上，但不得反超阵营轴；
4. **验收带影响**：G13 上线（代码批 2）后必须重跑数值详设 §6.4.1——~~预判典型锚 13.3 → ≈11.5 天（顶阶洞府期），验收带按新锚重定基线~~ **批 2 实测结案（v1.3）**：满驻提速系数 **0.744**，锚 13.30 → **9.90 天**（预判 11.5 低估了「后三层占总时长 ~85% 且已满驻顶格」的权重）；**比值结构（阵营间）实测完全不变**（caveMult 是独立乘区、对九画像同比生效，漂移 <0.005）⇒ 验收带**不需重定基线**，仍以无洞府锚 13.3 为分母。膨胀线：典型画像满驻全部 ≥5 天（最低魔浅 7.12 ✅），速通魔道 4.39 天破线但按 §6.4.1 观察项② 属带外单列——**本表 mult 维持 1.35 不动**，实测证据与两级杠杆失效分析见数值详设 §九.11；
5. 灵石售价即「财换地」的跨柱水槽：总投入 ≈ 552 万灵石（修仙首批表），对照 zone8 刷图收入 ≈ 17 小时——是长线目标而非硬门槛。

### 2.5 挂点增量

世界包 `specialHooks` 白名单（工程规范 §2.2，现 15 项）**新增 2 项**：

| 挂点 | 职责 |
|---|---|
| `on_cave_enter` | 入驻洞府时触发（日志 / 一次性演出） |
| `on_cave_mult` | caveMult 结算读取点（引擎唯一读取处，防旁路） |

## 三、G14 护法结缘（侣）

### 3.1 核心循环

```
奇遇抉择（指定分支）→ bond 好感 → 好感度升档 → 护法位（渡劫 p 加项）+ 个体助力（既有乘区小加成）
→ 「修仙路上有人替你守夜」的叙事兑现
```

### 3.2 好感度模型

- 存档：`worlds.{id}.bonds = { npcId: affinity }`，affinity 整数 −20~100（势力批 v2.4 值域扩展；−20~−2 = 厌恶区间），**只增不减**纪律不变（绝交锁例外，见 §3.6）；
  - **（势力批 v2.4 勘误）**值域扩展为 **−20~100**：−20~−2 = 厌恶（势力敌对联动，负好感无档位无助力，可被后续事件拉回正区间）；**绝交锁哨兵 −1 → −99**（normalize 自动迁移旧档）；好感仍只增，唯二例外 = 势力加入联动（一次性）与绝交/心结锁；
- 档位（世界包可改名，阈值引擎固定）：

| 档 | affinity | 通用名 | 解锁 |
|---|---|---|---|
| 1 | 1~29 | 相识 | 个体助力 ×1 档 |
| 2 | 30~69 | 知交 | 个体助力 ×2 档；部分 NPC 特殊能力开闸 |
| 3 | 70~99 | 生死之交 | 个体助力 ×3 档；**可任护法位**（guardianBonus +0.03） |
| 4 | 100 | 道护 | 个体助力 ×4 档（满档）；护法位 guardianBonus +0.06 |

- 好感来源**只有事件 `bond` 收益**（指定条目 × 指定分支，见修仙分卷 §五映射表）——不走商店购买（「侣」不可交易是世界观底线）；
- 单条事件可重复触发时 bond 可重复入账（受事件自身冷却约束）；
- **companions 数据表契约**（世界包提供）：`{ id, nameKey, flavorKey, category: 'friend'|'spouse', perk: { hook, field, perTier, maxTier }, carrierEvents: [eventId] }`——`category:'spouse'` 为道侣候选（可结缘双修，§3.8），修仙首批 20 人 = 道友 16 + 道侣候选 4；**双书梗化扩容批（2026-10-01）+8 → 28 人**（新增 8 人正典见道友池卷 §四（原修仙分卷 §5.6），出身事件 = 专属池 №62~73）；**双书梗化二批（2026-10-01）+30 → 现行设计 58 人 = 道友 44 + 道侣候选 14**（新增 30 人正典见道友池卷 §五（原修仙分卷 §5.7），出身事件 = 专属池 №74~113；扩编仍开放、规模不锁定）。

### 3.3 护法位（渡劫联动）

- **护法位 = 玩家手选优先，缺省回落「当前好感最高的道友」**（**择选批 2026-10-02 修订**：原口径「自动、不可手选——谁与你最亲谁来护法」作废；道友页顶部护法位行点开「择护法」浮层，仅列已结缘（好感 ≥1）、无绝交、无心结者，点选写入 `ws.guardianPick` 随档持久化；被选者资格失效（绝交锁 / 心结锁 / 未结缘）时运行时自动回落好感最高者，脏档 normalize 回落 null = 自动）；
- 档位 ≥3 → 渡劫 p 公式新增加项 `guardianBonus`：档 3 = +0.03，档 4 = +0.06（与 resistBonus / talentBonus / karmaMod 并列，先加总后 clamp [0.05, 0.95]）；
- **魔道档位（karma ≤ −200）护法位失效**（guardianBonus = 0）：「魔道夜行，无人替你守夜」——与 ALIGN_EFFECTS 的「快而险」定位咬合，个体助力保留（市井之交不问正邪）；
- 护法生效时渡劫演出加一行叙事（「{道号} 立于雷幕之外，为你护法」）+ 渡劫日志追加标记。

### 3.4 个体助力（既有乘区小额加成）

- 每位 NPC 绑定**一种**助力类型，数值 = 每档增量 × 当前档（1~4），满档合计控制在「半条特殊词条」量级（≤8% 或 ≤6pp）；
- 全部走既有挂点白名单（`on_debuff_apply` / `on_check` / `on_shop_price` / `on_kill_drop` …）**或既有乘区被动通道**（combatPower / combatSpeed / artsSpeed / gearLuck 等加算来源，同法器特殊词条口径，不新开钩子），来源登记「道友助力」（数值详设 §8.2）；
- **合计封顶**（防多 NPC 同类型叠穿）：debuff 时长减免合计 ≤ −50%；判定成功率加点合计 ≤ +15pp（含功法「摄魂」）；shopCost / stonesRate / dropRate / artsSpeed 各来源合计仍受工程规范 #105 乘区审计约束（口径按通用规范 v2.3 澄清：#105 = 功法层自身极限，道友助力为独立登记来源，各自预算由冒烟 #129 对表）。
- **实施口径（v1.4 · 批 3 定稿）**：
  1. **心魔类 debuff 定义** = 负面性质奇遇（`nature:'bad'`）施加的减益——幻境/心魔叙事全部出自负面池；failE 追加的减益随宿主事件性质计入。老黄「忠护」与阴阳双修「−25%」只作用于心魔类；陈郎中「药箱」全域；
  2. **合计封顶算法**：先按既有「心如止水 × 枯井不波」叠乘（专属池 v2.0.1 §4.1 不变）得基础减免，再叠加药箱/忠护/阴阳双修各减免，**总减免 clamp ≤ 50%**——保证零道友时行为与批 1/2 完全一致；
  3. **冥佑（楚老拐）层时长 = 14 天**（2× 授予周期）：7 天一授 + 14 天存续 ⇒ 稳态可达上限 2 层；层被负面奇遇触发消耗即提前失去。计日锚点 `chuBlessAt` 在首次档 ≥2 时初始化为当时时间（不追溯历史）。

### 3.5 `companion` 判定（事件 DSL 第九类）

事件池设计 §2.2 判定 DSL 扩至九类，新增：

| type | 判定内容 | 通过 | 失败语义 |
|---|---|---|---|
| `companion` | 护法位档位 ≥ `{ minTier }`（G14） | 全额收益 | 收益折半（「交情尚浅，无人搭手」） |

- 与 attr/karma 等既有八类同规则：只在玩家选定分支时在线掷；魔道档位下护法位失效 → companion 判定**必然失败**（分支按钮对魔道玩家显示「无人可援」置灰提示，不隐藏——让玩家看见自己丢了什么）；
- bond 类事件改造随代码批 3 回写两个内容分卷（映射表为唯一事实源）。

### 3.6 绝交锁（分支后果的长尾）

- 指定事件的**魔道分支**可设 `bondLock: {npcId}`（如卖狗、抢劫苦主）：该 NPC 好感**永久锁定为 0**，不可再结缘——「有些事做了，就再没有回头路」；
- 绝交锁写入 `bonds[npcId] = -99`（哨兵值，势力批 v2.4 由 −1 迁移——好感值域扩为 −20~100 后 −20~−2 为厌恶区间，−1 不再可用作哨兵；负值 = 锁死语义不变，旧档 normalize 自动迁移），图鉴/浮层显示「缘尽」；
- 绝交锁条目必须在事件文案里有清晰预告（叙事流里该分支 label 带「绝缘」暗纹角标），不做暗坑。

### 3.8 结缘双修（道侣候选专属 · v1.1）

- **对象**：`category:'spouse'` 的道侣候选；**条件**：好感满档（affinity = 100）+ 玩家主动「提亲」+ CONFIRM 模态明示三形态与代价；
- **形态由结缘瞬间 karma 档位决定**，存档 `worlds.{id}.spouse = { npcId, form, since }`（null = 未结缘；**同时仅一位**）：

| form | 名称 | 结缘/维持条件 | 效果（独立来源「道友双修」，§8.2 登记） | 代价 |
|---|---|---|---|---|
| `yinyang` | 阴阳双修（正道） | karma ≥ +200；跌破即解除，7 天后可重新提亲 | qiRate +6%、offlineEff +10%、心魔类 debuff −25% | 无 |
| `huzhu` | 互助双修（左道） | −200 < karma < +200 | qiRate +10% | 无 |
| `luding` | 炉鼎采补（魔道） | karma ≤ −200 | qiRate +18% | ①结缘一次性 karmaEventScore −20 入账；②双修期间该道友个体助力归零；③karma 回升 > −200 即解除，且该道友好感锁死当前值、**永不再任护法位** |

- **与护法位的关系**：双修道侣若恰为好感最高者，照常占护法位（guardianBonus 与双修效果并行，不冲突）；炉鼎采补解除后的心结锁只封护法位，好感数值本身不变（只增不减纪律的唯一例外仍是绝交锁 −99）；
- **性别与种族**：双修不限性别（道侣结的是心）——`profile.gender`（默认 'male'）与 `profile.race`（默认 'human'）为**预留字段**，本期创角不提供选择（工程规范 §3.1 v2.2 登记），未来开放后本机制自动兼容；
- **内容红线（引擎级纪律）**：双修文案一律写意留白，无任何亲密描写；炉鼎形态的黑暗感只靠代价机制表达；新世界转译示例：古武 = 侠侣双修 / 政治联姻 / 采补邪功，魔法 = 灵魂契约 / 塔灵共鸣，均走词表。
- **实施口径（v1.4 · 批 3 定稿）**：
  1. **互助双修不自动解除**——表中「−200 < karma < +200」是结缘瞬间的形态判定口径；「无维持条件最稳/最自由」（四柱卷 §5.3）即此后 karma 任意漂移均不触发解除。阴阳（跌破 +200）与炉鼎（回升 −200）才有自动解除；
  2. **心结锁三义**（炉鼎解除后 `scars[npcId]`）：① 永不再任护法位；② 好感锁死当前值（后续 bond 收益拒入账，与绝交锁 −99 的区别是数值保留、身份保留）；③ **不可再提亲**——「缘锁」封的是这段缘，防 karma 摆荡刷炉鼎 +18% 的退化玩法；其余候选不受影响；
  3. **提亲冷却**：阴阳双修自动解除 → `spouseCdUntil = 解除时刻 + 7 天`（全局，冷却内任何候选不可提亲）；炉鼎解除走心结锁不设冷却；
  4. **解除叙事消费通道**：解除发生在 karma 重算点（事件结算 / claim 漂移），视图不在场——引擎写 `spouseLog = {npcId, form, reason:'karma'|'redemption', at}`，视图会话内按 `at` 键控消费一次（与出关呈报同模式），炉鼎解除附加「缘锁」提示行。
