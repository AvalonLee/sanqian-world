## 一、分区地图与准入规则

新文件**先归位、再登记**（登记动作见 §四）。一个目录只许一类东西：

| 分区 | 准入 | 禁入 |
|---|---|---|
| `docs/` 根 | **账本与叙述面**：`README.md`（文档索引）/ `VERSIONS.md` / `FACTS.md` / `ledger.json`（机器）/ `交接快照.md`。**只减不增**——新叙述面立卷须用户点头 | 正典卷、过程档、数据、任何新 README |
| `docs/总纲/` | **正典骨架卷**：主设计 / 工程规范 / 任务清单 / 本卷——全项目级纪律与批次账 | 世界专属内容、一次性方案 |
| `docs/系统设计/` | **跨世界通用系统卷**：引擎 / 数值 / 属性 / 事件池 DSL / 词族契约 / 轮回 / 成就等 | 某个世界的专属数值 |
| `docs/UI/` | UI 卷与移植方案 | —— |
| `docs/玄幻修仙/` `docs/武侠世界/` | **世界专属正典**（设定 / 数据口径 / 事件卷）；修仙区另有《世界设定》§七**内容级二级索引**（分工：本卷与总索引管归置/版本/更新义务，§七只做内容摘要、允许滞后——册268 立） | 跨世界通用件（进系统设计） |
| `docs/设计稿*/` | 视觉稿 / 交互说明 / 原型（**不是产品代码**，不进门禁） | 正典叙述 |
| `docs/过程档/` | **过程记录**：勘察 / 报告 / 草案 / 交接（三态与退出见 §三、§六） | 正典内容（转正后本体留正典区） |
| `docs/_archive/` | 被取代的冻结卷与整树快照（**只读**，追加不改写；新归档动作见 §六） | 现行件的修改 |

**命名纪律**：卷名 → 文件名 basename 全仓唯一（`versions-check` 按 basename 配对，跨目录同名即撞——册152 实测）；新增/改名卷**不带计数后缀**（「功法全录（51部）」式历史名不作口径）；过程档件名带日期后缀（`<主题>-YYYY-MM-DD.md`）以便自然排序。

## 二、入口件职责表（全仓 README / AGENTS / CLAUDE）

**规则：全仓级「门面 README」只许仓库根一份；目录说明件每目录至多一份、首行必须写明「本件只管本目录」；docs/ 下永不新增 README。**

| 件 | 职责 | 读者 | 维护义务 |
|---|---|---|---|
| `README.md`（仓库根） | **项目门面**：一句话定位 / 双世界总览 / 快速开始。不承载开发纪律 | 新人、GitHub 访客 | 形态级变化时更新（新界上线 / 主形态更换） |
| `docs/README.md` | **文档索引**（全卷唯一索引 + 分区归置纪律头注）。⚠️ 它不是「项目介绍」——找门面去根 README | 全体 | **每新建 / 移动 / 归档一卷，同批对索引行**（§五）；头注纪律段改动须随批 |
| `AGENTS.md`（仓库根） | **agent 正典指引**：硬规矩 / 路径口径 / 门禁 / 接手顺序 | 接手 agent | 硬规矩变化时同批更新（第 0 件指针指向交接快照） |
| `CLAUDE.md`（仓库根） | **指针件**，只指 AGENTS.md，零独立内容 | Claude 系工具 | AGENTS.md 改名 / 挪位时才动 |
| `.tests/README.md`（扩展内） | **测试判据入口**：每件判据的末行标记、篇目行判数 | 跑验收的人 | **每碰一篇判据随批对齐该篇现值**（历史批加判未跟表已三例，册149 实证） |
| `docs/_archive/README.md` | 归档区说明（只读纪律 + 归档件索引） | 考古者 | 每次有新归档动作，同批登记一行 |
| `docs/设计稿-v2/README.md` | 设计稿目录声明（不是产品代码 / 不进门禁 / 占位清单） | 看稿的人 | 设计稿批次随批 |
| `docs/_archive/C-体验打磨线/docs/README.md` | **历史快照**（2026-10-05 时代的旧索引逐字节副本，随整树归档带入）——按归档纪律只读，**不修不删，不作任何现行依据** | 考古者 | 永不改 |

**防混指针**（v1.0 已挂）：根 README 与 `docs/README.md` 头部互挂一行分工说明；检索到多个同名 README 时按本表对号。

## 三、文档三态与维护义务

每个 docs 件必属其一（卷头写明），义务不同：

| 态 | 判定 | 更新义务 | 允许滞后？ |
|---|---|---|---|
| **账本态** | 机器生成或计数唯一登记处：`VERSIONS.md` / `FACTS.md` / `ledger.json` / `交接快照.md` / 各卷卷头版本行 | 严格随批（§五矩阵），哨兵段只许 `gen-ledger` 刷 | **不允许**（有门禁锚或同批纪律守着） |
| **正典态** | 有「唯一事实源」标注、卷头版本表格行的内容卷（总纲四卷 / 系统设计 / UI / 世界专属） | **内容被代码批改动时同批更新该卷对应节**；纯叙述不追批 | 叙述允许滞后，**数值与字段契约不允许**（代码冻结纪律：先文档后代码） |
| **过程态** | 卷头带「⚠️ 不立口径、不作账本」声明：勘察 / 报告 / 草案 / 交接 | **零随批义务**——写完即定格；只允许补「后续批处置结果」的销项注 | 允许，且预期滞后（这就是它存在的意义） |

**过程态的纪律**：① 卷头声明不全的（没写「不立口径」）不算过程档，按正典态要求追批；② 草案转正典后，草案本体**留在过程档、卷头加「已转正典」注**（正典卷头回挂指针）——不删（历史注），但检索者一眼知道权威在哪；③ 一次性方案（执行完毕）退出见 §六。

## 四、新建文档动作清单（五步，缺一即 `versions-check` 或索引漂）

1. **归位**：按 §一 选分区（拿不准 → 问「它是唯一的吗」——唯一事实源进正典区，复述件不建）。
2. **卷头**：`# 标题` + 版本**表格行** `| 版本 | vN.M（**册N · 标题 日期**：一句话）|` + 定位行 + 唯一事实源标注（若本卷只做指针，逐节注明权威卷）。
3. **登记 `VERSIONS.md`**：对应分区表加一行（同一提交内，卷头与总账同行）。
4. **登记 `docs/README.md` 索引**：对应分区表加一行——**定位描述 ≤2 行指针式**，不写批次史（索引行写长文 = 本轮「乱」的主因之一）。
5. **登记主设计**：立卷批在 §七A 条目里记「🆕 新卷」+ 卷职责一句话。

## 五、随批更新矩阵

| 触发 | 必更（同批） | 说明 |
|---|---|---|
| 每批收口（无条件） | 主设计 §七A 加条 → `manifest.json` +0.0.1 → 交接快照（anchor + 进行时 + 脉络 ≤8 行削插）→ `gen-ledger --fix` | 顺序照 AGENTS.md；快照只更叙述不抄数 |
| 本批动了某卷内容 | 该卷卷头版本行 +1 链式注 → `VERSIONS.md` 对应行 → `docs/README.md` 该卷索引行**看一眼**（描述漂了就改一句） | 索引行描述不追批次史，只追「这卷现在管什么」 |
| 本批新增 / 删除数据表、判据、词表 | `FACTS.md`（哨兵自动 + 人写表随批）+ `.tests/README.md` 篇目行 | 已三例陈旧，见 §二 |
| 本批 `git mv` 任何卷 / 目录 | **全仓 grep 旧路径**，现行卷内引用跟链；`_archive` 内不跟；`VERSIONS.md` 摘行 → `_archive/README.md` 加行 → 索引行移除 | 册261 实测 6 处漏跟后立此条 |
| 代码改了某卷描述的机制 | 该卷对应节先改（**先文档后代码**冻结纪律） | 数值 / 字段契约级 |

## 六、归档与退出

**卷归档五步**（被取代 / 已废弃的现行卷）：
1. `git mv` 进 `docs/_archive/<主题>-<日期>/`（或平铺）；
2. 全仓 grep 旧路径，**现行卷内引用跟链**（改 URL 不改正文叙述；历史注不动）；
3. `VERSIONS.md` **摘掉现行版本行**（checker 不扫 `_archive`，留行会 `ONLY-LEDGER` 或同名误配——册152 实测），冻结值写进 `_archive/README.md` 备案行；
4. `docs/README.md` 索引行删除或改为归档指针；
5. 主设计 §七A 条目记归档动作。

**过程档退出三途**（§三 ②③ 的展开）：
- **已转正典**（草案 / 勘察被采纳落地）→ 本体留过程档，卷头加「✅ 已转正典 → 指针」注；正典卷头回挂指针。
- **已执行完毕**（一次性方案 / 已消号的待办表）→ `git mv` 进 `_archive/`，走卷归档五步。
- **仍活着**（在途任务的交接 / 排期）→ 留原位，交接快照「进行时」必须挂着它的指针（**快照没提的过程档 = 视为死件**，下遍体检按上一途处置）。

## 七、检索纪律

1. **任何全库检索先排除 `docs/_archive/**`**——那里有 14+ 份与现行正典同名且内容落后的卷（归档卷无水印是有意为之，只读纪律），同名命中必是旧口径。唯一权威提示位 = 本条 + `docs/README.md` §九。
2. 找「现在该读哪卷」：根 README（门面）→ `docs/交接快照.md`（现状）→ `docs/README.md`（全卷索引）→ 各卷。
3. 同名卷按 §二职责表对号；`docs/README.md` ≠ 根 `README.md`。

## 八、门禁分工与已知盲区

| 关 | 管什么 | 不管什么（盲区） |
|---|---|---|
| `versions-check` | 卷头版本行 ⇔ `VERSIONS.md` 总账逐行对表；卷名 basename 查重 | 相对链接死活（→ 已由 `probe-doclinks` 补门）、索引行描述漂移、过程档时效 |
| `gen-ledger` + `HANDOFF_STALE` | 六处哨兵段同源刷新；快照 anchor ⇔ 主设计 §七A 最新条号 | 索引行存在性（新卷无索引行不红 → 靠 §四步骤 4 自觉） |
| `probe-doclinks`（册262 新立） | docs 全部 `.md` 相对链接逐条解析存在性；死链即红 | 外链可达性、锚点（`#`）存在性、归档区**豁免**（只读不修） |

盲区处置原则：**先立判据再立规矩**——本表每条「不管什么」要么挂了探针，要么在任务清单有登记项；两边都没有的盲区发现即补。
