## 一、设计定位

奇遇引擎是「江湖找上门」——被动等时钟掷判；传闻系统是「你听说江湖有事」——**主动选择介入**。两者互补：

- 给玩家一个**可见的近期目标清单**（卡片 + 倒计时），把「下一条奇遇是什么」的黑盒变成「这三条里我先追哪条」的白盒选择；
- **限时性制造取舍**：不点就过期，错过感是特性不是缺陷（离线照常消散，回归时一条日志交代「闭关期间，江湖事过境迁」）；
- **定向触发通道**：传闻指向的事件绕过随机两级抽取直取 id，但 `condOk / once / 冷却 / pendingChoice` 语义与随机通道完全对齐——图鉴照记、冷却照写、独占授予照走判定链，两个通道对同一事件池是**公平消费**。

## 二、数据结构与存档

```
worlds.{id}.rumors   = [ {rid, evId, tier, nature, bornAt, expireAt, tpl, place} | {rid, kind:'war', bornAt, expireAt} ]
worlds.{id}.rumorClock = 0        // 在线累计秒，跨分钟段驱动刷新（与 eventClock 同范式，独立计）
```

- `rid`：传闻实例 id（自增计数 + 时间戳混合，不重复即可）；
- `evId`：指向事件池词条 id（触发时用 `SQ.Events.findById` 定位）；
- `tpl` / `place`：文案模板 key 与地点词（生成时掷定入档，保证卡片文案稳定不闪变）；
- 上限 `RUMOR_MAX = 4` 条活跃；normalize：结构逐项校验、未知 evId / 已过期 / 超限截断丢弃；
- **不新增事件字段**：事件词条零改动，传闻侧全部是外挂状态。

## 三、刷新（在线时钟 · 与奇遇时钟并行独立）

- claim 编排内、`Events.tickOnline` 之后挂 `Rumors.tick`——**仅在线推进**（`!idleRes.offline && dtMs > 0`），离线 rumorClock 冻结（与 eventClock 同纪律）；
- `rumorClock` 每跨 `RUMOR_REFRESH_MIN = 10` 现实分钟边界掷一批：生成 `RUMOR_BATCH = [1, 2]` 条，活跃数达上限则本批跳过（不积压不补发）；
- 单条 TTL 按品阶：人阶 40 分钟 / 地阶 70 分钟 / 天阶 110 分钟（`RUMOR_TTL = {ren: 40, di: 70, tian: 110}` 现实分钟）——越高阶越耐用，天阶传闻值得留一轮再决定；
- `pendingChoice` 挂起期间**照常刷新与过期**（传闻是货架不是弹窗，不因抉择模态冻结；但触发入口在模态期间天然不可点）。

## 四、传闻池抽取（复用事件引擎积木）

生成一条事件传闻 = ①`natureDraw`（阵营 natureW + eventLuck，与随机通道同源）→ ②按阵营 `tierW` 加权掷品阶 → ③`SQ.Events.buildPool(pack, ws, D, tier, nature, now)` 组池（condOk / once-seen / 冷却中 / lastId 全过滤）→ ④**再滤活跃传闻已指向的 evId**（同一事件不同时挂两张卡）→ ⑤`weight` 加权抽取；空池沿 天→地→人 降级、再翻性质（与 fire 回退序一致）；仍空 → 本条流产（批次内其他条不受影响）。

- 文案：`tpl` 从 common 词表 `rumor.tpl.{tier}.1~10` 十句模板掷一，`place` 从地点池掷一（`rumor.place.1~8`：坊市 / 黑风寨方向 / 深山 / 官道 / 邻县 / 江面 / 古战场 / 无名荒谷——世界分卷可覆写为秘境名系）；模板含 `{place}` 占位，**不剧透事件名**（天阶模板允许暗示品阶气象：「钦天监夜观星象…」）；
- 传闻卡揭示信息 = 品阶角标（人/地/天）+ 性质暗示（机缘/危机色调，沿用 `event.nature.*` 词）+ 模糊文本 + 倒计时；**事件真名与 story 只在触发后的抉择模态揭示**（保留惊奇感）。

## 五、触发与过期

### 5.1 触发（前往查证）

`SQ.Actions.triggerRumor(ref, rid)`（mutate 通道内）：

1. 校验链：传闻在档且未过期 → `ws.pendingChoice` 为空（不为空返回 `busy`，UI toast「先了结眼前事」）→ `findById` 命中 → `condOk` 复核（刷新到触发之间玩家状态可能已变，如修为跌档）→ 非 once 已见 → 事件不在冷却；任一不过返回对应 reason，卡片置灰注明「时过境迁」；
2. 落地五件套（照抄 fire 语义）：`eventCooldowns[evId] = now`、`eventHistory.lastId = evId`、`seen[evId]` 首遇记、`pendingChoice = {id, at, tier, nature, via: 'rumor'}`——**不清 eventClock**（独立通道，随机奇遇节奏不受影响）、不消耗 eventShield（主动查证不是被动遇袭）；
3. 该传闻卡出档（consumed）；写日志「循着传闻寻至…」（`rumor.log.trigger`）；
4. 弹层栈自动接管：pendingChoice 一写入，现有抉择模态 / 判定演出 / resolveBranch / feed / 图鉴全链路与随机奇遇**零差异**；`via:'rumor'` 只供 feed 卡加一枚「闻」角标（叙事流溯源）。

### 5.2 过期

- 绝对时间戳判定（`expireAt ≤ now` 即废），claim 内每 tick 清扫（在线离线都扫——**离线只过期不刷新**）；
- 过期瞬间：在线静默移除（卡片倒计时归零自然消失，不弹 toast 不制造焦虑）；离线期间过期的在回归时聚合一条日志「闭关 {n} 日，{k} 桩江湖旧事已随风而去」（`rumor.log.expired`）；
- 过期事件的 once/冷却/seen 均**未消耗**（没触发就没消费），后续可再次以传闻或随机奇遇形式出现——过期损失的是「这次机会」，不是「这个事件」。

## 六、势力冲突情报（kind:'war' · G16 联动）

- 势力开战（《势力全录》§五）时向传闻栏推一条 `{kind:'war'}` 卡，TTL = 冲突剩余时长，文案 `rumor.war.tpl`（「{甲}与{乙}刀兵相见，战线就在你脚下这一带…」）；
- **按钮只读分流（走查修复批 2026-10-02）**：卡内「应战」按钮**仅交战方（已效力任一交战势力）可见可点**——点击跳势力页（弹应战 CONFIRM）；非交战方（未效力 / 第三方）**只渲染「观望」提示文字，无按钮**（旧口径按钮常驻但点击无动作，作废）；冲突结束卡即废；
- 冲突卡**不占** `RUMOR_MAX` 事件传闻名额（独立至多一条，随 factionWar 生灭）。

## 七、UI 契约

- **位置**：奇遇页顶部新增「江湖传闻」节（叙事流之前）——传闻与奇遇同属「江湖事」，同页承载形成「传闻在上、亲历在下」的阅读序；不新开 Tab（导航已满）；
- **卡片**：品阶角标（沿用 `event.tier.*`）· 性质色调边（机缘青 / 危机赭）· 模糊文本 · 沙漏倒计时（mm:ss，最后 5 分钟转红闪烁）·「前往查证」按钮（busy/时过境迁态置灰注明）；空态一句「江湖最近风平浪静」（`rumor.empty`）；
- **红点**：`ui.newRumorDot`——**走查修复批 2026-10-02 口径修订**：只对「出生晚于已读基线 `ui.rumorSeenAt`」的传闻亮（旧口径「场上存在未过期传闻即亮」会让战况卡 TTL 内把红点钉死不灭，作废）；进线时存档既有传闻基线化（不扰旧闻），进奇遇页刷新基线即消，传闻过期不复燃；新传闻到达**不弹 toast**（同屏 ≤2 纪律，卡片自身倒计时已足够醒目）；
- 倒计时每秒随 claim tick 重渲染（复用现有 1s interval，无新计时器）。

## 八、数值与纪律红线

| 红线 | 口径 |
|---|---|
| 经济零新增 | 传闻只改变事件的**触达方式**，不改任何事件收益——事件经济全部沿用双锚缩放与 §十三 勘误，传闻通道不产生第二套奖励 |
| 密度护栏 | 期望刷新 ≈ 6 条/小时（10 分钟批 1~2 条）× TTL 内可及 ≈ 场上常态 2~4 条；上限 4 硬顶——传闻是「选择的货架」不是「任务的堆栈」 |
| 通道公平 | once / 冷却 / seen / 图鉴 / 独占判定链与随机通道同一套语义；同事件两通道互斥（活跃卡指向的事件不会再被随机 fire 抽中——**传闻预留批 2026-10-05 口径修订**：`Events.fire` 组池后按 `Rumors.activeEventIds(ws)` 排除活跃卡指向的 evId，由旧口径「buildPool 不感知传闻 · lastId 与冷却仅覆盖绝大多数重叠 · 剩余重叠属可接受并发：先触发者得」改为「**传闻优先保留**」——活跃传闻指向的事件在 TTL 内不被随机 fire 抢先触发；排除后沿既有 降阶/翻性质 回退，仍空则流产且时钟保留；定向查证走 `Rumors.trigger` 不经 `fire`，不受影响） |
| 离线纪律 | 离线零刷新零触发（与奇遇正典对齐）；过期照绝对时间——「错过感」只在离线侧发生，在线侧玩家永远看得见倒计时 |
| CJK 纪律 | 引擎 `rumors.js` 零裸中文；模板与地点池全走 common 词表（世界分卷可覆写）；审计 A1/A2 同口径 |
