---

天道系统是《三千世界》的**伪智能叙事层**：一位「记得你、嘲你、偶尔帮你、可以被你驳、驳多了会认真劈你」的毒舌老天道。它不新增任何乘区、不动 p 公式、不进 tick 模拟——它把游戏已经在发生的事（渡劫、破境、抗旨、入魔）组织成一段**有记忆、有态度的对话关系**，机制侧全部经由既有通道兑现小额、一次性、带 clamp 的干预。设计上它同时是三件事：**叙事装置**（编年史驱动的私人化嘲讽）、**旁路 build**（抗旨积逆天值 → 逆天大劫的高风险高回报线）、**协议试验田**（V1 人工中继零网络零密钥即可上线，V2 换传输层契约一字不改）。

## 一、定位与三形态

### 1.1 系统定位

- 天道 = 游戏的伪智能叙事层：玩家通过「问天」仪式与天道对话，天道以「圣旨」回应——判词毒舌、旨意有实底、可以被驳回，驳回有代价；
- 天道的全部机制干预**白名单化、clamp 化、幂等化**（§四），叙事层的自由度不泄漏进数值层；
- 与既有系统的关系是「消费既有通道，不新开轴」：渡劫修正 = 数值详设 §8.3 talent 加项同读点；临时增减益 = 既有 buff 构型；奇遇注入 = 天道垂青池触发面；传闻播报 = G17 江湖传闻。

### 1.2 三形态（共享契约，只换传输层）

| 形态 | 传输层 | 状态 | 说明 |
|---|---|---|---|
| **V1 人工中继** | 玩家手动复制粘贴 | **首版实施** | 游戏生成奏疏文本 → 玩家复制到任意免费 AI webchat → 复制回复 → 游戏「接旨」解析生效。**零网络请求、零密钥**，预览 / 发布 / 离线全形态可用 |
| **V1.5 本地模拟天道** | 引擎本地生成 | **纳入 V1 同批实施** | 同一旨意词表由引擎加权随机生成 + 本地毒舌判词模板池；UI 明示「天机较钝」。保证无 AI 条件的玩家**功能完整**（问天 / 领抗旨 / 逆天值 / 天象全链路可用） |
| **V2 平台 LLM 中转** | 平台 LLM 代理路由（poll-first） | **⏸ 预留登记，不实施** | 只换传输层为平台 LLM 代理路由，圣旨契约（§四）一字不改；接口形态见 §11.3 |

- 三形态共享同一套**奏疏/圣旨契约**（§三/§四）与**旨意词表**（§11.1）：形态切换 = 传输层单函数替换，解析器、校验器、幂等账本、逆天值记账全部同源复用；
- V1.5 的输出**走与 V1 完全相同的校验器**（白名单 / clamp / seenIds 一概生效，验收 #195）——本地模拟不是旁路，是同一契约的另一个生产者。

### 1.3 世界适用范围（2026-10-02 归属归置批修订）

- 本卷为**玄幻修仙世界系统落地卷**（人格面具 = 毒舌老天道，旨意词表用修仙语汇；15 型旨意中 9 型机制干预挂修仙专属系统——渡劫 / 业力 / 道侣 / 奇遇池 / 秘境词缀）；
- **古武军势预留（重判口径）**：奏疏字段、圣旨 JSON 契约、三层容错解析器、逆天值记账为**世界无关的协议层**；但旨意词表与人格判词为修仙内容，古武启用需整套重设计词表与人格（如「老军师 / 苍天真宰」）而非仅换 `tiandao.*` 词表分卷——届时按《角色属性设计》先例**抽协议层回根目录为通用卷，本卷留世界目录为修仙实现卷**；是否/何时启用由古武世界批次自行评估，本卷不排期。

## 二、人格设定：毒舌老天道

### 2.1 设定

- 一位看了一万年凡人挣扎的老存在：嘲讽是日常语态，但**嘲讽永远针对玩家的具体行为**（引用编年史，§3.2），随玩家操作越来越私人化——渡劫连败三次和破境高光，天道的嘴脸完全不同；
- 语体基调：仙师长者的刻薄 + 账房先生的记仇；「不是心疼你，是看累了」式傲娇兜底。

### 2.2 范本判词（5 条 · 进提示词模板当 few-shot 范本）

> **纪律**：以下 5 条为提示词模板内的 few-shot 范本文本；实施时文本进词表 / 模板池（`tiandao.*` key，§11.1），**数据文件禁文案**纪律不变。

| № | 场景 | 范本判词 |
|---|---|---|
| 1 | 渡劫三连败 | 「三次。凡间山头上那头老牛，爬山也只会摔两次。罢了，老夫给你记着账呢，第四次雷会轻半成——不是心疼你，是看累了。」 |
| 2 | 破境 | 「哼，破了。别得意，你这根基在老夫眼里跟纸糊的一样，风往哪吹你往哪倒。」 |
| 3 | 香火少 | 「三块灵石的香火？三块！老夫的一缕雷都买不起。旨意拿去，爱领不领。」 |
| 4 | 抗旨 | 「哟——敢驳老夫的旨？好，好得很。你的名字，老夫刻画深了一笔。」 |
| 5 | 魔道 | 「你走魔道，老夫管不着。但别以为你心里那点算盘老夫看不见。走吧，雷劈你的时候，一道都不会少。」 |

### 2.3 内容安全兜底

- 提示词硬约束：「嘲讽 = 仙师长者调侃」，不涉真实人身攻击 / 敏感话题；
- 本地再过**敏感词过滤**：越线输出降级为通用谶语（type='谶语'，零效果，§4.3 兜底档同通道）；
- 判词长度设软上限（实施批定值），超长截断进谶语档，防粘贴回复夹带超长杂讯撑爆 UI。

### 2.4 红线：毒舌只在文本层

- 毒舌人格**只影响文本层**（判词 verdict / 谶语 omen / 天象短评）；
- **机制层一概不受文本影响**：白名单旨意、payload clamp、seenIds 幂等、逆天值记账全部按 §四/§六 数值正典执行——判词骂得再凶，`tribBonus` 也只能在 ±0.03 内走账。

## 三、奏疏协议（游戏 → AI）

### 3.1 结构

- 奏疏 = **固定系统提示词模板**（内置游戏，含人格设定、§2.2 范本判词 few-shot、圣旨 JSON 契约说明与字段示例）+ **紧凑状态摘要**（游戏按当前存档实时拼装）；
- 总长控制 **500~800 字**（`MEMO_LEN=[500,800]`）——免费 webchat 上下文友好、玩家复制负担低；超长按字段优先级（编年史 > 状态摘要 > 香火栏）压缩；
- 奏疏为纯文本，玩家一键复制；**不含任何存档原文 / 内部字段名 / 密钥**（摘要字段全部是渲染后的叙事口径）。

### 3.2 状态摘要字段

| 字段 | 内容 | 取值来源（实施批对表） |
|---|---|---|
| 境界与修为进度 | 当前境界名、修为 / 下一阶 need 百分比 | `ws.realm`、`ws.qi`、REALMS 表（数值详设 §6.1） |
| 灵石 | 当前持有数 | `ws.stones` |
| 业力档 | karma 值与所在区间摘要 | `ws.karma`（KARMA_CLAMP ±1000 既有口径） |
| 阵营 | 正道 / 中立 / 魔道 | karma 档位派生（数值详设 §8.1 ALIGN_EFFECTS 同分档） |
| 当前秘禁区与词缀 ✅ | 区名 + 当前词缀名与剩余时长 | `ws.zone`、`ws.zoneAffix`（数值详设 §2.5 ✅ 已落码 `data.js:494`/`combat.js:43`；2026-10-07 执行取证 = 奏疏实测出「身在乱星秘窟，词缀灵潮。」，无词缀时回落 `tiandao.memo.noaffix`「词缀无」——`tiandao.js:273-276`，「未实施期显示无词缀」的降级口径已成为**正常态兜底**而非待实施） |
| 下次渡劫预估难度档 | 定性档位（如 顺 / 常 / 险 / 绝），读既有预估口径 | 渡劫预估（`XTrib.info()` 同源，分档映射实施批定） |
| 势力职位与关系要点 ✅ | 效力势力、职级 / 职位、敌友关系一两句 | `ws.factionRep` 派生（势力全录 §三/§八 ✅ 已落码：`tiandao.js:282-285` 读 `Factions.nameOf` + `Factions.rankOf`（阈值表 `FACTION_RANKS.TH`）；2026-10-07 执行取证 = 奏疏实测出「效力黄枫谷，职级真传弟子。」） |
| 道侣 / 羁绊要点 | 道侣形态、护法位、关键道友一两句 | Bonds 既有读点 |

### 3.3 编年史（核心差异化字段）

- **最近 10 条大事**（`CHRONICLE_MAX=10` 环形缓冲）：破境 / 渡劫成败 / 结缘陨落 / 叛宗 / 首通 / 领抗旨记录；
- **累计统计**：渡劫成败次数、领旨 / 抗旨次数、业力区间、首通区数；
- **提示词硬要求：AI 判词必须能引用编年史**（few-shot 范本同步示范引用句式）——这是「天道记得你」的契约化表达，也是与通用 AI 套壳的本质差异；
- 实施注记：编年史数据源 = 既有结算日志与存档统计的取数映射（`ws.cleared` / 渡劫统计 / `ws.tiandao.history` 等）；领旨 / 抗旨**累计**计数如既有存档无来源，实施批在 `ws.tiandao` 内补累计计数子结构（唯一写口纪律不变，收口时登记工程规范卷存档字段总表）。

### 3.4 香火栏

- 奏疏末行附本次问天供奉的灵石数（§5.2 四档之一）与对应档位的启示提示（香火越厚、稀档权重越高——档位由游戏预掷后写入奏疏，AI 按档回应；本地模拟同权重直掷）。

## 四、圣旨契约（AI → 游戏）

### 4.1 契约字段

回复中的圣旨为**严格 JSON**，七字段：

```json
{
  "decreeId": "td-20261002-a1b2c3",
  "hexagram": "问劫",
  "tier": "敕令",
  "type": "天心护佑",
  "payload": { "tribBonus": 0.02 },
  "verdict": "……毒舌判词（引用编年史）……",
  "omen": "劫云偏东，雷声藏了三分敬意。"
}
```

| 字段 | 语义 | 校验 |
|---|---|---|
| `decreeId` | 圣旨唯一 id（AI 按契约生成；本地模拟由引擎生成） | 已入 `seenIds` → 幂等无效（「此旨已领」） |
| `hexagram` | 卦位（§5.3 六选之一） | 非法值按「烧空表」语义降级为纯文本档 |
| `tier` | 档位：**天机 / 敕令 / 稀** | 非法值按天机档记账（宽进；逆天值按此档计） |
| `type` | 旨意类型 | **白名单枚举**（§4.2），不在白名单 → 整旨拒绝 |
| `payload` | 数值参数（按 type 的 schema） | 越界 → clamp 到词表区间 |
| `verdict` | 毒舌判词文本 | 敏感词过滤（§2.3），越线降级谶语 |
| `omen` | 谶语短句 | 纯文本 |

- 实施注记：`type` / `tier` / `hexagram` 的枚举值以本卷中文名为正典口径；实施时允许映射为稳定英文 / 拼音 id（与词表一一映射），**白名单成员与映射关系不变**。

### 4.3 解析三层容错

| 层 | 动作 | 失败去向 |
|---|---|---|
| ① 剥壳 | 剥 markdown 围栏 / 前后缀杂讯（AI 常见的「好的，这是您要的 JSON：」类包裹） | 进 ② |
| ② 提取 | 提取回复中**第一个 `{...}`** 完整 JSON 块 | 进 ③ |
| ③ 降级 | 本地生成「天机紊乱」谶语档（type='谶语'，零效果） | 终止——**绝不崩、不抛异常** |

### 4.4 校验器

- `type` 不在白名单 → **整旨拒绝**，降级谶语档；
- `payload` 数值越界 → **clamp 到 §4.2 词表区间**（clamp 后照常生效，不整旨拒绝——宽进严数值）；
- `decreeId` 已入 `seenIds` → **幂等无效**，提示「此旨已领」；
- 卦位作用域（§5.3）为**生成端约束**（提示词硬要求），校验器不按卦位二次拒绝 type（容错优先，越卦旨意按白名单照常兑现）。

### 4.5 一次性纪律

- 每道圣旨一次性：生效后 `decreeId` 入 `ws.tiandao.seenIds`；重复粘贴同一回复永远得到「此旨已领」；
- 领旨 / 抗旨二选一后本旨终结（抗旨也入 seenIds——驳过的旨不能再领）。

- **问题**：扩容前每节点仅 3 条模板、`randInt(1,3)` 裸掷无记忆，一局内同一节点连掷两次即撞文案（玩家实测「天象内容太少」的主因是**重复**而非绝对条数）。
- **口径**：去重范围 = **一局（一世 `ws`）**，不入 `meta`——转世即清空，下一世从头开始（与 `ws.tiandao.seenIds` 旨意幂等账同层级、同生命周期）。
- **容器**（两个整数掩码，落档 ≈30B，刻意不存 id 字符串数组以零成本满足容量防线批的存档纪律）：

| 字段 | 形态 | 语义 |
|---|---|---|
| `td.omenSeen[]` | 长度 = `OMEN_NODES.length`（7）的整数数组，缺省 `[0,0,0,0,0,0,0]` | 第 i 位 = 第 i 个节点已用过的模板位掩码；bit k 置位 ⇔ 模板 `k+1` 已用 |
| `td.chenSeen` | 单个整数，缺省 `0` | 谶语池已用位掩码（30 位 < 2^53，安全整数内） |

- **选取算法**（`pickOmenTpl(node, td)` / `pickChenYu(td)`，唯一取用口）：
  1. 取该节点池容量 `n = OMEN_TPL_N[node]`，算未用集合 `free = {k ∈ [1,n] : bit k-1 未置位}`；
  2. `free` 非空 → 从中均匀随机取一、置位、返回；
  3. `free` 为空（该节点池耗尽）→ **重置该节点掩码为 0** 后重取（开启第二轮），不报错、不入日志、对玩家不可见；
  4. 谶语同法（池 30，耗尽重置 `chenSeen`）。
- **配权依据**（每节点池容量 ≥ 该局期望触发次数，使第二轮在正常局内几乎不发生）：

| 节点 | 一局期望触发 | 池容量 | 依据 |
|---|---|---|---|
| `tribwin` | 9~13 | **12** | 每境界一次渡劫成功，REALMS 9 段 |
| `tribfail` | 0~15 | **13** | 失败可重试，上限高于成功 |
| `break` | 9~13 | **15** | 与渡劫成功同瞬间但**独立入队一次**（§7.1 合并注记：叙事双评） |
| `clear` | ≤10 | **15** | 秘境 10 区首通 |
| `karma` | 4~8 | **10** | 三阵营档位跨线 |
| `war` | 5~15 | **13** | 势力冲突开战，随机性最大 |
| `rebirth` | 1 | **8** | 每世一次；留足余量供飞升 / 兵解 / 转世三种收束文案取向，且仍为七节点最小池（配权不倒挂）|

- **normalize**：`omenSeen` 逐项 `Math.floor` + clamp `[0, 2^OMEN_TPL_N[node])`、长度不足补 0、超长截断；`chenSeen` 同法 clamp 到 `[0, 2^30)`。脏档零崩溃、旧档无字段 → 全默认（§8.1 既有纪律）。
- **红线**：去重只影响**取哪一条模板**，不改任何机制数值；天象仍是纯文本零机制产物、不进 tick（§9.3 / 验收 #196 口径不变）。
