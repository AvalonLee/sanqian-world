## 建议批次顺序

```
A（丢档与静默面收口，含 A3 取证）→ C1+C2（界面盲区）→ C3+C4（门禁可信 + 提速）
→ B1（挂到下一条改结算批）→ D1（降频落盘）→ C5+E1+E2（账本与文档）
→ D3 或 D4 的口径裁定 → D2 → D5 逐片 → B2 → G1
```

理由：A/C 都是「不裁定就能做、且每条能少一次返工」；B1/D1/B2 各自挂着锚或容量，等窗口；D3/D4/G1 三条都在等同一句点头，先点再做。

## 每批收口纪律（沿用，不新立）

`npm test` 必跑 ‖ 改到界面再 `npm run test:ui` ‖ 改玩法数值/节奏才 `npm run test:sim` ‖ 升版本只改 `manifest.json` 一处 + `npm run ledger:fix`（档位 = 每批 +0.0.1）‖ 一次性件写到仓外 ‖ `git checkout -b <主题> dev` → PR 进 `dev` ‖ 提交后 `git status --porcelain` 为空 **且** `git show --stat HEAD` 与批次叙述逐文件对表。
