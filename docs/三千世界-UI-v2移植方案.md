## 0. 结论先行

1. **这不是一次换皮，是「壳 + 信息架构 + 全部页面渲染器 + 两块演出」的整体换装。** 设计稿的 88KB HTML 里绝大多数是静态演示数据，真正要移植的是：五区导航、三栏布局、宣纸水墨令牌、行/卡/条这几组原语，以及每页的「一屏一主事」重排。
2. **引擎、存档、词表、动作名基本不动。** 所有页面渲染器仍是「读 `c.w/c.p/c.d/c.mods` → 拼字符串」，只换拼出来的结构与样式；`data-act` / `id` / 判定条件保持原名，测试改造量才能收敛。
3. **三件事已拍板**（详见 §7.1）：  
   - 宣纸底选 **B**：照设计稿铺不透明宣纸 + 自带墨夜，同步改 UI 卷 §8.1；  
   - 创角顺序 **保持**「名 → 择界 → 观天赋」，设计稿步骤条随之改；  
   - 「法与器」**拆掉**，分成功法 / 百器两页（测试改动最大，单独一批）。
4. **建议 11 批 PR**：先壳、再试点、再拆页、再逐区换页、最后浮层与收口。每批都保持 `npm test` 绿，不做「全部改完再跑」。
5. **最大的三个风险**：设计稿把现有页面大量内容省略了（照抄会丢功能）；52 处旧名引用 + 97 处 `#tab-arts` 选择器 + 90 处导航点击会把测试成批打红；宿主主题铁律不允许铺不透明页面底。

### 2.5 行为变化（需明确接受）

1. **创角顺序**：设计稿先观天赋后择界；现行天赋池由所选世界决定（`draft.worldId` 先定，`rerollTalents()` 才抽）。**已拍板保持现行顺序**，原型步骤条已改为「立名 → 择界 → 观天赋」。
2. **道心预告**：现行 UI 卷明确「karma 不预告（按钮无道心数值）」；设计稿三分支右侧直接写 +24/−24/+2。这是玩家决策信息的变化。
3. **渡劫确认**：现行点「渡劫」立即掷判；设计稿先给一张七项账单，再按「引雷」。这是节奏变化，也改变「自动渡劫」的演出路径。
4. **菜单顺序下线**：设计稿明确取消；现行 `settings.tabOrder` 是落盘偏好，还有走查 A10 钉着。
5. **离线「收下」**：现行是自动结算、无手动收功；设计稿的「收下」按钮不能照搬，否则会把已结算的收益说成待领取。
6. **寿元写法**：设计稿写「5 / 5,162 年」；现行已按用户令改为「N 岁，尚余约 M 年」，不能回退。
7. **修为数字**：设计稿用「8.52 亿」；现行修行页刻意用全位数字逐秒跳动，不能回退成分段缩写。
8. **天赋品阶**：设计稿用「天 / 地 / 人」三品竖排；现行数据只有 `common` / `rare`（转世赠礼另有 `epic`），创角池不会出现「天品」。照搬会显示不存在的品阶。建议保留现行「稀有」角标，或建立 `epic→天 / rare→地 / common→人` 的映射，但创角屏实际只会出现地 / 人两档。
9. **所有池计数**：设计稿的「17 处势力」「44 位道友」「96 件百器」「131 条奇遇」等是演示值或旧快照；一律从引擎取，不抄数字。

### 2.6 宿主平台冲突（必须处理）

- UI 卷 §8.1：页面底永远透明；深浅色归宿主 `data-xhub-theme`；面板用宿主玻璃令牌；扩展不做自己的主题切换按钮。
- 设计稿：整张不透明宣纸 + 自带墨夜切换 + 固定 392×848 / 1440×920 设备框。
- **结论（已拍板 D1=B）**：主题切换、设备框、工具条、说明区仍属原型专属；但宣纸底与自带墨夜**按设计稿保留**，迁入时同步改 UI 卷 §8.1 的平台铁律。

## 3. 移植原则

1. **只搬结构与样式，不搬原型数据、文案、JS。** 设计稿里的「罗云州」「85.0 万」「苏晚」都是演示值；所有值从现有引擎取，所有文案走词表。
2. **保留 `id` 与 `data-act`。** `#tab-*`、`#m-tabbar`、`#m-who/#m-rank/#m-stones/#m-sub`、159 个 `data-act` 名称不动；换的是它们外面的结构与 class。
3. **CSS 分域，不做全局同名覆盖。** 现行 `.lrow` 是卡片，设计稿 `.lrow` 是平铺行；同名直接追加会把未移植页面一起改坏。新原语统一 `sq2-` 前缀；页内类名用 `#tab-*` 作用域（如 `#tab-zone .zrow`）。每页移植完，删掉该页不再使用的旧选择器。
4. **一页一批。** 每批只换一页（或一个紧凑页组），同批改该页的走查；不做「壳换完、页全白」的中间态。
5. **引擎零改。** 新读数必须来自既有 API（`SQ.*` / `worldSystems.*` / `w` 字段）或页内派生；不新增落盘字段。确实需要新字段（如动效开关）单独裁定。
6. **不静默丢功能。** 原型省略的现行块，按 §2.3 的「必须保留」列安置：折叠段、右栏、详情浮层、设置页。任何要删的功能先登记，不靠「设计稿没画」当理由。
7. **可访问性不回退。** 44px 点击区、`prefers-reduced-motion`、色弱不靠纯色、窄屏不横向溢出。
8. **收口标准**：`npm test` 绿；改动到的走查 + `verify-ui-alltabs` 绿；`npm run test:ui` 全绿；380/720/1024/1440 四档截图无横向溢出、无 pageerror。

### 4.2 导航数据模型

把 `GAME_TABS` 从「一维数组」扩成「区 → 页」：

```js
var SECTIONS = [
  { id: 'idle',  labelKey: 'nav.sec.idle',  items: ['idle'] },
  { id: 'zone',  labelKey: 'nav.sec.zone',  items: ['combat', 'event'] },
  { id: 'arts',  labelKey: 'nav.sec.arts',  items: ['arts', 'gear', 'treasure', 'alchemy', 'shop'] },
  { id: 'bonds', labelKey: 'nav.sec.bonds', items: ['bonds', 'faction', 'prodigy', 'sect'] },
  { id: 'life',  labelKey: 'nav.sec.life',  items: ['achv', 'legacy', 'journal', 'settings'] }
];
```

- `GAME_TABS` 保留为「页元数据表」（id / 词表键 / 门槛），顺序由 `SECTIONS` 决定。
- `tabOrder()` 不再参与导航；旧档 `settings.tabOrder` 读了也不用（字段保留，不做迁移）。设置页的「菜单顺序」整块下线。
- **桌面**：`#m-tabbar` 仍作为导航容器，渲染 5 个区标题 + 16 个页按钮；保留 `data-v`，现有按 `data-v` 点的走查不改。**结构上保持「区标题与页按钮同为 `#m-tabbar` 的直接子元素」**，不要真的套 5 个 `.band` 容器——`verify-ui-arts` A0 用 `bar.children` 数按钮，嵌套会当场打红；区标题只是插在按钮序列里的兄弟节点。life 区之前保留一枚 `navsep`，A0 的「12 游戏 + 3 系统」判据可以少改。
- **手机**：`<720px` 隐藏 16 项 `#m-tabbar`，出 `#m-zonebar`（5 个区按钮，B13 落地）；区内子项仍由 `#m-subnav` 承担。这样默认 1280 宽度的走查仍点 `#m-tabbar button`。
- **子导航**：桌面也显示当前区的子项（设计稿 `.subnav`），与左带高亮同步；它是「同区快速切换」，不是第二套权限。
- **红点**：沿用现有键（`newArtsDot` / `newTreasureDot` / `newBondDot` / `newShopDot` / `newFeedDot` / `newLogDot` / 成就签名 / 解锁红点），挂在二级项上；区标题汇总亮一个小点即可，不新造判定。

### 6.3 建议新增的判据

1. **壳**：`#m-tabbar` 恰 5 band + 16 项；切页时 band/subnav 高亮同步；门槛项仍为「？」且不可点。
2. **右栏**：每个区至少一个块；块内数字与页面同源（例如修行四柱的灵石 = 顶栏灵石）；无数据块不出现。
3. **不丢功能**：为每页列一个「必须存在」的元素清单（域主按钮、洞天节、融合坛、库藏阁、造化换算、特席、承袭入口、60 条成就段、称号墙、自动三开关），一条断言一个。
4. **不回退**：修行页修为为全位数字（含千分位、非「万/亿」）；寿元行含「岁」与「尚余」；离线条没有「收下」式领取按钮。
5. **响应式**：380/720/1024/1440 四档，`document.scrollingElement.scrollWidth <= clientWidth`；卡片网格列数随宽度变。
6. **主题**：`data-xhub-theme=dark` 下文字/线/面可读；不出现写死浅色底导致的暗色白块。
7. **零 pageerror + 零 console error**：每篇收口照旧。

### 7.3 主要风险

1. **内容丢失**：设计稿是「核心六屏 + 补铺」，每页只画了主路径；照抄会把大量既有功能挤出屏幕。对策 = §2.3 的保留清单 + §6.3 的「必须存在」断言。
2. **测试雪崩**：拆页 + 改名 + 结构重排三件事叠在一起会一次打红十几篇。对策 = 分三批、每批只改一类口径。
3. **宿主主题**：不透明底/自带主题是平台铁律的反面；先拍板再动 CSS，避免做完再返工。
4. **渲染性能**：右栏每秒重绘 + 页面每秒重绘，若在右栏里重复跑重计算会拖慢 tick。对策 = 复用 `mods()` 缓存，右栏只做轻量派生。
5. **CSS 冲突**：`.lrow` / `.slot` / `.bar` 等同名不同义，直接追加会改坏未移植页。对策 = `sq2-` 前缀 + 页 id 作用域。
6. **词表孤儿**：合并页/菜单顺序退役会留下 `arts.system`、`arts.seg.*`、`arts.ov.*`、`settings.taborder.*`；A6 会当场红。对策 = 同批删键并改 smoke/probe。
7. **旧档兼容**：`settings.tabOrder`、`ui.lawChip`、`ui.feedExpand` 等内存态不迁移；旧档不能崩。对策 = 保留字段、忽略未知 id、走查加旧档加载。
