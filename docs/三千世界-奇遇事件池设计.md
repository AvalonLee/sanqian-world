## 一、设计原则

1. **引擎与内容分离**：触发/筛选/结算逻辑在通用引擎 `systems/events.js`，事件词条是内容包 `worlds/{worldId}/events.js`——换世界只换词条和文案，引擎不动（对标天赋池的两层结构）。
2. **三分支抉择制（v1.6 核心重构）**：旧的 positive/negative/choice 三分类废除——**每一条奇遇都是抉择事件**，固定提供 **正道 / 魔道 / 左道** 三个分支：各带 karma 值与浮动收益，选定后按事件设定掷判定。事件本身改用两维标签：**性质 `nature`（机缘 good / 危机 bad）× 等级 `tier`（人 / 地 / 天）**。奇遇由此成为修仙善恶系统的核心内容载体——「你是谁」由一次次三分支选择堆出来。
3. **机缘/危机偏向由 `eventLuck` + 阵营档位共同驱动**：`eventLuck` 不改变触发频率（频率归奇遇时钟 × `eventRate`），只修正机缘/危机抽取权重；阵营档位另给基础权重位移（正道 70/30、左道 55/45、魔道 35/65，见数值详设 §8.1 ALIGN_EFFECTS）。
4. **防刷屏**：同一事件有独立冷却；`once: true` 的事件一生只出一次（用于剧情向彩蛋与顶级独占奖励）；连续两次触发不出同一事件。
6. **奇遇是叙事与收集的主载体（v1.6）**：每条奇遇配 100~200 字叙事文本（梗化二创，见 §六），触发记录进奇遇图鉴（见 §五）——「遇过的仙」本身成为收集玩法。
5. **结算全部走 `mutate`，但**奇遇是在线玩法**：事件效果与玩家手动操作同一条读改写通道；触发只发生在在线 tick（v1.5 起离线结算不再产生奇遇，见 §四）——「闭关静修不遇仙，出世方知天下事」，奇遇的稀缺感与打开游戏的仪式感绑定。

## 二、数据结构（v1.6 三分支抉择制）

```js
// worlds/xiuxian/events.js 中的单条奇遇
{
  id: 'demon_at_crossroad',
  world: 'common' | 'xiuxian',
  tier: 'ren' | 'di' | 'tian',       // 人 / 地 / 天三级（收益与判定幅度带）
  nature: 'good' | 'bad',            // 机缘 / 危机（叙事视角与 karma 基调）
  special: false,                    // true = 特殊奇遇（必带 cond 触发条件，图鉴单列）
  weight: 8,                         // 同 等级×性质 池内抽取权重
  once: false,                       // true = 每个存档只触发一次
  cooldownHours: 36,                 // 同一事件再次触发的最小间隔
  cond: {                            // 触发条件（普通奇遇为 null；特殊奇遇必填 ≥1 项）
    realmMin, realmMax, zoneMin, zoneCleared,
    minKarma, maxKarma, align,       // align: 要求当前 karma 档位
    hasArt, gearSpecial              // 持有某功法 / 佩戴某特殊词条法器
  },
  storyKey: 'event.demon_at_crossroad.story',  // 100~200 字叙事文本（词表 key，创作守则见 §六）
  choices: {                         // 三分支固定齐全：right / evil / neutral
    right:   { labelKey, karma: +15, gain: [ { stones: [60, 120] } ],
               check: null },
    evil:    { labelKey, karma: -20, gain: [ { stones: [180, 320] }, { qiPct: [-0.06, -0.03] } ],
               check: { type: 'attr', attr: 'jing', dc: 'medium' } },
    neutral: { labelKey, karma: -2,  gain: [ { stones: [100, 180] } ],
               check: { type: 'stones', cost: [80, 150] } }
  }
}
```

### 2.1 三分支设计三角（内容守则）

| 分支 | karma | 收益 | 判定倾向 | 叙事口吻 |
|---|---|---|---|---|
| 正道 right | +（幅度按等级带） | 中规中矩（×1.0） | 宽松或无判定 | 仗义出手、舍利取义 |
| 魔道 evil | −（幅度按等级带） | 高（×1.5~2.0） | 严苛判定，失败反噬大 | 趁火打劫、富贵险中求 |
| 左道 neutral | ≈0（±小幅） | 稳（×0.8~1.2） | 资源型判定居多（灵石/修为「买路」） | 明哲保身、花小钱办稳事 |

- **收益全部为随机浮动值**：数值字段一律 `[min, max]` 区间均匀取整（v1.6 起禁止定值），同一条奇遇两次触发收益不同；
- **karma 幅度带**：人级 |k| ≤ 8 / 地级 ≤ 15 / 天级 ≤ 25；karma 不受判定成败影响（义挙不因力竭打折）；
- 危机（bad）事件的三分支 = 三种应对方式（正：迎难而上护人 / 魔：借危牟利 / 左：破财消灾），**危机分支收益可以更高**（风险补偿），但 karma 与判定代价同步上浮。

### 2.2 判定 DSL（v1.6 扩至八类，按事件设定选用）

| type | 判定内容 | 通过 | 失败语义 |
|---|---|---|---|
| `attr` | G12 属性判定 `{ attr, dc }`（正道档位 dc ×0.95） | 全额收益 | 收益折半或小幅损失 |
| `karma` | 善恶值门槛 `{ min?/max? }` | 全额 | 分支不可选（置灰）或收益折半 |
| `align` | 当前 karma 档位 == `{ need }` | 全额 | 收益折半（「正道身板干魔道勾当，手艺生疏」） |
| `stones` | 支付灵石 `{ cost: [min,max] }`，足额即过 | 扣灵石 + 全额收益 | 不足 = 失败（不扣） |
| `qi` | 消耗修为 `{ pct }`，足额即过 | 扣修为 + 全额收益 | 不足 = 失败（不扣） |
| `art` | 持有/槽内功法 `{ has?/slotted?, id?/tier?/alignment? }` | 全额（可选额外消耗功法等级） | 分支不可选或收益折半 |
| `gear` | 佩戴法器 `{ slot?/tierMin?/special? }` | 全额 | 同上 |
| `power` | 战力 ≥ 当前秘境需求战力 × `{ ratio }` | 全额 | 收益折半 + 小伤 debuff |
| `companion` | 护法位档位 ≥ `{ minTier }`（G14 道友结缘，v1.8 第九类） | 全额 | 收益折半（「交情尚浅，无人搭手」）；魔道档位护法位失效 → 必然失败（按钮显示「无人可援」置灰提示） |

- **判定护栏不变**：失败损失 ≤15% 资源、debuff ≤24h；天级特殊奇遇可设**多重判定链**（`check: [c1, c2]` 顺序掷，全过才拿独占奖励）；
  - **v1.11 升级为强制 lint（冒烟 #121）**：`failE` 内 `qiPct` 幅度带下界不得低于 −0.15、`failE` 内任何 `mult<0` 的 buff `hours ≤ 24`，超限即冒烟失败——护栏不再只是写作守则；
  - **v1.11 内容勘误（代码批 1 实测发现）**：两个内容分卷共 **26/40 处 `failE` 幅度带超限（−18%~−30%）+ 6 处 debuff 48h 超限**。魔道分支判定通过率实测仅 40%（左道 81% / 正道 60%），超限反噬与低通过率相乘，把 ALIGN_EFFECTS 魔道 ×1.5 的领先吃干并反转（长窗净进度 −14~−26%）。按「下界钳到 −0.15、上界同比缩放」回缩，48h debuff 压到 24h；正向超长 buff（天级 once 的 72h 额度）不受影响。分卷同步升版：通用池 v2.0.1 / 专属池 v2.0.3；
  - 幅度带映射表（改数唯一依据）：`−[20,30]% → −[10,15]%`、`−[15,25]% → −[9,15]%`、`−[15,22]% → −[10,15]%`、`−[12,20]% → −[9,15]%`、`−[12,18]% → −[10,15]%`、`−[10,16]% → −[9,15]%`；
- 判定只在玩家选定分支时在线掷（v1.5 离线零奇遇口径不变）；
- attr 判定的 UI 成算预告沿用《角色属性设计》§四（五档话术：十拿九稳 ~ 九死一生）。

### 2.4 普通奇遇 vs 特殊奇遇

- **普通奇遇**：`cond: null`，仅受境界/区域通用筛选，按权重进池——日常流量主体；
- **特殊奇遇**：`special: true` 且必带触发条件（karma 区间 / 阵营档位 / 持有指定功法 / 佩戴指定特殊词条 / 首通指定秘境 / once 剧情），条件满足才进池——**剧情彩蛋与顶级独占奖励（§七）的主要载体**；图鉴中单列「特殊」徽标，未解锁显示「？」。

## 三、触发机制

### 在线奇遇时钟（v1.5 核心改动）

奇遇由一个**只在在线时推进的时钟 `eventClock`（单位：秒）**驱动，取代旧的固定 `BASE_CHANCE = 0.10/小时`。设计意图：把奇遇变成「在线玩法的核心回报」——在线越久越可能遇仙，且**最长 20 分钟必遇一次**（硬保底），彻底告别「在线挂机一小时无事发生」的空窗。

```
仅在线 tick 推进（离线不结算奇遇，见 §四）：
1. eventClock += dt（dt = 本次在线 claim 的秒数）
2. 每跨过一整分钟（eventClock 进入新的第 k 分钟段，k = floor(eventClock/60) + 1，k∈[1,20]）
   掷一次「本分钟段是否触发」，段触发概率随 k 非线性（二次）增长：
       p_k = min( 1, (k / 20)^2 × (1 + Σ eventRate) )      // 二次曲线，慢起陡收
   当 k = 20（即在线累计满 20 分钟）时强制 p = 1 —— **20 分钟硬保底，必定触发**
3. 未命中 → 继续累积时钟；命中 → 两级抽取（v1.6）：
   ① 掷性质 nature：机缘/危机，基础权重取当前阵营档位 ALIGN_EFFECTS.natureW
      （正道 70/30，左道 55/45，魔道 35/65），再受 eventLuck 修正：
      luck>0 → 机缘权重 +luck×100，危机权重 −luck×60（luck<0 反向；各侧下限 10）
   ② 掷等级 tier：人/地/天，权重取 ALIGN_EFFECTS.tierW（左道 60/30/10，魔道 35/40/25）
4. 组池：common 池 + 当前世界池，取 该性质×该等级 子池，过滤 cond / 冷却中 /
   已触发过的 once 事件，且排除上一条触发的事件 id；
   子池为空 → 逐级回退（先降级 tier：天→地→人；再翻 nature），仍空 → 本次触发流产，
   **eventClock 保留不清零**（下分钟段继续掷，不浪费玩家时钟）
5. 按 weight 加权抽一条 → **弹三分支抉择模态**（story 全文 + 正/魔/左三分支，
   写 pendingChoice 挂起）；玩家在模态中选分支 → 掷该分支 check → 结算 gain →
   karma 入账 → 写 log 与叙事流（§十）
6. **触发即重置**：eventClock = 0，重新开始计时；记录 eventCooldowns[eventId] = now、
   eventHistory.seen[id] = 首遇时间戳（图鉴解锁，§五）
```

- **非线性曲线口径**：`p_k = (k/20)²` 为无 eventRate 基线，逐分钟段为 `k=1→0.25% / k=5→6.25% / k=10→25% / k=15→56% / k=19→90% / k=20→100%（硬保底）`。期望触发间隔 ≈ **9.2 分钟**（约 6.5 条/在线小时），20 分钟硬保底自然触发率 ≈ 99.996%，几乎只为极端非酋兜底；eventRate 只加速命中、**不缩短 20 分钟保底的上限语义**（保底分钟段恒为 p=1）。**（修行状态批 v2.0）rateMult 再乘模式乘区 `MODES[ws.mode].eventMult`（闭关 0.5 / 历练 1.5）**——本节 6.5 条/h 为无模式（×1）基准口径；实测闭关 ≈4.7 条/h、历练 ≈7.0 条/h（20 分钟保底不随乘区线性缩放，sim-event-economy 重跑校准）。
- **挂起即冻结（v1.6）**：`pendingChoice` 挂起期间 **eventClock 暂停累积、不再抽新奇遇**（防止模态未关时奇遇堆积）；玩家关掉游戏也不丢——pendingChoice 跨离线保留，回线恢复弹窗；
- **存档字段**：`worlds.{id}` 的 `buffs: []`、`eventCooldowns: {}`、`eventHistory: { lastId, seen: {} }`（v1.6：seen 由 once 专用列表扩为**全量首遇记录** `{id: ts}`，供图鉴消费；seenOnce 语义并入 seen + once 标志）、**`eventClock: 0`（秒，在线奇遇时钟，v1.5）**（全部纳入 normalize 缺省补齐）；
- **在线 UI**：v1.6 起所有奇遇都走三分支抉择模态（**必须选择才关闭**，无倒计时、不自动选）；旧「非 choice 事件 toast 直结算」通道废除，结算结果仍写日志栏与奇遇叙事流。

## 四、离线与奇遇（v1.5 重写：离线零奇遇）

- **离线结算完全不触发奇遇**：离线 `while (t < now && iter < 64)` 循环只做修为累积、离线上限截断与批量渡劫，**不掷奇遇、不推进 `eventClock`**（旧「每次 claim ≤ 3 条 / choice 自动选善分支 / 离线掷判」三条规则全部废除）；
- `eventClock` 跨离线**冻结保留**：下线时累积到 7 分钟，回线后从 7 分钟继续爬（不清零、不代练）；
- 离线的核心回报是**离线收益**（修为/灵石/渡劫，见数值详设 §1.3 与 UI 设计 §3.2 离线收益面板）；奇遇的价值锚定在「回到游戏」这个动作上——回线弹窗看完离线收益，爬时钟遇奇遇，是在线段的仪式接力；
- 回线时若存在**挂起中的抉择**（下线前未选完分支）：`pendingChoice` 跨离线保留，回线恢复弹窗，玩家选定分支时才掷 check 判定、才记 karma；
- `buff.hours` 按离线时长正常流逝——离线 8 小时吃到的 4 小时 buff，只剩 0 小时，结算时直接过期，**不给补偿**（规则简单可预期）。

## 五、奇遇图鉴（v1.6 新增 · 收集玩法）

- **数据源**：`eventHistory.seen = { eventId: 首遇时间戳 }`——触发过（无论选了哪个分支）即解锁；
- **布局**：按 天 / 地 / 人 三节纵排；每格显示：已解锁 = 事件名 + 等级色底 + 性质图标（机缘☀/危机☾）+ 特殊徽标（若有）；**未解锁 = 「？」+ 该等级色底剪影**（保留神秘感，但等级底色让玩家知道「还差几条天级」）；
- 点已解锁格 → 回看 story 全文 + 首遇时间 + 上次所选分支与结果（叙事流同源数据）；
- 图鉴进度计数显示在页首：「已遇 37 / 113 · 天级 2 / 18」；
- once 类特殊奇遇解锁后加「缘」字角标（一生一会）。

## 六、叙事创作守则（v1.6 新增 · 梗化二创）

每条奇遇配 **100~200 字** 叙事文本（storyKey 入词表），是奇遇页的主体内容。创作公式：

```
世界观场景（修仙骨架） × 互联网梗（认知捷径） → 反转收尾（落回收益/抉择语境）
```

- **人称与时态**：第二人称「你」，现在时；结尾必须停在「抉择点」上，把选择权交给三分支按钮（不在 story 里剧透分支后果）；
- **梗的使用纪律**：
  1. 优先**常青梗**（内卷/躺平/摆烂、电子木鱼、city 不 city、精神离职、硬核、天选打工人、拴Q、刺客系（雪糕刺客→丹药刺客）、画大饼、PUA、city walk、脆皮、显眼包、泼天富贵等）——半衰期 < 6 个月的时效热梗**不进池**（防文案快速过期）；
  2. 梗必须完成**世界观转译**：「996」→「九九六炉火淬体」，「内卷」→「卷宗修炼/同门内卷成蛊」，「画大饼」→「画大道之饼」——直接贴现代词原文的算不合格；
  3. 一条 story 至多 1 个梗位（梗是佐料不是主料），天级奇遇允许 2 个；
- **等级口吻带**：人级 = 市井轻快（小确幸/小倒霉）；地级 = 江湖波澜（恩怨/夺宝/秘境）；天级 = 命运岔路（大能因果/大道抉择），天级文本必须有「多年后回想此刻」的分量感；
- **审核红线**：不涉真实人物/品牌/政治与平台敏感词；负面梗自嘲可以、冒犯特定群体不行；
- 词表 key：`event.{id}.story`（叙事）、`event.{id}.name`（图鉴名）、`event.{id}.branch.{right|evil|neutral}`（分支按钮文案）；旧 `event.{id}.a/.b` 双分支 key 随三分支制废弃。

「个别顶级法器和功法，仅个别奇遇可获得」的落地机制：

| 通道 | 载体 | 规则 |
|---|---|---|
| 独占功法 | 功法全录新增 `obtain.type: 'event_locked'`（每世界 3~5 部，天级） | **不进商店池 / 掉落池 / 首通池**，仅指定天级特殊奇遇的指定分支 + 判定全过才授予；图鉴与功法架上未获得时显示剪影 |

| 独占 buff 称号 | 天级奇遇 once 奖励可给超长 buff（72h）或永久小加成（attrBonus 顶格） | 走既有效果字典，不新开系统 |

- 修仙世界首批独占清单（P5.5 内容批产出）：功法 3 部（如《斩三尸诀》《红尘炼心录》《太上忘情篇》——正/左/魔各一）+ 法器 2 件（如「诛邪剑残」「照世镜」），具体词条在世界设定分卷登记。

## 八、与善恶系统的衔接


karma 采用 **覆盖式重算**（主文档 §6.2 已定），事件贡献的是「历史事件分」：

```js
// 每次变更后重算，不用 += 增量
karma = clamp(
  Σ 功法.alignment分(Lv×±2)
+ Σ 装备.alignment分(件×±15)
+ worlds.{id}.karmaEventScore        // 三分支选择的累计事件分
+ worlds.{id}.alignDrift             // v1.6 新增：创角阵营倾向漂移分
, -1000, +1000)
```

- `karmaEventScore`（整数，初始 0）：**每条奇遇**选定分支时 `+= 分支.karma`（v1.6 起不再只有 choice 事件记账），**只增不清**（历史行为永久留痕，装备功法可以换、做过的事赖不掉——这是善恶系统的世界观表达）；
- 分支 karma 幅度受等级带约束：人级 |k| ≤ 8 / 地级 ≤ 15 / 天级 ≤ 25（§2.1）——高频触发（≈6.5 条/在线小时）下事件分仍是 karma 的主要流量，装备/功法是主要存量；
- `alignDrift`（v1.6 新增，主文档 §6.4）：创角阵营倾向 × 12/天 缓慢漂移，分量封顶 ±260——保证「长时间游玩档位固化」被打破：即使玩家不换装备不改功法，倾向也会以约 17 天/200 分的速度把角色拉向创角所选阵营；行为（事件/装备/功法）仍是主导，漂移只是底色；
- 部分修仙事件可加 `minKarma / maxKarma / align` 门槛（cond），做出 **阵营反馈**：如 karma ≤ -200 才会遇到「魔道密使」，karma ≥ +200 才会遇到「仙门点化」——配合 ALIGN_EFFECTS 的性质权重（正道 70/30 机缘、魔道 35/65），形成「档位 → 遭遇构成 → 分支倾向 → karma」的动态环，防止档位长期固化。

**长窗净进度**（12 在线小时，同 build：挂机+奇遇 vs 只挂机；取境界 7/8 —— 窗口内不触发突破、不撞修为上限；repeats=30）：

| 左道 | +18.3% | +16.1% | 13.30 → **≈11.4 天** |
| 魔道 | **−16.2%** | **−25.8%** | 9.57 → **≈12.2 天** |

**这与 §6.3/§6.4.1 的定位（魔道最快而险、正道最慢而稳）完全反转**：魔道从 0.72× 变成三档最慢，正道从 1.22× 变成最快。

把长窗差值拆成两条通道后，根因是**两个各自独立、方向相反**的实现级 bug（不是内容数值定错）：

| 画像 | 事件直接转移（qi/qiPct 一次性） | buff 放大产出（速率被临时增益抬高） | 主因 |

### 十三.4 勘误①：buff 同字段同向不叠加

- 规则：同一 `field` 的增益**只保留最强一条**，重复获得时**时长取较长者**（不缩短已在身的长 buff）；
  减益同规则独立生效——**正负号分开判**，同字段的增益不会吞掉减益（反之亦然）；
- 例外：`eventShield` 是「层」语义（逢凶化吉可叠层，四柱卷 §五 楚老拐冥佑上限 2 层），逐条并存不去重；
- 落地：引擎 `SQ.Events.pushBuff(ws, field, mult, until)` 单一入口，事件分支 / 人间烟火 / 丹药（坊市走同一 `applyEffects`）三处 push 全部改走它；
- 性质：**实现级修复**，60 条词条的 `mult`/`hours` 一字未动；「重复获得刷新而非叠加」是挂机品类的通行语义，
  也与 §八「同乘区加算」不冲突（加算仍在，只是同字段不再无限复制加数）。

### 十三.5 勘误②：`qiPct` 类效果加「等价挂机小时」封顶

- 新增世界参数 `EVENT_QI_PCT_HOUR_CAP = 1.5`（小时）；
- 结算规则：`qiPct` 生效时 `|Δqi| ≤ CAP × 当前每秒产出 × 3600`，超出即截到边界（正负对称）；`qi` 绝对值条目与 `stones` 不受影响；
- 低境界天然不触发（境界 0 的 −25% ≈ −125 修为 ≪ 上限），只在「当前修为 ≫ 1.5 小时产出」的高境界收敛：
  实测境界 8 的 −25% 由 −5.0e8 截到 −1.07e8（= 1.5h 产出）；
- 选「封顶」而不选「下调百分比幅度带」的理由：幅度带是文档定稿的内容资产，逐条重校 60 条会让低境界失去体感；
  封顶是 1 个常量 + 引擎 1 处，可复跑同脚本验证；
- 不选「抬高刷图/挂机产出对齐事件通道」的理由：动 §6.4 全表，与《数值复核报告》§五「先动 need、不轻动产出乘区」的调参优先级冲突。

### 十三.6 勘误③：灵石经济触发线重定基线

风险台账「事件经济过热」触发线由 `> 刷图收入 30%` 改为 `> 刷图收入 400%`，并追加 sink 对表口径
（洞府/坊市/功法升级三处定价各自折算成「多少在线小时事件收入」，超过 40h 或低于 0.5h 才判失衡）。
理由见 §十三.2。原「先降人级收益带」的处置顺序保留，仅在超新线时启用。

### 十三.8 勘误④：灵石缩放改「双锚」——灵石挂刷图曲线、修为保留三次方

**问题**：§2.5 旧口径「`stones`/`qi` 绝对值一律 ×(1+境界索引)³」与刷图收入曲线（`ZONES[r].stones` 每境界 ×2.5~2.7）**不同源**。

| 锚 | 公式 | 常量 | 覆盖 |
|---|---|---|---|
| 灵石锚 | `max(1, EVENT_STONE_ZONE_K × ZONES[境界].stones)` | `EVENT_STONE_ZONE_K = 0.075` | gain/failE 的 `stones` 绝对值 |

- **为什么灵石挂刷图曲线**：刷图是灵石的既有分母，同曲线 ⇒ 比值与境界无关（结构性解决漂移，不是逐境界调参）；
- **为什么留 `max(1, …)` 下限**：§2.5 明写「表内为练气期基准值」，练气/筑基（`ZONES[0..1].stones` = 3/8 → 0.225/0.6）
  若不加下限会把词条面额削到 1/4~1/10，违背内容分卷的写作语义；加下限后练气/筑基按面额结算，金丹起改挂曲线；

  对齐福地池卷（原四柱卷 §四）「灵石总投入 ≈552 万 ≈ 17 小时刷图」的长线定位（若不换锚，境界 8 只需 ≈4 小时，「长线目标」名存实亡）；

  在总增量里占比极小（实测 <1%），换锚无边际收益，反而要重定 60 条内容的面额语义。
