## 一、通用层抽象（G12，引擎规则）

世界包声明 2~4 条 **属性（attribute）**，引擎只提供统一机制，不理解具体含义（与 karma 同样的「只透传不解释」纪律）：

| 引擎职责 | 内容 |
|---|---|
| 数值合成 | `属性值 = 境界基础 + 功法滋养 + 装备滋养 + 事件永久加成 + buff`（**重算式**，与 karma 同款：任何来源变更后整体重算，防刷分；装备 = 世界化术语——修仙「法器」/ 古武「兵甲」，下同） |
| 判定机制 | 统一 `check(attr, dc)` 概率公式（§四），所有系统共用 |
| 存档 | 属性为缓存值可随时重算；事件永久加成单独存档（只增不清） |
| UI 挂钩 | 角色浮层三值面板 + 构成明细 + 判定成功率文案转换（§六） |

**各世界换皮示例**（词表层，验证抽象通用性）：

| 世界 | 属性一 | 属性二 | 属性三 |
|---|---|---|---|
| 玄幻修仙 | 精（体魄） | 气（真元） | 神（道心） |
| 古武军势 | 外功 | 内力 | 胆魄 |
| 魔法能量 | 力量 | 奥术 | 意志 |
| 科技降神 | 义体 | 算力 | 权限 |

## 四、判定机制（全系统统一）

### 4.1 公式

```
成功率 p = clamp( 0.5 + (属性值 − dc) / (2 × dc), 0.05, 0.95 )

dc = dc标准线 × 难度系数
dc标准线 = 当前境界基础值 × 2      （= 「正常养成」玩家的中位水平）
难度系数：简单 0.6 / 中等 1.0 / 困难 1.5 / 天险 2.2
```

- 属性 = dc → 50%；属性 ≥ 1.9×dc → 95% 封顶；裸身（属性 = dc/2）→ 中等难度恒 25%；属性 = 0 → 5% 下限，**永不归零**（放置游戏不羞辱人；P5 勘误：原「属性=0 → 25%」与公式矛盾，25% 对应裸身档 dc/2，梯度以 §4.2 实算表为准）；
- **阵营档位修正（v2.2 登记）**：正道光环（karma ≥ +200）属性判定 **dc ×0.95**（ALIGN_EFFECTS `checkDcMult`，数值详设 §8.1）——「各类判定条件 -5%」的实现口径，作用于 dc 而非成功率；
- **成功率加点通道（v2.2 登记）**：摄魂（功法 +10pp）、古阶引路（秦老丈道友助力 +1.5pp/档，满档 +6pp）等走加算，**合计封顶 +15pp**（工程规范 #112 审计）；
- dc 标准线随境界水涨船高，**旧内容自动降难**（金丹期的「困难」事件到元婴期自然变「简单」），无需逐条重标。

### 4.2 梯度验证（脚本实算）

| 玩家档位 | 中等难度 p（全程） | 困难 p（真仙） | 天险 p（真仙） |
|---|---|---|---|
| 裸身 | 恒 25% | 17% | 11% |
| 适中养成 | 42% → 62%（随养成缓升） | 42% | 28% |
| 极限单修 | 92~95%（封顶） | 68% | 46% |

> 判读：中等难度是「养成就有回报」的主线体验；困难/天险给极限单修留悬念——**属性堆满也做不到 100%**，选择与风险管理永远有意义。

### 4.3 判定的四个挂点

| 挂点 | 规则 |
|---|---|
| **奇遇事件**（主战场） | 事件条目挂 `check`：非选择事件替换纯权重抽取；选择事件的分支可挂判定（选了还要过骰，词条示例见《玄幻修仙/精气神属性实现》§五） |
| **渡劫失败损失** | 神被动修正损失 40%~60%（§二），不触 p 公式 |
| **战斗瓶颈** | 精 ≥ 中等 dc → 瓶颈击杀间隔惩罚 ×3 → ×2 |
| **门槛解锁** | 隐藏事件/特殊商品可设属性门槛（与 karma 门槛并列，如「神 ≥ 困难线」才遇「仙缘照面」） |

## 七、数据结构与存档字段

```
worlds.xiuxian 新增：
  attrs: { jing: 0, qi: 0, shen: 0 }        // 缓存值，随时可重算（同 karma 纪律）
  attrEventBonus: { jing: 0, qi: 0, shen: 0 } // 事件永久加成，只增不清

功法结构新增： attr: 'jing'|'qi'|'shen'
装备结构新增： attrValue: { attr, value }    // 灵品起存在
```

- 重算触发点与 karma 合并为同一个 `recalcDerived(ws)`：换装 / 功法升级 / 渡劫清零 / 事件结算后统一重算 attrs + karma；
- normalize 缺省：`attrs` 缺失 → 按当前来源重算；`attrEventBonus` 缺失 → 全 0。

## 八、平衡待办（P5 与数值复核同批）

1. 精被动的 combatPower +12% 封顶会抬高渡劫「战力项」获取速度——复核 resistBonus 战力项是否需从 ×0.15 系数微降；
2. 气 → qiCap +30% 封顶与 `max(2h, 1.15×need)` 公式的交互：确认上限放大永不影响渡劫触发（need 线不动，应无影响，跑冒烟验证）；
3. 魔道功法滋养 3/级 vs 正/左 2/级：全魔 6 槽比全正多 **+54 属性**（Lv9 重校准 = 6×9×1；旧 Lv5 口径 +30），叠加 karma −40 → 验证「魔道判定流」build（高属性过判定 + 恶分支高收益 + 渡劫劣势）是否形成有趣但不超模的第三条路线；
4. 事件 `attrEventBonus` 累计 +15 上限的投放节奏：建议 P5 首发只投 5 处（每境界段 1 处）；
5. 判定频率控制：带 check 词条占专属事件池 ≈1/4（二轮扩容后：修仙 18/80 ≈ 22%，见《专属事件池（80条）》（已归档 `_archive/`）；古武同构 18/80），维持「事事掷骰」疲劳线以下；天险难度修仙全池仅 1 条（兽潮护城·精）、古武仅 1 条（攻城肉盾·胆魄）；
6. 冒烟测试新增 6 项（见工程规范 4.10）：重算一致性、dc 随境界漂移、瓶颈精判定、神→损失修正区间、判定 clamp、善行 karma 照给。
