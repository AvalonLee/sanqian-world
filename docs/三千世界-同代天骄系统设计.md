同代天骄是《三千世界》的**同代竞争叙事层**：创角那一刻，世界上同时出道的还有 **10 名**（遗泽解锁至 **30** 名）有名有姓、有师承、有资质的同龄修士。他们按自己的节奏破境、变强，在「江湖榜·同代卷」上与你实时换位——你闭关时他们在历练，你论道赢他们时他们记仇或记恩。本卷的档位是**交互档**：天骄是「活着的同代人」而不是「模拟的人生」——系统只推进每个天骄**两个标量**（境界、战力）与一组**事件 flag**，全部戏剧性由玩家侧交互（切磋 / 结缘 / 结仇 / 宿敌 / 机缘竞争）产生；不模拟天骄的战斗、奇遇、师门细节（深度人生线 ⏸，§1.2）。机制侧全部经由既有通道兑现：bond 走 `Bonds.gain`、灵石走 `in.event`/`out.event`、心结渡劫修正走数值详设 §8.3 talent 加项——零新增乘区、玩家数值轴零影响、`sim-pacing` 稳态带复跑不变。

## 一、定位与档位

### 1.1 系统定位

- 天骄 = 与玩家**同代出道**的竞争者镜像：给放置主线一个「别人也在跑」的参照系——排名焦虑与被超越的不甘是叙事燃料，不是数值惩罚；
- 与既有系统的关系是「消费既有通道，不新开轴」：bond = Bonds 既有值域与 gain 口（洞府福地卷 §3.2）、赌注 = Ledger 既有 `in.event`/`out.event` 分类（恒等式 #113 零新增）、渡劫修正 = 数值详设 §8.3 talent 加项同读点、播报 = G17 传闻展示卡（war 卡先例）、编年史 = 天道系统卷 §3.3 数据源扩展 ✅（`tiandao.js:241-247`）、天象 = §7.1 节点表扩展 ⏳（2026-10-07 取证：`data.js:753 TIANDAO.OMEN_NODES` 仍为七节点、无「同代换位」，`pushOmen('prodrank')` 实跑返回 `null`）；
- **天骄与道友 58 人体系完全隔离**：天骄不进 companions 名录、无个体助力乘区、不占护法位、不进道友页——只共享 bonds 值存储（id 命名空间隔离，§10.1）与 `Bonds.gain` 通道。

### 1.2 档位裁定：交互档（用户拍板）

| 档 | 内容 | 状态 |
|---|---|---|
| 叙事档 | 生成、命名、阵营/势力归属、月度推进、同代榜对比 | **首版实施** |
| 交互档 | 论道切磋 / 结缘结仇 / 宿敌心结 / 机缘竞争 / 跨世宿敌 ✅ | **首版实施**（跨世宿敌 ✅ 2026-10-07 取证：轮回卷已落地——`meta.unlocks.nemesis` 购口 `data.js:777 UNLOCK_PRICES`＋`legacy.js:187`，消费口 `prodigy.js:169-178` 转世重建 / `:503-513` 转世留存） |
| 深度人生线 | 天骄自主事件模拟（其师门恩怨 / 奇遇经历 / 道侣婚配 / 陨落概率） | **⏸ 登记不做** |

**⏸ 深度人生线选做理由（登记）**：① 容量——自主事件模拟要求每天骄存事件史与关系网，击穿每人 ≤240B 预算（§10.3），30 人上限下将远超 50KB 红线，不划算；② 挫败控制——天骄自主陨落/婚配等不可干预剧情会产生「无从应对的失去感」，与 §八 挫败受控红线相悖；③ 收益比——交互档已承载「活的同代人」全部核心体验（对比 / 胜负 / 恩仇），模拟细节玩家不可见即无感知；④ 复杂度——自主事件需要独立掷判时钟与事件池，违反「不进玩家 tick、轻量结算」纪律（§十一.2）。后续如有需求以独立卷立项，本卷 ⏸ 不排期。

### 1.3 世界适用范围

- 首发**玄幻修仙世界**（人名池 / 势力池 / 阵营语汇用修仙口径）；
- **古武军势预留**：推进模型、同代榜、切磋、心结均为世界无关层——换皮只动词表 `prodigy.*` 分卷（人名池换古武姓名构型、势力池换军势 16 池、境界名走既有 REALMS 军衔命名层）；古武侧是否启用由古武批次自行评估，本卷不排期。

## 二、天骄生成（创角）

### 2.1 数量与解锁

- 创角时 roll 默认 **`COUNT_DEFAULT = 10` 名**（与玩家同刻「出道」，开场即上同代榜）；
- **遗泽解锁上限 30**：轮回卷遗泽点购买「同代更多天骄」类解锁（`meta.unlocks.prodigySlot`）后 `COUNT_MAX = 30`（新增天骄于转世开场补 roll）——meta 层唯一事实源 = 轮回转世卷，本卷只登记消费口：`meta.unlocks` 含该解锁 → 生成数取 30；解锁结构与遗泽定价**不在本卷定义**。
- **榜面节律（v1.3 榜面批）**：每代名录**至多 30 人**，**榜面只展前 `BOARD_SHOW = 10` 位的详细信息**（`Prodigy.boardShow(D)` 提供截断数）；玩家跌出前 10 时榜尾补一行自己的名次（`gap` 分隔）。榜面为**冻结快照**——每满一个节律（`RANK_REFRESH_MS = 10 游戏年 = 10 × 360 × 1000 = 3600 现实秒`）重算一次 `board()` 并把 `myRank` / `rankRows`（`{me,id,realm,power}`）落 `ws.prodMarks`，区间内直接读快照、不每 tick 重排；玩家榜位变动推 `prodrank` 编年 + 传闻（§4.2）。
- **⚠️ 存档压缩例外（v1.4 · 存档容量防线批 2026-10-05）**：`rankRows` 满档 31 行（`COUNT_MAX + 1`）实测 **1.64KB**，是名录 2→10 / 上限 4→30 扩容后主档越 50KB 红线的主因之一，故列为**存档压缩阶梯级⑨**（正典 = 轮回卷 §8.4 v1.4）——主档超 45KB 触发线且前八级耗尽后，落盘**裁除 `prodMarks.rankRows`**。**零功能损失依据 = 本卷 `Prodigy.rankRows()` 既有契约「无快照返回 null → 视图回落实时榜」**；代价仅「**区间内不重排**」语义在本次落盘后失效（视图改读实时 `board()`，下次 `RANK_REFRESH_MS` 到期重新冻结快照即恢复）。`prodMarks` 其余字段 **`slotMax`（槽位不复用、斩杀出榜者占号）/ `myRank` / `rankAt` / `sudiWin` / `evf`（事件幂等键）全部保留**，级⑨只裁 `rankRows` 一键。断言 **#249**（裁除 + 回落闭环 + 字段保留）。

### 2.2 人名池（prodigy.name.* · 自建 · 复用世界名命名池构型）

- 构型同《玄幻修仙/世界设定》§五 世界名命名池（三段拼接 **9 × 7 × 5**），**独立自建三段池、表值互不混用**（世界名池是 prefix/middle/suffix 地名词，本池是姓/名一/名二人名词）：

```
姓（9）：   苏 顾 叶 萧 洛 裴 谢 楚 秦
名一（7）： 青 云 寒 惊 梧 照 凌
名二（5）： 尘 崖 霄 月 珩
```

- 池规模 = 9 × 7 × 5 = **315 组合名**；样例：顾青尘 · 裴照月 · 楚凌霄 · 苏梧珩；
- 存档只存三段索引 `nm:[s,m,l]`（≈10B，§10.2），名字渲染走词表 `prodigy.name.{s|m|l}.{1..n}`；
- **重名去重**：同档内两名天骄全名不得相同（撞名重掷该段）；与既有 58 道友道号撞名**可接受**（道友池多为单字 id 拼音 + 道号，如「韩立」——撞名属江湖常态，无机制影响，登记不处理）；
- 姓氏池与道友 id 防混注记：天骄 bonds 键用 `pr{n}` 槽位前缀（§10.1），不用姓名拼音，**不存在与道友 id 撞键的可能**。

### 2.3 天赋简化 roll（纯展示 · 零数值）

- 从**既有天赋池正面词条**抽 **2 条**（同一次 roll 内不重复，抽取权重沿用天赋池 weight 口径）：~~现行池 = 通用正面 28 + 修仙专属正面 40 = 68 条~~；系统深化批扩容后 = **勘误（2026-10-07 执行取证 `SQ.TALENTS.common.positive` / `SQ.TALENTS.xiuxian.positive` 实跑计数）：通用正面 40 + 修仙正面 66 = 106 条**——原登记「28+40=68」与「36+62=98」两口径均已过期，双口径作废，收口 = **106 条单口径**（抽取实现 = `prodigy.js:124-134`，两池 positive 合并按 weight 加权）；
- **红线：纯叙事展示**——天骄天赋只渲染在天骄详情页（复用 `talent.{id}.*` 既有词表 key，零新文案），**不进 `mods.collect`、不作用玩家、不作用天骄战力公式**（战力只由境界 × 资质档系数派生，§3.3）；
- 存档存 2 个天赋 id 字符串（≈30B）。

### 2.4 阵营与势力归属

## 三、推进模型（每游戏月轻量结算）

### 3.1 结算节奏

- **每游戏月结算一次**（游戏历口径：1 游戏月 = 30 游戏日 = **30 现实秒**，数值详设 §1.6）；
- 结算钩子挂 claim 编排内的独立轻量步（与 `Rumors.tick` 同范式，独立计秒），**每次结算 = 每天骄 2 次标量加法 + 至多 1 次境界进位循环**（循环上限 10 = REALMS 长度）——无掷判、无事件模拟、无玩家字段读写；
- **离线照常推进**（游戏历离线照常流逝，同 §1.6 口径）：回归 catch-up = 按流逝游戏月数**一次性公式补算**（`prog += baseQi × 流逝秒 × aptCoef`，再循环进位境界），不逐月重放、不进玩家离线结算链（`Idle.settle` / 离线收益零触碰）。

### 3.2 境界推进公式（节奏曲线 = REALMS 裸身曲线）

```
每结算：prog += REALMS[realm].baseQi × 30(秒) × aptCoef(× 临时加成 §8.2/§九)
进位：  while (realm < 9 && prog ≥ REALMS[realm+1].need) { prog −= need; realm +1 }
封顶：  realm = 9（真仙）后 prog 停积（溢出丢弃）
```

- **不掷渡劫**（简化裁定，登记）：天骄突破按期望直通——掷 p 只会产生无意义方差与「同代人集体渡劫陨落」的喜剧效果，且天骄渡劫不是玩家叙事；代价是天骄全程**无失败损耗**，该优势已折进 §2.5 到真仙期望的推导（裸曲线连续累积 ≈11.5 天，与典型玩家 13.3 天同带）；
- 境界突破瞬间：进同代榜排名重算（§四）+ 编年史 + 传闻播报（仅**天才档**突破播报，防刷屏，§4.3）；
- **推进完全确定性**：给定资质档，天骄境界-时间曲线无随机——排名变化全部来自玩家自身节奏选择（闭关/历练/渡劫成败），可测可断言（#213）。

### 3.3 战力标量

```
power = REALMS[realm].P × POWER_COEF[资质档]    // 常人 0.95 / 俊杰 1.05 / 天才 1.15
```

- 天骄**不模拟装备/功法/法宝养成**——战力是境界的确定性派生标量（两标量纪律，§1.2 ⏸ 理由④同源）；
- 对照玩家：玩家战力 = (境界基础 + Σ装备) × 乘区（数值详设 §2.2），养成充分时同境界压制天骄、裸装时反被压制——切磋胜负随玩家养成自然翻转（§五）。

### 3.4 事件 flag 边界

- 天骄字段变更的**唯一来源** = 本卷系统（月度推进 / 切磋 / 结仇 / 机缘竞争 / 跨世 ✅ 已落码 `prodigy.js:169-178`+`:503-513`）；天骄不自主产生事件、不自主变更关系——「事件 flag」全部由玩家侧交互写入（`feud` / `lastSparAt` / `boost` 等，§10.2）；
- 天骄之间**不互动**（互不切磋、互不结仇）——同代榜排名变化只来自「玩家 vs 天骄」与「天骄 vs 天骄」的确定性曲线差异（不同资质档曲线天然交叉换位，无需模拟）。

### 5.1 入口与冷却

### 5.2 掷判

```
玩家侧：P = 玩家当前战力 × (1 + U(−0.10, +0.10))
天骄侧：Q = prodigy.power × (1 + U(−0.10, +0.10))
P > Q × 1.01 → 玩家胜；Q > P × 1.01 → 天骄胜；其余 → 平（双方浮动独立掷）
```

- ±10% 随机浮动（`SPAR_JITTER = 0.10`）让「压线局」有悬念、碾压局无冷门——战力差 >22% 时结果确定；
- 切磋**只掷一次判、走独立结算**，不占用奇遇事件通道、不进 pendingChoice 模态（不是三分支抉择事件——切磋是即时对局，胜负直接结算）。

### 5.3 小额赌注（灵石 · Ledger 既有分类）

- 赌注 = `ZONES[min(realm, 9)].stonesPerKill × SPAR_STAKE_K (20)`（realm 取玩家当前境界）——例：筑基 8×20 = **160** 灵石；真仙 15,000×20 = **30 万**（对照 §九.5 终局刷图 ≈540 万/小时 ≈3.3 分钟收入——全程「小额」定位成立）；
- 记账（恒等式 #113 零新增分类）：开局玩家押注记 **`out.event`**（mutate 扣账）；玩家胜返还双倍记 **`in.event`**（净 +stake）；负不返还（净 −stake）；**平局不记账**（押注不扣，省两笔流水）；
- 天骄侧灵石不记账（NPC 非记账主体，同道友赠礼先例）；赌注是切磋唯一经济面——**天骄系统不产生第二套收入曲线**（传闻卷 §八「经济零新增」同纪律）。

### 5.4 胜负后果（bond 与结仇判定）

| 结果 | bond 变化（走 `Bonds.gain` 正向口） | 附加 |
|---|---|---|
| 玩家胜 | 玩家对天骄 **bond +2**（心服） | 编年史 + 日志 |
| 玩家负 | 天骄对玩家 **bond +1**（不打不相识） | 另掷 **30%**（`SPAR_FEUD_P`）**结仇判定**——命中则开启心结事件链（§七），本次 bond +1 照入（结仇在入账后冻结） |
| 平 | 双方 **bond +1**（棋逢对手） | 编年史 + 日志 |

- bond 存入既有 `ws.bonds[pr{n}]`（值域 −20~100 / 只增不减 / gain 判定链沿用，洞府福地卷 §3.2）；
- 胜/负/平累计计数存天骄记录 `wl:[w,l,d]`（详情页战绩展示 + 编年史取数）；
- 对**宿敌**（`feud = true`）切磋照旧可发起（「再打一场」），胜负照常记账与 bond 判定——但 bond 被冻结拒入（§7.2），且胜负**不解除心结**（解除唯二通道见 §7.3），胜宿敌只写编年史「自宿敌手中抢回一胜」。

### 5.5 三档赌注（切磋平衡批 v1.2 修订 · 替代 §5.3 单一赌注）

- 发起时三选一：**轻注 K=10 / 标准 K=20 / 重注 K=50**（`STAKE_K3` 表；赌注 = `ZONES[min(realm,9)].stonesPerKill × K`，realm 取玩家当前境界）；
- 缺省与非法 kind 一律归一 **std**（`normKind`，旧调用签名 `spar(..., pid, now, log)` 零破坏兼容）；
- **重注高风险**：败北结仇率 `SPAR_FEUD_P_HEAVY = 0.40`（轻/标维持 0.30）——高回报伴随高结仇风险，心结 −0.02 渡劫代价是重注的真实成本；
- 押注门槛按档判定（重注不足 poor 拒、不掷不耗 CD）；`SPAR_STAKE_K: 20` 保留为回退参照值（表缺项兜底，零改动）。

### 5.6 强弱差让经济（切磋平衡批 v1.2 核心裁定）

**问题**：天骄推进 = REALMS 裸曲线（玩家数值轴零影响红线），玩家乘区全套成长远快于天骄——中后期 ratio 恒 ≥1.5，
切磋退化为「7 天一次的必胜提款」（净 +stake 无风险单向水流），决策面死亡。

**裁定**：赌注返还与 bond 收益随**浮动前真战力比** `ratio = myP / q` 让差（UI 详情面板透明展示局况徽标）：

| 局况 | 判据 | 胜返还 | 胜 bond | 胜材料率 | 设计意图 |
|---|---|---|---|---|---|
| 碾压局 | ratio ≥ 1.5 | stake × **1.5**（净 +0.5） | **+1**（胜之不武） | 10% | 必胜带收益压制——提款机不划算 |
| 势均力敌 | 1.0 < ratio < 1.5 | stake × 2（净 +1，原口径） | +2（心服） | 10% | 标准带维持原经济 |
| 问强 | ratio ≤ **1.0** | stake × **3**（净 +2） | **+3**（心折深服） | **15%** | 挑战上位者高回报——恢复决策张力 |

- **brave 阈值 1.0 裁定（实施批修订，初稿 0.8 作废）**：±10% 抖动下玩家胜判定带 = ratio ∈ (0.818, 1.222)——
  若 brave 取 0.8，则「问强 ∧ 胜」= 空集、×3 返还与 bond+3 永不发生（纯摆设）；取 1.0 使 (0.818, 1.0]
  「对手更强仍可胜」段有真悬念真回报，ratio ≤ 0.818 的必败挑战由玩家自担（选打无望局输钱合理）；
- 碾压带 (≥1.5) 完全覆盖必胜带 (>1.222)——「必胜局必低收益」无漏网；
- **Ledger 记账口径零新增分类**：非平局 = `out.event_loss`(stake) 一笔；胜 = `in.event`(ret) 一笔（ret = 让差后实际返还，
  平局两笔全免）——恒等式 #113 `100 + Σin − Σout === stones` 三局零漂移（#232 实证）；
- 平局/败北路径让差零介入（败 = 净 −stake 不分档；平 = 不记账）；bond 败 +1/平 +1 原口径不变。
