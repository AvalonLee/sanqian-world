## 一、阵营袭击（对称事件族）

正道数值（karma 正档）越高 ⇒ 越易被**魔道高手**袭击；魔道（karma 负档）越深 ⇒ 越易被**正道高手**袭击。袭击者人选从 **道友（`D.COMPANIONS`）/ 道侣（`ws.spouse`）/ 天骄（`ws.prodigies`）** 三池任取，取到的人必须是「在册且未绝交/未死亡」者；名册为空则该族静默不触发（不留点不开的按钮、不编假人）。

- 触发口：挂在既有在线奇遇时钟旁的新分支（与 `rumorClock` / `eventClock` 同纪律），**离线不掷、时钟冻结**。
- 抉择：`迎战` / `避战` / `认输` 三选，**必须手动**，限时；超时默认 **迎战**。
- 载体：复用 `ws.pendingChoice` 模态与 `resolveBranch` 结算口，不新开抉择通道。
- 结果：迎战胜 = 收益（按 §四 递增带）；迎战败 = 道伤（§二）；避战 = 无收益无惩罚 + 该敌手记「避让一次」；认输 = 交灵石/材料买平安，走既有 `out.shop`? 不——走 `out.event`，且**先判后扣**（第廿六批纪律）。
- 身份指纹：`pendingChoice` 带 `{attackerId, expireAt, sig}`；结算时回查敌手仍在册且 `sig` 相符，不符 ⇒ `stale` 拒单（弹窗期间换架那族的同型缺陷，必须挡住）。

## 二、道伤接口（已存在的口，不新建伤势系统）

失败惩罚一律落在寿元批已立的 `ws.daoShang` 槽（`cap 15 / warn 8 / cleanse 2 / healPerYear 0.01`，判死认 ceil）。袭击/寻仇的「较高道伤」= 世界包新增一个 `daoHit` 调用点（带 cause 区分），**不许**直接写 `ws.daoShang`，也不许新开第二种伤势字段。

## 三、袭杀天骄 + 族中寻仇

- 天骄页新增「袭杀」入口（`Prodigy.ambush`）。与既有「斩杀」的关系：**同一身死判定链**，袭杀只是新的主动入口，不复制一套「天骄死亡」写口。
- 计数挂在**天骄条目自身**（`p.ambushed`），第 3 次 ⇒ 判定该天骄死亡 ⇒ 播种「族中高手寻仇」事件。⚠️ 容量红线：**不得**新开 `ws.ambushLog` 之类随名录线性增长的容器（本仓 58 道友 / 30 天骄吃过两次）。
- 寻仇敌手境界 = `min(主角境界 + 1, 9)`；到顶即同境，词表与屏上如实写「同境」，不做隐性削弱。
- 主角**只能迎战**（无避战/认输选项）。胜 ⇒ 事件进入 **10 分钟**冷却，冷却后继续触发下一轮（奖励递增）；败 ⇒ 吃较高道伤，**寻仇链判定结束**，不进冷却。
- 冷却与时钟：`expireAt` 与 10min 冷却一律走**在线时钟**（离线冻结不推进、不补算），避免「睡一觉被仇家打死」。

## 四、收益递增的顶

连胜计数**派生不落库**；收益倍率带硬顶（推荐 ×3 封顶）。灵石一律 `SQ.Ledger.note(ws,'in','event')`（**#113 零新增分类**红线），装备/材料走既有掉落口。递增曲线与顶值写在 `data.js` 新表里，判据口与界面口只取表。
