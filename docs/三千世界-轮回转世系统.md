## 二、遗泽点体系（meta 层唯一事实源）

### 2.1 定义与恒等式

- **遗泽点（legacy，存档字段 `meta.karma`）**：非负整数，meta 层唯一通货，只用于遗泽商店（§三）消费；
- ⚠️ **勿混注记（最高优先级）**：`meta.karma`（遗泽点）与 `ws.karma`（善恶值，KARMA_CLAMP ±1000，项目设计文档 §六）**同名字段、不同层、不同语义、零关联**——玩家可见文案中遗泽点一律称「遗泽」，善恶值一律称「业力」；词表族分属 `legacy.*` 与既有 `karma.*`，日志 reason 分属两套枚举，实施批 audit 加同名混用扫描；
- **收支恒等式（本卷独立定义，不入 Ledger）**：

```
meta.karma（余额） = Σ earnedKeys{}（全世首次得分，只增） − Σ spent{}（商店购买，只增）
```

- **遗泽不进 Ledger**：Ledger = 现世灵石记账（`ws.ledger`），恒等式 #113 与九路分类**零改动**——遗泽收支不产生任何 Ledger 流水；遗泽账本 = `meta.karmaLog[]`（近 20 条 `{ts, delta, reason, balance}` 环形缓冲），reason 走 `legacy.log.*` 词表枚举；
- **只计首次、跨世不重复刷**：每笔得分挂**幂等键**入 `meta.earnedKeys{}`（键 → 分值），同键二次达成零入账；档级项（境界 / 职位 / 榜位）按「历史最高档差额补分」——首世化神得 90，次世大乘补 360−90=270，三世再化神零分。

### 8.4 容量预算（meta 层 · ~~50KB~~ → **64KB** 红线，v1.4 重核）

- **⚠️ 红线重核裁定（v1.4 · 2026-10-05 存档容量防线批 · 50KB → 64KB / 触发线 45KB → 56KB）**：本节标题与下表「meta 层 · 50KB 红线」及「红线核算」行的 **50KB 口径自本批起作废**，现行 = **红线 64KB（65536B）/ 触发线 56KB（57344B）**。三条实测取证（**非放宽纪律**）：
  - **① 50KB 无任何外部依据**——平台扩展开发指南全文无存储配额条目；`xhub.storage` 按扩展隔离持久化、只要求 value 可 JSON 序列化；平台实际落盘 `.storage.json` 就是按 key 直写的普通 JSON 文件，**该文件本身实测 53942B 已 > 旧红线**（即旧红线连自己的落盘容器都装不下）。
  - **② 同一套存储接口上的兄弟键已在跑 256KB 预算**——日志独立存档键 `sanqian-logs-v1`（2026-10-05 日志存档批定）字节预算 **256KB**，即平台侧单键体量早就不止 50KB 一个量级。
