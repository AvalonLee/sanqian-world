## 一、四柱定位（引擎视角）

「财侣法地」是修仙类放置游戏的经典成长四轴。引擎层映射：

| 柱 | 引擎承载 | 状态 |
|---|---|---|
| 财（资源） | 灵石经济 + G6 商店 + G4 炼化 + 事件收益 | 已有，补总账可视化（`ledger`） |
| 侣（护持） | **G14 护法结缘**：好感度名录 + 护法位 + 个体助力 | 🆕 本卷定义 |
| 法（方向） | G5 功法（54 部 + 独占通道） | 已有，形式化「主修」 |
| 地（效率） | **G13 洞天福地**：洞府驻留 + 独立乘区 | 🆕 本卷定义 |

设计公理：**财是底气，法是方向，地是效率，侣是护持**——四柱各管一个维度，互不越界：地不产灵石（财）、侣不提基础产出（地）、法不送好感（侣）。跨柱联动只走已登记的乘区与加项。

## 二、G13 洞天福地（地）

### 2.1 核心循环

```
灵石 / 境界 / 秘境首通 → 获得洞府入驻资格 → 择一驻留 → caveMult 独立乘区 + 签名效果
→ 产出效率提升 → 更快换境界 → 解锁更高阶福地
```

### 2.2 数据契约（世界包提供 `caves` 表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 全局唯一 |
| `nameKey` | string | 词表 `cave.{id}.name` |
| `descKey` | string | 词表 `cave.{id}.desc`（灵气浓度叙事，30~60 字） |
| `mult` | number | caveMult，1.00~1.35（引擎硬顶 1.40，世界包不得超） |
| `reqs` | object | `{ realmMin?, stonesCost?, zoneCleared? }`——入驻资格三要素（可组合） |
| `signature` | object/null | `{ hook, field, value }`——签名效果，挂点限既有白名单（工程规范 §2.2）+ §2.5 新增两项 |

### 2.3 驻留规则

- **同时只能驻留一处**；入驻即生效，切换有 **游戏时间 1 年冷却**（360 游戏日 = 360 现实秒；走查批 v2.8 口径澄清：冷却统一为游戏 1 年，非现实一年）；
- caveMult 对**在线产出与离线结算同时生效**（「闭关」叙事 = 离线，洞府是闭关质量的第一变量）；
- 签名效果只在驻留期间生效，搬离即失——高阶福地各有侧重（冲离线 / 冲渡劫 / 冲产出），**择洞如择路**，是切换策略的核心张力；
- 资格校验发生在入驻时（境界 / 首通 / 灵石一次付清）；灵石扣除走 `mutate` 并记入 `ledger.out.cave`；
- 初始洞府免费（caveMult 1.00，无签名），保证「地」柱从创角起就可见、可成长。

### 2.4 数值纪律（硬约束）

1. **caveMult 是独立乘区**：产出公式末端 `× caveMult`，**不进 qiRate 加算池**——防止击穿功法六槽乘区审计上限（工程规范 #105）；
2. 签名效果走**既有乘区加算**（offlineEff / combatPower / artsSpeed / tribBonus 加项），来源登记「洞府签名」（数值详设 §8.2）；同一时刻只有一处签名生效（驻留唯一性天然防叠加）；
3. 全表 mult 预算：初阶 1.00 → 顶阶 ≤1.35，与阵营倍率（0.75~1.5）同数量级——「地」是第四条大轴，量级配得上，但不得反超阵营轴；
4. **验收带影响**：G13 上线（代码批 2）后必须重跑数值详设 §6.4.1——~~预判典型锚 13.3 → ≈11.5 天（顶阶洞府期），验收带按新锚重定基线~~ **批 2 实测结案（v1.3）**：满驻提速系数 **0.744**，锚 13.30 → **9.90 天**（预判 11.5 低估了「后三层占总时长 ~85% 且已满驻顶格」的权重）；**比值结构（阵营间）实测完全不变**（caveMult 是独立乘区、对九画像同比生效，漂移 <0.005）⇒ 验收带**不需重定基线**，仍以无洞府锚 13.3 为分母。膨胀线：典型画像满驻全部 ≥5 天（最低魔浅 7.12 ✅），速通魔道 4.39 天破线但按 §6.4.1 观察项② 属带外单列——**本表 mult 维持 1.35 不动**，实测证据与两级杠杆失效分析见数值详设 §九.11；
5. 灵石售价即「财换地」的跨柱水槽：总投入 ≈ 552 万灵石（修仙首批表），对照 zone8 刷图收入 ≈ 17 小时——是长线目标而非硬门槛。

### 2.5 挂点增量

世界包 `specialHooks` 白名单（工程规范 §2.2，现 15 项）**新增 2 项**：

| 挂点 | 职责 |
|---|---|
| `on_cave_enter` | 入驻洞府时触发（日志 / 一次性演出） |
| `on_cave_mult` | caveMult 结算读取点（引擎唯一读取处，防旁路） |

## 三、G14 护法结缘（侣）

### 3.1 核心循环

```
奇遇抉择（指定分支）→ bond 好感 → 好感度升档 → 护法位（渡劫 p 加项）+ 个体助力（既有乘区小加成）
→ 「修仙路上有人替你守夜」的叙事兑现
```

### 3.2 好感度模型

- 存档：`worlds.{id}.bonds = { npcId: affinity }`，affinity 整数 −20~100（势力批 v2.4 值域扩展；−20~−2 = 厌恶区间），**只增不减**纪律不变（绝交锁例外，见 §3.6；**v1.10 校正**：该纪律的准确含义与本批新增的四态/两负向写口见下方两条）；
  - **（势力批 v2.4 勘误）**值域扩展为 **−20~100**：−20~−2 = 厌恶（势力敌对联动，负好感无档位无助力，可被后续事件拉回正区间）；**绝交锁哨兵 −1 → −99**（normalize 自动迁移旧档）；好感仍只增，唯二例外 = 势力加入联动（一次性）与绝交/心结锁；
- 档位（世界包可改名，阈值引擎固定）：

| 3 | 70~99 | 生死之交 | 个体助力 ×3 档；**可任护法位**（guardianBonus +0.03） |

### 3.2a 好感三渠道（v1.11 · 批 B ⑤ 好感度新渠道批 2026-10-06）

**起因（用户诉求⑤）**：「目前道友系统的好感度获取方式比较局限」。

**取证结论（先量后改）**：§3.2 旧口径称正向写口「两条」，**与代码不符**——落码前实测已有 **八条**（事件 `bond` 收益 / 同道相吸 / 势力入门联动 / 势力战胜利同门 / 天骄切磋赌注 / 天骄致歉解冻 / 天道旨意情缘牵引 / 跨世之缘创角）。但真正的问题不在条数，而在**结构**：这八条里**玩家可主动、可重复、可指向指定对象**的一条都没有——事件靠抽、势力战与切磋靠系统触发、名号与创角一世各一次。玩家想让某位具体道友对自己改观，**没有任何一个按钮可按**。故本批不铺量，补三条**主动渠道**。

|---|---|---|---|---|---|---|
| **A 拜访论道** | `Bonds.visit(ws, pack, D, npcId, now, log)` | 玩家点名任一道友（**含未识与厌恶者**） | 零 | 全局单冷却 `BOND_VISIT_CD_MS` **300000ms**（🆕 **v1.12 用户裁定 2026-10-09 由 1h 改 5 分钟现实** = 300 游戏日 ≈ 0.83 游戏年；锚仍是现实 ms 时间戳，与 `FACTION_SUPPLY_CD_MS` **同口径不同值**） | 按当前档位递减 `BOND_VISIT_BY_TIER` **[3,3,2,1,0]**（索引 = `tierOf` 结果 0~4）；同向另加 `BOND_VISIT_ALIGN_BONUS` **1** | `ws.bondVisitAt`（单锚 int） |
| **B 赠丹** | `Bonds.giftPill(ws, pack, D, npcId, pillKey, now, log)`（🔧 issue #4 起 profile 形参随日限一并退役） | 玩家点名道友 + 择丹 | **自有丹药** 1 颗（`ws.alchemy.pills` 扣 1） | 🔧 **无日限**（GitHub issue #4 · 2026-10-14 撤销 `BOND_GIFT_DAILY` 3/游戏日；原行写「`BOND_GIFT_DAILY` **3** / 游戏日（`alchemy.giftDay`，与丹毒 `pillDay` 同形同口径）」——该日限因 `gameDayOf` 的 1 游戏日 = 1 现实秒而永不生效，屏上恒显「今日 1/3」，属说谎的计数器）；真实节流 = 丹药库存与炼制耗时 | 按丹方 tier `BOND_GIFT_BY_TIER` **黄 4 / 玄 6 / 地 9 / 天 14**；丹纹版（key 尾 `_rw`）× `BOND_GIFT_RUNE_MULT` **1.5** 取整 | 🔧 零落盘字段（`ws.alchemy.giftDay` 已随 issue #4 退役；原登记见本卷 §五 同字段行） |

**八条设计口径（逐条都是防坑裁定，改动前必读）**：

1. **「侣不可交易」底线守住的方式**：§3.2 明定好感「均不走商店购买」，本批**一字未破**——渠道 A/C 零消耗，渠道 B 送的是**玩家自己炼出来的丹**（灵石从头到尾不经手，`ws.stones` 与 `ws.ledger` 前后逐字节相同，断言 #257(l) 钉死）。区别在于「以丹会友」是人情往来，「买好感」是货殖；前者是世界观允许的，后者不是。
2. **渠道 B 顺带解决一个既有结构问题**：丹药此前只有「自服」**一个出口**（`drinkPill`），整条炼丹产线（材料 30 种 / 丹方 11 份（2026-10-14 勘正，原 10 份漏跟洗髓批） / 双轨熟练度）没有社交侧水槽。赠丹给它开了第二个出口，且**不改炼丹卷任何数值**——只在消费侧多一个去处。
3. **双特例丹不可赠**：`ap_pozhang`（破障）/ `ap_zhenjie`（镇劫）带 `once` 标记、「每境界限 1」，那是自己的底牌；外移会让「每境界限 1」的语义归属混乱。引擎侧拒（reason `once`）、视图侧**根本不列进 chips**，两层同口径。
4. **冷却 / 日限只在真入账后推进**：满档、绝交锁、心结锁、名录外四类被拒**一律不推进** `ws.bondVisitAt`、**不扣丹、不占日限**（校验链全串行，扣丹与日限计数放在 `gain` 成功之后）。玩家点错不付代价。
5. **未识者可拜访、可赠丹 = 本批最大体验增量**：此前「结识」的唯一途径是抽到该人的出身事件，58 人的池子在一世里抽不全，多数玩家一辈子只认识十几个人。渠道 A 的 tier 0 档 +3 让玩家**主动去认识人**；厌恶区间（−20~−2）同吃 tier 0 档，于是「厌恶 → 相识」第一次有了**可主动的修复通道**（此前只能等事件）。
6. **`met` 按结果判、不按入口判**：`visit` 返回的 `met` = `tierBefore < 1 && tierAfter >= 1`。厌恶 −5 拜访一次到 −2 仍是 tier 0，此时若按入口判 `met=true`，视图会弹「由此结识 X」而名录格仍是「？」剪影 = **假反馈**。断言 #257(b) 三例钉死。
7. **同向加成只对已相识生效**：`align`（阵营）属身份信息，未识者在名录里是「？」剪影。若未识拜访也给 +1，玩家会经「+4 而非 +3」把对方阵营**反推出来**。故引擎与视图两侧都按 `tier >= 1` 门控，未识恒 +3。断言 #257(c) + probe-bondact「身份零泄漏」双向钉死。
8. **视图标注的增量 === 引擎实发的增量**：按钮上标多少、结算就加多少，绝不允许「标 +14 实给 +1」。赠丹 chips 标的是 `min(名义值, 距满档余量)`；接近满档时 `gain` 自带 clamp，返回值 `gain` 一律是**实际增量**（`nominal` 另存名义值供对账）。probe-bondact 第 10 组把四档拜访与四阶赠丹**逐一对表引擎实跑**，任何一侧漂了就红。

**🔧 屏上用词口径（第廿二批 2026-10-12 · 用户令「道友页顶部道侣弹窗里还出现『提亲』字样，都改成『双修』」）**：词表 `bond.propose.*` / `bond.spouse.pick.*` / `bond.spousecond.*` 等**值**已全线改口为「双修」（含那颗主按钮「双修 ♡」与 CONFIRM 标题「双 修」），而**键名、`data-act="spousePickPropose"` / `propose` 引擎动作名、冷却字段一律不改**——改键名会牵动存档与全部引用点，收益不抵风险。故本卷与其余各卷正文里的「提亲」= 同一动作的旧称，读作「双修」即可（历史版本志按体例不改写）。

**⚠️ 日限口径警示（易误读）**：渠道 B 的「每游戏日 3 次」走既有 `Alchemy.gameDayOf`，而 **1 游戏日 = 1 现实秒**（§1.6 同源）——与丹毒日限 `PILL_DAILY_CAP` 完全同口径。所以这个「日限」**不是 24 小时限**，它只防单帧连点；真正的节流是**丹药库存与炼制耗时**（天阶丹要境界 9 + 六样稀有材料 + 炼制等待）。读表时勿把「日限 3」当成每日三次。

### 3.6 缘尽四态 · 双门槛 · 赎回 · 同道相吸（v1.10 全面重写）

> **v1.10 缘尽收敛批（2026-10-06）**：用户诉求「缘尽状态太容易触发了，玩到后期一大半的道友都是这个状态，体验不好」，拍板**砍触发面 + 给挽回通道 + 加条件门槛**三项全要。本节由原「绝交锁（分支后果的长尾）」三条扩写为四态模型；原口径中「好感永久锁定为 0」的描述与实现（−99 哨兵）不符，一并校正。

#### 3.6.1 魔道分支的四态取值域

指定事件的**魔道分支**可对某位道友产生四种后果之一（`bondDrain` / `bondLock` 在同一分支**互斥**，同分支只出一种）：

| 态 | DSL | 好感结果 | 可逆性 | 视图角标 |
|---|---|---|---|---|
| 无反应 | — | 0 | — | — |
| **情谊有裂** | `bondDrain: {npcId}` | 大跌（`round(\|分支 karma\| × 1.2)`，clamp `[6, 25]`）走 `lose` | **可逆**——后续事件可拉回正区间 | 「情谊有裂」 |
| **真绝交锁** | `bondLock: {npcId}` | `bonds[npcId] = -99`（哨兵值，势力批 v2.4 由 −1 迁移——值域扩为 −20~100 后 −20~−2 为厌恶区间，−1 不再可用作哨兵；旧档 normalize 自动迁移） | **本世不可逆**，可跨世以遗泽赎回（§3.6.3） | 「绝缘」暗纹 |
| 心结锁 | `bondScar`（§3.8 炉鼎采补） | 好感锁死不入账 | 本世不可逆 | 心结标记 |

图鉴/浮层对 −99 显示「缘尽」。绝交锁与情谊有裂条目都必须在事件文案里有**清晰预告**，不做暗坑。

#### 3.6.2 双门槛与自动降级（砍触发面 + 加条件门槛）

`Bonds.lock(ws, npcId, gate)` 的 `gate = { karma, D }` 启用**两道门槛**，两者同时成立才真锁：

| 门槛 | 常量 | 默认 | 语义 |
|---|---|---|---|
| ① 玩家够黑 | `BOND_LOCK_KARMA_MAX` | **−400** | 玩家 karma ≤ −400（凶名邪修及以上）——素人行恶不至「恩断义绝」，对方顶多失望 |
| ② 交情够深 | `BOND_LOCK_BOND_MIN` | **30** | 该道友当前好感 ≥ 30（知交及以上）——未识之人谈不上「缘尽」，也无从「绝交」 |

- **不合条 → 自动降级为情谊有裂**：`applyEffects` 捕获 `{ok:false, reason:'karma'|'bond'}` 后改走 `Bonds.drainFor`，把 `bondLock` 效果从结算账里删掉、写入 `bondDrain`。玩家看到的是「情谊有裂」而非「缘尽」，且**可由后续事件拉回**。
- `gate` 省略 = **无条件锁**（保留给既有旁路与断言直测，后向兼容不改签名）。
- `gateKarma` 由 `resolveBranch` 传入**投影值**（`(ws.karma||0) + 分支 karma`）——判门槛时 `ws.karma` 还是上一次重算的缓存，用结算前的旧值会把「这一分支正好把玩家推过 −400」的情形误判为不合条。
- **重判结果**（道友池卷 §二 = 内容侧唯一事实源）：全池 **26 事件 / 27 处**锁 → **保留真锁 6 事件**（判据 = 分支 |karma| ≥ 20 的真重背叛）+ **转情谊有裂 20 事件 / 21 处**。

#### 3.6.3 缘尽赎回（给挽回通道 · 唯一解锁写口）

`Bonds.redeem(ws, pack, D, meta, npcId, now)` —— 以**遗泽**（meta 跨世通货）赎回一位缘尽道友。

| 项 | 口径 |
|---|---|
| 代价 | `BOND_REDEEM_COST` = **30 遗泽**，走 `Legacy.spend(meta, 'redeem.'+npcId, cost, now)` 唯一支出口 |
| 落点 | `bonds[npcId] = BOND_REDEEM_AFF` = **10**（档 1 相识，不直接复原满档——赎回来的是「重新认识的机会」） |

- **对象**：`category:'spouse'` 的道侣候选；**条件**：好感满档（affinity = 100）+ 玩家主动「提亲」+ CONFIRM 模态明示三形态与代价；
- **形态由结缘瞬间 karma 档位决定**，存档 `worlds.{id}.spouse = { npcId, form, since }`（null = 未结缘；**同时仅一位**）：

| form | 名称 | 结缘/维持条件 | 效果（独立来源「道友双修」，§8.2 登记） | 代价 |
|---|---|---|---|---|
| `yinyang` | 阴阳双修（正道） | karma ≥ +200；跌破即解除，7 天后可重新提亲 | qiRate +6%、offlineEff +10%、心魔类 debuff −25% | 无 |
| `huzhu` | 互助双修（左道） | −200 < karma < +200 | qiRate +10% | 无 |
| `luding` | 炉鼎采补（魔道） | karma ≤ −200 | qiRate +18% | ①结缘一次性 karmaEventScore −20 入账；②双修期间该道友个体助力归零；③karma 回升 > −200 即解除，且该道友好感锁死当前值、**永不再任护法位** |

- **与护法位的关系**：双修道侣若恰为好感最高者，照常占护法位（guardianBonus 与双修效果并行，不冲突）；炉鼎采补解除后的心结锁只封护法位，好感数值本身不变（只增不减纪律的唯一例外仍是绝交锁 −99）；
- **性别与种族**：双修不限性别（道侣结的是心）——`profile.gender`（默认 'male'）与 `profile.race`（默认 'human'）为**预留字段**，本期创角不提供选择（工程规范 §3.1 v2.2 登记），未来开放后本机制自动兼容；
- **内容红线（引擎级纪律）**：双修文案一律写意留白，无任何亲密描写；炉鼎形态的黑暗感只靠代价机制表达；新世界转译示例：古武 = 侠侣双修 / 政治联姻 / 采补邪功，魔法 = 灵魂契约 / 塔灵共鸣，均走词表。
- **实施口径（v1.4 · 批 3 定稿）**：
  1. **互助双修不自动解除**——表中「−200 < karma < +200」是结缘瞬间的形态判定口径；「无维持条件最稳/最自由」（四柱卷 §5.3）即此后 karma 任意漂移均不触发解除。阴阳（跌破 +200）与炉鼎（回升 −200）才有自动解除；
  2. **心结锁三义**（炉鼎解除后 `scars[npcId]`）：① 永不再任护法位；② 好感锁死当前值（后续 bond 收益拒入账，与绝交锁 −99 的区别是数值保留、身份保留）；③ **不可再提亲**——「缘锁」封的是这段缘，防 karma 摆荡刷炉鼎 +18% 的退化玩法；其余候选不受影响；
  3. **提亲冷却**：阴阳双修自动解除 → `spouseCdUntil = 解除时刻 + 7 天`（全局，冷却内任何候选不可提亲）；炉鼎解除走心结锁不设冷却；
  4. **解除叙事消费通道**：解除发生在 karma 重算点（事件结算 / claim 漂移），视图不在场——引擎写 `spouseLog = {npcId, form, reason:'karma'|'redemption', at}`，视图会话内按 `at` 键控消费一次（与出关呈报同模式），炉鼎解除附加「缘锁」提示行。

- 只登记**灵石**流水（修为流量已有 total 字段）；分类粒度到系统级即可，不做逐笔明细（存档体积纪律：<50KB）；
