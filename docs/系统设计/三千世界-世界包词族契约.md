## 一、机制：三级回落取词

所有面向玩家的文案一律走 `SQ.t(key, vars, worldId)`，取值按**三级回落**：

```
世界分卷 SQ.LEX[worldId][key]  →  common[key]  →  key 本身
```

- **世界分卷**：`assets/worlds/<id>/lexicon.js` 等分卷注册进 `SQ.LEX[<id>]`，只放**该世界专属**文案；
- **common**：`assets/lexicon.js` 的 `common`，只放**跨世界通用**文案（按钮、确认框、数字格式、系统页）；
- **key 本身**：两者皆缺时原样输出 key，让遗漏在界面上**肉眼可见**（不静默空白）。

`worldId` 由调用方给出：视图层用 `wid()`（读 `state.profile.worldId`）；系统层用 `pack.worldId`。
**只要文案 key 走本取词器，世界包就天然可覆写**——这是「换世界即换文案」的全部底层机制。

## 二、键族契约（可覆写清单）

世界分卷按下列键族划分职责。机读镜像 = `SQ.LEX_CONTRACT`。

### 2.1 must —— 必覆写族（世界的「系统身份」）

> **规则**：每个 `status: 'live'` 世界分卷**至少各有一条**该前缀的 key。缺任一族 = 世界包未完成，审计 **C1** 报错。

| 族前缀 | 覆盖内容 | 修仙世界示例 |
|---|---|---|
| `resource.` | 主资源 / 货币 / 战力名 | 修为 · 灵石 · 战力 |
| `realm.` | 阶位体系名与各阶名 | 境界 · 练气…真仙 |
| `idle.` | 挂机动作与状态 | 打坐 · 产出 {n}/秒 · 下一境界 |
| `combat.` | 战斗区域体系与各区名 | 秘境 · 青云试炼地…界外古道 |
| `gear.` | 体系名（各世界化：修仙「法器」/ 古武「兵甲」）/ 槽位 / 品阶 | 法器 · 兵刃… · 凡品…仙品 |
| `skill.` | 技能体系名与滋养 | 功法 · 滋养精/气/神 |
| `shop.` | 商店体系名与丹药 | 坊市 · 黑市 · 聚气丹… |
| `event.` | 事件体系名与道心增减 | 奇遇 |
| `tribulation.` | 突破 / 试炼体系 | 渡劫 · 天劫将至 |
| `karma.` | 善恶体系与档位名 | 善恶 · 正道光环/左道/魔道气息 |
| `attr.` | 属性名与释义 | 精 / 气 / 神 |
| `world.` | 世界卡显示名与关键词标签 | `world.xiuxian.name` / `world.tag.*` |
| `tab.` | **菜单描述**（游戏页 Tab 名） | 修行 · 奇遇 |

> **`tab.` 族特别说明**：游戏页 Tab 名由**世界分卷拥有**（common 不再兜底 `tab.idle`/`tab.event`）；
> 系统页 Tab（`tab.log` 日志 / `tab.settings` 设置）与世界无关，留在 common。

### 2.2 may —— 建议覆写族（世界可选体系）

> **规则**：世界启用该系统则覆写；未启用可整族缺失（回落 common 或该系统不出现）。审计不强制。

| 族前缀 | 覆盖内容 |
|---|---|
| `cave.` | 洞府体系（G13） |
| `bond.` | 道友体系（G14） |
| `treasure.` | 法宝体系（G15） |
| `creation.` | 创角流程文案（缺则回落 common 通用创角词） |
| `talent.` | 天赋名与字段标签（`talent.{id}.name` / `talent.field.*`） |
| `log.` | 世界专属日志模板（`log.cave.enter` 等） |

### 2.3 forbid —— 禁止覆写族（跨世界通用文案）

> **规则**：世界分卷**不得**出现该前缀的 key。通用文案只留 common，防止世界之间漂移。审计 **C2** 报错。

| 族前缀 | 内容 |
|---|---|
| `ui.` | 通用按钮 / 确认框 / 数字格式 |
| `app.` | 应用名 |
| `world.status.` | 世界状态角标（首发 / 混沌） |
| `settings.` | 设置页（系统级，非世界内容） |

## 三、落地示例：修仙世界 → 假设的战争世界

设想下一个世界包 `war`（战争世界）。引擎、系统、存档字段**零改动**，只新增 `assets/worlds/war/lexicon.js` 覆写 must 族，界面即整体换皮：

| key | 修仙（xiuxian） | 战争（war，假设） |
|---|---|---|
| `tab.idle` | 修行 | **战争** |
| `tab.event` | 奇遇 | **遭遇** |
| `idle.action` | 打坐 | **备战** |
| `resource.primary` | 修为 | **士气** |
| `resource.currency` | 灵石 | **军饷** |
| `realm.system` | 境界 | **军衔** |
| `realm.0`…`realm.9` | 练气…真仙 | 列兵…元帅 |
| `combat.system` | 秘境 | **战场** |
| `tribulation.system` | 渡劫 | **决战** |
| `skill.system` | 功法 | **战术** |
| `shop.system` | 坊市 | **军市** |
| `karma.system` | 善恶 | **忠奸** |

> 引擎侧读的是 `SQ.t('tab.idle', null, worldId)` / `SQ.t('combat.system', null, wid)` 这类**同一批 key**，
> 世界包换一份词表，界面文案即随 `profile.worldId` 切换——这正是本契约要保住的「预留」。

> **注（与项目最新状态对齐）**：上表 `war`（战争世界）是**为演示机制而设的假设世界**，非项目登记条目。项目内**真实登记**的第二世界是 `guwu`（**古武军势**，`status: coming`，路线图 **P6**）；其**权威术语**见 [`古武军势/世界设定与专属系统.md`](./古武军势/世界设定与专属系统.md) §二 与主设计 §3.3 矩阵——主资源 **战意**（非「士气」）/ 货币 **军功** / 阶位 **军衔** / 突破 **晋衔** / 挂机动作 **操练** / 战斗区域 **战场** / 技能 **武学** / 商店 **军需处** / 随机事件 **战报** / 善恶 → **侠名**。示例中的「士气 / 军饷 / 决战 / 战术 / 军市 / 忠奸」仅作机制演示，**勿与 guwu 实际用词混用**。

## 四、新增世界包检查清单

1. `assets/worlds/registry.js` 增条目：`id` / `displayNameKey` / `status` / `nameParts` / `tagsKeys`；
2. `assets/worlds/<id>/lexicon.js`：按 **must 族逐条覆写**（13 族，见 §2.1）；
3. 按需覆写 **may 族**（cave/bond/treasure/creation/talent/log）；
4. **不得**出现 **forbid 族** key（通用文案只留 common）；
5. `world.{id}.name` + `world.tag.*` 入分卷（世界卡显示名与标签）；
6. `pack.lexicon` 与世界分卷**共享同一对象引用**（工程规范 §2.2）；
7. 跑 `node .tests/audit.cjs`：C1（must 族覆盖）与 C2（forbid 零命中）必须全绿；
8. 若世界启用专属系统（善恶 / 渡劫 / 洞府 / 道友 / 法宝），其数据表 key 一并入分卷并过 A2 key 对账。
