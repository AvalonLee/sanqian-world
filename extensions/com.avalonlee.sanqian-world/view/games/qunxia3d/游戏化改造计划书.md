## 一、现状盘点（差距即清单）

**三维原型已有**（可视化壳）：真实地理世界图（30 地界/长城/江河湖海/山系）、30 张特色本境沙盘（210 格台 + 八类格景 + 设定卡地貌）、行脚演示、钻入双层、纸面 HUD 骨架。**零游戏逻辑**。

**原版游戏系统**（源规格十节）：创角向导（出身/天赋/誓言/命格）｜旬时间机（advanceTime :3281）｜玩家状态 state（:2906，单 JSON 可整体序列化）｜八格动作中枢（collectTileActions :4859）｜**三招对决战斗引擎**（startDuel :7152 → playDuelCard :7427 → finishDuel :7661）｜36 案世界事件全生命周期（排期→传闻→赴会三档→余波→写回）｜名宿 12 人（把酒/切磋/授艺/三幕传记）｜五抽屉（武学/门派/行囊/隐庐/名册）｜行商走镖传世秘境｜终局六道途+轮回碑林｜BGM 五曲合成器｜P4 五大扩展（市井/配角/朝廷/情感/立号，约 2600 行）。

**关键迁移优势**（源规格 §10 结论）：核心逻辑全是**纯函数**（advanceTime/playDuelCard/finishDuel/collectTileActions/attendEvent），对 DOM 的依赖集中在 render* 与弹窗；`state` 单一 JSON；与扩展主壳契约只有两个 localStorage 键 + gen 世代比对。**逻辑可整体复算迁移，表现层重建。**

## 二、成品定义（什么叫「可游玩的成品」）

一条完整可玩的循环：

> 创角（出身+命格+誓言）→ 世界图行脚（徒步/快马/途中奇遇）→ 进本境 → 七格交互（饮酒回气/揭榜悬赏/铸炉淬炼/拜师学艺/灵脉吐纳/秘境探幽/名胜寻幽）→ **三招对决**（悬赏要犯/演武/名宿切磋/宗门闯阵/世界事件赴会）→ 旬推进（36 旬）→ 36 案世界事件逐旬上演（当场戏三档：观/入/领）→ 武学研习境界突破 → 36 旬终 → 六道途终局结算 → 轮回碑林（二周目遗泽）。

**MVP 验收线**：不读攻略的玩家能从创角玩到任意一个终局，全程无断链、数值与原版同规则（对表单逐条核验）、存档可续。

**四条铁律**：
1. **逻辑/表现分离**：core+systems 禁 import THREE/DOM；3D 与 DOM 面板只读 state 调系统函数。保住原版「逻辑可 headless 复算」的性质。
2. **数据抽取脚本化**：`game/scripts/extract-*.cjs` 从 game.html/wuxia/index.js 按行段切表（正则+括号配平），可重跑、带源行号注释——禁手抄数据。
3. **数值对表**：每迁一个纯函数，建对表用例（同输入 → 原版值 vs 新版值 逐字段相等），收进 `game/tests/table-check.cjs`。
4. **存档新键**：`shanqian3d_save_v1`（字段命名与原 state 对齐便于对照）；保留读 `qunxia-payload-v1` / 写 `qunxia-result-queue-v1` 的主壳契约与 `worldGen` 对账（将来并回 x-hub 零改造）。

## 八、新知沉淀（迁移实测出的经验，随批续写）

**册273（M0）**：
1. **抽取器配平不能手写扫描器**——字符串/注释/模板串/正则四态状态机在 game.html 的 9.36MB 语料上必失配（实测五张表切不准）。现行方案 = **vm.Script 编译试探**：对候选终结符逐个试编译「声明起点→候选」前缀，第一个可编译前缀即终点，语法级保证；声明起点同样逐候选试编译（防表名出现在注释/字符串里的假匹配）。切片器在 `game/scripts/lib.cjs`。
2. **SIDE_CAST 内嵌 base64 头像**（P4-B 配角，12+ 条 ×146~211KB ≈ 3.5MB）——按容量预算不进 M0 抽取，M7+ P4-B 迁移批需先立头像资产策略（外置 or 压缩 or 惰性）再抽表。
3. **源表实测数 ≠ 计划书叙述数**：MASTERS_INIT 24 名宿（「名宿 12 人」指可交互子集）、ENDINGS_DB 6 条（六道途）、MAIN_QUEST_CHAPTERS 3 章（主线三章）——抽取器守恒断言以实测为准并逐条写归因。
4. **core 命名空间挂载约定**：`window.QX3D.core.{data,state,time,player}` / `QX3D.systems.travel`，node 侧同名 require——core 各件 IIFE 双态导出，取数统一走 `core.data.D`；**canon 数据表内闭包（onCanonExpire）逐字引用全局 state** → data/canon.js 内立 `var state` 槽位 + `setRuntimeState`，core/time 调用前自愈回填（不依赖外部纪律）。
5. **对表单的随机纪律**：两侧必须**同一 rng 实例贯穿全程**（创角摇残卷 + 每旬名宿游走共用一条 mulberry32 序列）——中途换种子 = 轨迹失同步 = 全字段红（M0 首跑踩过：新版侧创角用一个种子、advanceTime 又开一个）。
6. **reconcileWorldGen 的 worldGen 只记内存**：载档对账不落盘，随下一次 saveGame 持久化（原版同构）——走查判「记值」要看内存态，判「清档回创角」要先过一次旬。
7. **快速网新常态**：table-check 入 run-dod（件数 22→23）；走查网 verify-ui-qunxia3d（界面走查 42→43 篇，断言数随批对齐 .tests/README）；HUD 条不得与右上工具条同层重叠（z-index 44 居中 880px 恰好盖住「吐纳过旬」钮，实测 elementFromPoint 抓出）。
8. **（册274）初始档自带两桩悬赏**（initialState :3024 luoyang/huashan）——揭榜首击走「已有恶徒直出榜文」early-return（不扣精力不设冷却）；对表测生成路径必须先清空 bounties（S9 修正 + S9b 补 early-return 判）。
9. **（册274）行脚到达语义是双面的**：抵达主线章地点（洛阳格1）⇒ state.viewLayer=local **且 3D 板须同步钻入**——M1 实测「state 在本境、3D 在世界」的层错位格卡全失灵，落 syncBoardLayer() 在 afterAction/boot 双向对账（diving/rising 过渡态由 board3d mode 守卫挡重）。

**册313（P4-E E3a）**：
11. **「勘察数」也可能是抄错的**——册310 记 `ROMANCE_CAST` **34 人**、册311 照抄，实测原表 `:13923–:13936` 只有 **12 行**（抽取件逐字节同源）。34 是 `SIDE_CAST` 的数，被串了族。迁移批的第一次落地就该用抽取件回数（`node -e "console.log(require(...).ROMANCE_CAST.length)"`），别信上一批的叙述；勘正按「历史注不改写」在新条加行。
